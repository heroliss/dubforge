# 故障排查

先保存错误原文、发生时间和当前步骤，再按下面的范围定位。安装问题见[安装指南](installation.md)，日志与隔离验证方式见[开发与维护](development.md)。不要先删除数据库、原稿回执或整个缓存目录。

## 启动或网页连接失败

| 现象 | 先检查什么 | 处理方式 |
|---|---|---|
| 前端 `ECONNREFUSED`、`/api/health` 代理失败 | 后端端口是否在本次启动中就绪；后端最近的启动阶段日志 | Vite 启动成功不代表后端已完成初始化。先看后端日志，不因前端报错反复重启全部服务 |
| 后端停在 `Waiting for application startup` | `backend.err.log` 最后一个“启动初始化”阶段是否仍有输出或明确异常 | 数据迁移/恢复扫描可能需要时间；若已报错，按该阶段原因处理。启动器超时不是数据库可直接删除的证据 |
| API 健康但页面空白/404或脚本失败 | 是 Vite 地址还是后端构建页面，`frontend/dist/` 是否存在且与源码一致 | 开发时检查前端服务与代理；后端单服务模式需先构建前端。不要把健康响应当成页面可用验收 |
| 端口已被占用 | 原控制台 `status`、占用进程是否属于当前工作区 | 优先复用或通过原控制台管理。未知进程不要按端口强杀；AI 验证固定隔离使用 8611 |
| 配置端口与页面连的不一致 | 启动器输出，手动开发终端中的 `DUBFORGE_BACKEND_PORT` | 显式设置代理到同一后端端口，或使用 `StartDev.bat` 统一传入。不能假设裸 Vite 默认端口与自定义配置一致 |

前后端日志在程序目录 `data/dev-logs/<后端端口>-<前端端口>/`，可在原控制台运行 `logs backend`、`logs frontend`、`logs launcher`。中文乱码或 PowerShell `CLIXML` 包装不是独立的业务失败原因，应继续寻找真实异常和启动阶段信息。

## 模型或配音服务不可用

- 在「设置 → 模型与服务」核对工具、可选组件与地址。发现 Python 包不等于模型权重、CUDA 动态库、网络和参考音频都已就绪。
- IndexTTS / GPT-SoVITS 使用独立环境。页面「启动服务」只支持已安装且可识别的本机服务；远程地址需在远端启动。`127.0.0.1` 指后端所在机器。
- 快捷启动失败先看页面给出的服务日志路径，或原控制台 `services` / `logs <服务标识>`。需要交互安装、下载确认或第三方登录时，到该软件原始终端处理。
- 排队等待 GPU/配音服务时，当前内容句数与本次待合成数量可能不同；任务范围尚未准备不应理解为“0句”。只有实际进入合成后的完成数量才代表本轮进度。
- `HTTP 429`、配额/余额不足、订阅无效、鉴权失败是不同问题。根据中文原因和错误码修正对应服务配置；反复点击恢复不会增加额度或修复订阅。
- 明确的内容拒绝与服务故障分开处理。评论流程可以保留已成功评分/翻译的结果，并隔离拒绝项；模型不可用、格式校验失败或账号错误仍可能要求人工处理，不应一律跳过。

不要在配音请求仍在途时强制重启主程序或模型。请求超时/进程中断可能留下远端结果不明，系统会保留核对信息；不要删凭证后直接把同一句再发一次。

## 进度、暂停与恢复

| 显示 | 含义与可执行操作 |
|---|---|
| 正在检查/提交恢复请求 | 正在核对方案或等待受理回执，尚不能等同于模型已开始执行；等待同一请求结果 |
| 已受理/排队 | 后台已登记任务，可能等待资源；不要再次启动同一工作 |
| 执行中但一段时间无新条数 | 可能在处理当前长句、模型加载或有界后处理；看实际阶段、日志与最近活动，不按固定轮询间隔推断卡死 |
| 任务已结束，产物核验中 | 执行已结束，完整配置/文件核验尚未返回；只读检查仍可用，暂不开放重复制作或资源修改 |
| 核验失败/读取超时 | 使用页面已有“重新读取/重新核对”入口；不要把未知结果手动当成最新，也不要为刷新状态重做整步 |
| 上次中断/历史中断 | 保留的流程或批次记录，可能与后来单独恢复的项目状态并存；以当前任务进度为准，折叠详情可追查旧原因 |
| 已停止 | 用户停止或程序退出，不等同于模型服务失败；已完成有效结果保留，未完成部分需要按原计划检查恢复 |

当前阶段 ETA 只适用于该阶段；编码结束进入音频复核后，旧编码剩余时间不代表音频复核还需多久。任务累计时间也可能包含排队，不能直接当成模型实际运行时间。

关闭网页不会停止后台任务。正常停止后等待收尾，再从「运行或继续」选择原流程或原批次检查恢复；确认将复用的结果和实际起点后继续。未知启动回执需核对原任务，不能通过另建流程绕过。

## 产物过期、缓存或磁盘路径变化

“已是最新”需要当前配置、上游与文件合同一致；文件仍在磁盘上不代表可以复用。先看“设置变化”或“上游变化”的具体解释，再重做必要范围。单独字幕导出是可选操作，不需要为烧录字幕强行把所有展示步骤都跑一遍。

清理或迁移前区分三类数据：

- **项目与数据库**：正式结果、逐句声音、校对稿、回执、manifest 和日志；完整备份后再迁移，不按“缓存”删除。
- **外部引用**：本地导入视频和手动配置的参考音频可能在项目目录之外；原文件移动后需要恢复路径或重新明确选择来源。
- **可重建下载缓存**：模型缓存等可以重新下载，但删除后会增加首次执行时间。显式配置的共享目录还可能被其他软件使用。

模型缓存使用安装/设置页面支持的路径配置；修改后在所有相关任务结束时重启，确认新路径可用再清理旧副本。工作目录迁移会同时影响数据库和产物，不能只改 `server.data_root` 而不搬完整数据。账号凭据在另一 Windows 用户或机器上不能解密时，保留原记录并重新登录。

## 合成慢、显存不足或声音报告未达目标

高分辨率视频的软件编码可能很慢；是否重编码还取决于字幕、评论、剪辑和音频等实际目标。需要硬件编码时，明确选择 NVIDIA NVENC 并通过能力/资源检查；CQ 与软件 CRF 含义不同，相同数字不保证相同画质或体积。显卡忙、设备不支持或局部修订不兼容时，应处理预检原因，不假定自动切换。

音频报告分别记录目标响度与真峰值上限。峰值安全限制可能使最终响度低于目标，`target_reached=false` 需要如实阅读；不能为了让状态变绿而提高安全上限。AAC 纠偏会测量编码后的真实音轨，并在有界轮次内调整；失败时保留旧正式产物和每轮原因，按报告处理。

## B站上传、审核和章节

- 上传 100%、取得 BV、审核通过和公开可见分别核对。关闭发布页面不会取消后台上传；创建或保存草稿也不会自动投稿。
- 投稿结果不明时，先在发布页或官方创作中心核对并关联已有回执；不要新建稿件反复提交。恢复沿用原冻结清单及已完成上传，不通过删除发布记录“清状态”。
- 平台退回显示真实原因并等待处理；自动监控只查询原稿状态，不自动重投。账号处罚、验证或申诉由官方渠道处理，程序不能保证审核通过或绕过限制。
- 更新原稿应明确选择原记录及替换/同步范围；新稿会生成另一个 BV，不能因为“最近有一个BV”就自动替用户决定。
- 视频已通过而章节失败时，先看逐P状态、稳定错误码、服务原因和重试范围。只处理未完成章节，不为章节重跑配音、合成或重新投稿。原视频没有章节时跳过是合法结果。
- 配音/原声版本与分P顺序分别按已保存的版本和发布清单核对，不能从旧文件名猜测。

## 提供问题证据

反馈时提供：版本/提交标识、发生时间、操作路径、错误码与完整中文消息、相关步骤日志末尾，以及必要的脱敏截图。说明是否改过配置、移动源文件/缓存或强制退出过进程。

不要公开 `config.yaml`、Cookie、二维码、请求鉴权头、完整账号凭据或私有参考音频。诊断结果应区分“已经确认的原因”“仍待验证的线索”和“已完成的验收”，避免以一次重试成功推断原因为已确定。
