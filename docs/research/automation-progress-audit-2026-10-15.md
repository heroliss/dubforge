# 自动流程编排与过程可见性审查

日期：2026-10-15。范围：单项目手动执行、自动制作与发布、顺序批次，以及独立资料和评论处理。决策见 ADR-0164。

## 目标与判定标准

用户在任一页面都能回答：当前由哪个任务处理、正在处理什么、已经得到什么、等待什么、能否安全离开、停止或重试会保留什么。

这里的“全面”是覆盖每个会等待、失败、重试、产生结果或需要控制的过程。快速本地校验、读取和保存作为相邻阶段的一部分，不为每个函数创建进度条。没有可测总量的阶段明确显示等待或处理状态，不用计时器伪造百分比。

审查结合现有 ADR-0014/0015、0081、0158、0163，逐项追踪生产者、状态保存、API 和页面消费者。保留已约定的 LLM 估算进度，但明确“估算”；实际字节、返回的音频时间、已校验字幕行、完成文件等单独展示。

## 主要发现及处理

| 问题 | 原因与影响 | 本次处理 |
|---|---|---|
| 许多细节只能翻日志，任务结束就消失 | StepContext 的 phase/detail 原先仅在内存；不同页面从文本猜当前动作 | 新增有界 execution 诊断快照，阶段、计量、等待、重试、最近过程统一读取；任务完成仍可查看 |
| 同一进度在一个页面多处重复、另一个页面却缺失 | 步骤、自动流程、批次各自拼接状态；评论独有完整过程面板 | 共用 ExecutionProgress 展示，自动流程沿当前叶任务投影；整体阶段与叶任务工作量分层 |
| 自动流程借用了同项目的其他手动任务动态 | 导航取第一个 running 步骤，没有核对当前冻结计划项 | 按本次 run/plan 当前项及任务身份取过程，旧任务不得覆盖新任务 |
| 完成的 100% 与实际收尾顺序不一致 | 步骤函数返回后立即 done/100 并启动下游，临时文件登记清理尚未完成 | 成功收尾完成后才公开 done/100，再继续下游；失败保留原错误与正式产物 |
| 最后保存完成与停止存在竞态 | 停止写入 cancelled 后，旧的完成写入仍可能覆盖 StepRun，产生步骤与任务矛盾 | 最终提交和停止共用启动边界并重验任务身份；收尾中停止也阻止自动继续 |
| 协调器可能读到半边成功 | StepRun 和 Job 终态原先分两次提交，流程读到步骤已完成时任务回执仍可能 running | 步骤和任务的正式终态在同一数据库事务中公开 |
| 长任务可能突破自动重试次数 | 重试计数超过十分钟失效，而单次制作本身可能更长 | 同一次自动操作保留尝试次数，到成功或显式重新操作才结束该次预算 |
| 成片制作与发布可能采用两个版本快照 | 排队后参数变更，执行按最新定义合成，而发布仍按旧计划构造 | 发布绑定实际成功的版本、产物与摘要，避免错用或错误报告需更新 |
| 停止自动核对后仍可能提交章节 | 停止只有监控状态，章节调度器把该稿件视作可独立继续 | 持久化后处理暂停门禁，调度、生成和每次外部提交前检查；显式继续才能解除 |
| 升级旧记录可能丢失用户的停止意图 | 新布尔列默认关闭，旧版只有明确的停止状态和阶段文字 | 精确识别两种旧停止记录并幂等回填暂停标记；其他失败不推断为停止，显式恢复后不重复暂停 |
| 冷启动配音服务和项目服务地址不一致 | 只允许曾受托管的进程自动启动；资源准备读取全局配置 | 使用当前任务冻结的项目配置；允许可启动的本机服务冷启动，仍保护外部服务 |
| 评论采集中停止响应慢 | 同步子进程阻塞，外层取消标记无处检查 | 有总截止时间的轮询和取消检查，回收本次提取进程树；已保存快照保留 |
| 项目列表过程信息可能增加查询负担 | 若逐项目逐步骤读最近 Job 或日志，会放大列表耗时 | 列表只批量查询最新 Job 快照，不扫描日志、不解析模型正文 |
| 手动章节同步失败后旧确认框仍可再次提交 | 错误显示在遮罩后，旧计划未失效；切换BV时还有迟到响应风险 | 失败后退出旧确认，重新读取/规划才能再提交；旧BV回执不更新新BV页面 |
| 评论提示与可用操作矛盾 | 精确汇总之外重复旧 warning，只剩审核拦截时仍建议重试 | 优先精确结果与实际可重试范围，保留具体错误，不重复过时建议 |
| 发布文案生成期间仍能修改正在使用的发布设置 | 占用原因已登记，但细粒度字段门禁未消费这一类占用 | 统一 runtime_edit 增加发布文案执行项，只冻结 publish 路径；其他制作设置与其他项目仍可编辑 |

线程池排队的资源准入另有专项回归：等待 GPU 额度不能占满所有通用工作线程，使有可用额度的下载、LLM 长期排在等待者之后。实现必须保留全局线程上限和既有资源额度，取消、关闭与再次启动不得泄漏额度。

## 各过程覆盖矩阵

| 执行过程 | 当前阶段与详细信息 | 计量依据 | 中断、复用与限制 |
|---|---|---|---|
| 本地视频导入 | 具名上传动作与结果登记 | 浏览器上传进度仅代表传输；服务器完成登记后才成功 | 临时文件完整后原子替换；上传成功不等于后续制作完成 |
| 下载源视频 | 检查来源、连接、分音视频下载、合并、校验、概要、保存 | 音视频合计字节、速度；连接/ffprobe/概要等待无可靠总量 | 下载分片沿用现有断点；完整临时下载替换正式源文件 |
| 原视频资料/章节刷新 | 具名采集动作、等待、成功/失败；原始章节在源资料可见 | 元数据请求通常无逐条回调，不显示伪造章节百分比 | 原快照保留；独立刷新 API 暂无单独取消接口 |
| 提取与分离音轨 | 抽轨、模型加载、读取、分段分离、CPU 降级、保存、缓存复用 | 实际已处理音频秒，考虑分离模型与 shifts 的工作量 | 分段取消；有效完整音轨可复用；模型加载阶段未知总量 |
| 语音识别 | 来源检查、平台字幕导入、ASR 加载、语言/VAD、等待首段、转录、词时间保存 | 已返回 segment.end 对应音频秒；首段前未知 | 段间检查取消；当前没有 ASR 中途检查点，失败后可能重新识别 |
| 语义整理 | 输入准备、核心分块、请求、思考、输出、校验、复用、边界协调、保存 | 分块数量与已验证结果真实；块内模型百分比为估算 | 合格分块才落盘复用；边界失败不抹除核心块；默认分块策略保持既有设置 |
| 翻译 | token/行数窗口、请求、校验、拆窗、逐句复核、交接摘要、部分保存、对齐审查 | 已完成行/总行、当前窗口、复用；LLM 内部为估算 | 有效窗口原子保存；失败重试局部，不重做已合格窗口 |
| 配音任务准备 | 句子/时间审查、任务与槽位计划 | 句数；快速本地校验不单列百分比 | 沿用任务策略；用户精调、目标槽、继续/重做语义不由进度层改变 |
| 配音服务与资源等待 | 等待资源、检查服务、启动服务、加载、释放冲突驻留 | 资源/服务状态，无模型加载假百分比 | 启停使用任务项目配置；外部服务不会被误停 |
| 配音合成 | 当前句、总数、生成/复用、服务端迭代、时间审查、整窗排布、必要缩时修复、回执保存 | 句数及已有服务端迭代工作量；排布作为独立阶段 | 已完成单句和槽位保留；自动修复不覆盖无关槽；整体排布阶段不再伪装成正在合成某句 |
| 字幕文件导出 | 输入准备、逐文件导出、全部保存 | 文件 0/N 到 N/N | 由配音页也可查看/停止当前字幕任务；文件边界取消，短步骤不另建恢复系统 |
| 评论采集 | 连接平台、等待提取、保存快照 | 已有数量/目标上限/耗时；采集器无实时逐条回调 | 自动流程取消可回收提取进程；独立采集尚无取消 API |
| 评论评分 | 分批、当前模型、等待/思考/接收/校验/修正、逐条保存 | processed/total、成功/失败/复用、批次、请求字符与耗时 | 已保存评分复用；失败数与已处理数分开，不把处理完误写全部成功 |
| 评论翻译 | 筛选、批次、当前模型、校验与结果保存 | 与评分一致，按实际待译条数 | 独立重试与缓存；复用既有评论诊断，不新增重复任务 |
| 内容审查 | 具名扫描与报告，结果、风险和 checked_at | 本地同步规则扫描，无长时间 LLM 请求 | 保留轻量按钮状态；不增加虚假后台进度 |
| 成片准备 | 版本检查、配音时长、铺轨、混音、响度、评论准备 | 阶段、版本/文件数量；非线性准备无可靠百分比 | 已完成版本按指纹复用；NumPy 操作在检查点响应停止 |
| 成片编码 | 当前版本、FFmpeg 编码、登记、清理 | FFmpeg out_time_us/目标媒体时长 | 可停止子进程；只登记完整产物；编码到终点后仍展示登记和清理 |
| 文案/封面候选 | 输入收集、模型请求、结果校验、候选可选用 | 候选数量或阶段；LLM 字符不冒充最终质量 | 生成候选不修改已保存草稿/发布回执；失败保留已有资料 |
| 发布统一预检 | 配方、产物、账号、重复保护、章节策略与确认 | 检查结果清单，而非长时间制作百分比 | 阻断条件与可自动补做任务分开；用户批准具体发布范围 |
| 上传与投稿 | 排队、文件/分P上传、合并、封面、提交、回执 | 视频上传字节与完成分P；100%只表示视频字节 | 结果不明进入核对，不自动重复投稿；暂停/停止作用于本次任务 |
| 平台审核与合集 | 等待审核、下次核对、合集归属/排序核对 | 平台状态，不推算审核完成时间 | 可停止自动核对并继续；审核不占制作工作线程 |
| 自动章节交付 | 源章节、标题处理、裁剪映射、逐P预检、提交、回读 | 当前分P/总数、已完成分P、阶段 | 投稿回执与章节结果独立；未知只回读；远端不同章节需显式处理 |
| 远端稿件设置同步/手动章节 | 具名载入/生成计划/提交/回读状态与错误 | 操作阶段与结果差异，不冒充视频上传 | 保留已有预检、变化计划、二次读取与未知结果保护 |
| 自动流程继续与批次 | 整体完成阶段数、当前项目/步骤、叶任务进度、等待/重试/人工处理原因 | 阶段数是阶段数，当前工作量是当前工作量；不做等权总时间百分比 | 运行项冻结、未执行项可编辑；本次快照、已完成产物和远端回执各有明确归属 |

实现入口：`execution_progress.py`、`runner.py`、`pipeline/step_*.py`、`pipeline/version_render.py`、`comments_auto.py`、`video_info.py`、`workflows.py`、`publishing/service.py`、`publishing/chapter_sync.py`；页面统一组件 `ExecutionProgress.vue` 与 `executionProgress.ts`。

## 信息与操作层级

1. **整体**：当前项目和当前阶段、已完成阶段/总阶段、流程状态与下一步。阶段长度不同，不把 5/10 阶段解释为剩余一半时间。
2. **当前工作**：清晰的中文阶段名、已完成/总量、缓存/失败等有用事实、等待原因、已用时间、最近活动和下次核对。真实百分比与估算标明各自范围。
3. **细节**：折叠的最近过程；模型思考/正文和完整日志继续放原有详细入口，不把长文本复制到状态接口。

列表用精简当前状态，步骤页显示叶任务详情，自动流程页显示整体加当前叶任务，批次显示项目位置加相同叶任务。重复信息合并，不要求用户去另一个页面才能知道任务停在何处。

停止、暂停和重试仍是业务控制，不由诊断状态推断授权。暂停请求显示“等待安全暂停”；停止请求显示“等待安全收尾”，不能点击后立即宣称已停止。输入任务代次可防旧弹窗误停新任务。已提交但结果不明的远端操作只做核对，不能因超时或刷新自动重发。

## 数据、性能和一致性

- Job.execution 和 WorkflowRun.execution 是诊断投影，不是第二套任务状态机，不进入配置/产物指纹。
- 阶段切换和终态立即保存，同阶段活动最多每秒保存一次。只保留最近 24 个阶段，完整日志另存；这避免长视频状态响应无限膨胀。
- 保存有限标量和安全指标，不收集提示词、模型正文、思考正文或认证信息。模型只记录阶段、模型名、请求次数、字符计数。
- Job 的心跳、任务回执和 execution 各自按列更新，旧内存快照不能覆盖新回执或新过程。
- 诊断写库不持有快照读取锁，SQLite 忙时页面仍可读取当前内存状态；同一记录的写入有序取最新快照。
- 结束状态耗时冻结；刷新页面不会让已完成任务继续累加时间。终态父任务覆盖陈旧的 running 阶段。
- 项目列表批量读取最新任务的有限列，不加载整份 task_data、不扫历史 JSONL；页面兼容旧接口没有 execution 的情况。

## 尚不能推算或保证的事项

- 模型加载、首次生成、外部网络首响应、平台审核没有可靠剩余时间，只能显示阶段、等待和活动证据。
- 单独点击源资料/评论刷新尚不具备独立后台取消端点；自动流程采集已能停止。短请求状态不等同于进程内部逐条进度。
- 本地导入有真实上传进度，但仍没有中途暂停/取消传输；独立同步文案/章节预览生成也没有跨刷新恢复的后台任务。平台封面读取有最长 30 秒等待，请求内部暂不能取消。
- ASR 目前只有段级进度，没有模型加载内部百分比，也没有逐段永久检查点。
- 暂停/停止对不提供细粒度取消的第三方计算库在安全检查点生效；需要明确展示这一事实。
- 最近 24 项是诊断摘要，不是每一次 token、每一句和所有历史尝试的审计总账；详细产物、日志及评论/配音结果仍保留在各自入口。
- 本次以隔离数据库、模拟模型/平台、事件可控的任务验证；没有用正式视频执行真实投稿或章节覆盖。

## 研究依据

- [Microsoft 进度控件指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/progress-controls)：能测量时显示确定进度，总量未知时使用不确定状态；避免多个无意义的加载圈。
- [W3C ARIA25](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA25)：状态信息通过适当 live region 传达，不要求用户移动焦点才能知道更新。
- [NN/g 等待与中断体验](https://www.nngroup.com/articles/designing-for-waits-and-interruptions/)：让用户理解等待、保留工作上下文和中断后的连续性。

这些资料支持信息层级和可访问性原则。具体阶段、持久化策略与取消边界来自本仓库代码和隔离回归，并非外部资料能替代证明。

- 前端最终全量：`node --experimental-strip-types --test --test-concurrency=1 tests/*.test.ts`，**1148/1148 通过**，0 失败、0 跳过，耗时约 124 秒；Vite 最终构建通过，耗时 7.85 秒。日志：`data/diagnostics/progress-audit/frontend-full-final.log`、`frontend/.execution-build-last.log`。仍有已有的打包文件超过 500 kB 提示，不影响构建通过。
- 后端覆盖 **4118 个不同测试用例，均已有通过记录**。这是全量扫描、未执行项与修复项续跑、最终修复项重验的分段结果，并非单条全量命令一次全绿。按用例身份去重的汇总 `data/diagnostics/progress-audit/validation-summary.json` 显示 missing 与 unresolved 均为空；最后一轮 85/85 通过，仍有 2 条 Starlette 弃用提示。原收集 4115 项，加本次最终迁移回归 3 项，共 4118 项。
