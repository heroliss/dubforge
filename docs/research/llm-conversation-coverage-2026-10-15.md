# LLM 对话可见性专项核查

日期：2026-10-15。范围：所有真实模型补全调用，以及章节整理与标题自定义要求。决策见 [ADR-0166](../decisions/0166-shared-llm-conversation-journal.md)、[ADR-0165](../decisions/0165-bilibili-chapter-adaptation.md)。

## 结论与覆盖

当前生产模型补全统一经过 `backends/llm.py` 的公共入口，没有发现绕开公共入口的第三方 SDK。此前底层具备请求、流式思考/正文、最终回复、校验和重试事件，但只在调用方传入持久 trace 时可回看。

| 调用 | 旧状态 | 本次统一归属与查看 |
|---|---|---|
| 获取视频时的中文标题与概要 | 有步骤 trace，步骤页入口受限 | summary，按项目/任务归属；资料面板入口 |
| 独立重新生成概要 | 没有可读的完整对话 | summary，实际调用线程绑定项目；同一抽屉 |
| 语义整理、分块与边界协调 | 步骤独立实现 | split，每次逻辑请求记录；保留原动画与质量信息，共享聚合/渲染 |
| 翻译、局部补救与恢复对齐审查 | 步骤独立实现 | translate，补救与重试可查，不把思考混成译文 |
| 评论评分、评论翻译、拆批修正 | 已有专有诊断 | comment_score/comment_translate，保留业务结果，复用同一对话渲染 |
| 项目发布设置 AI 文案 | 没有完整记录 | publish_copy，项目归属；AI 助手入口 |
| 具体发布记录 AI 文案 | 只有阶段/字符数 | publish_copy，项目及稿件归属；同一抽屉 |
| 自动流程补全文案 | 只有阶段/字符数 | publish_copy，实际线程绑定流程及对应稿件；全局/项目可回看 |
| 自动章节整理与内容审查 | 只有阶段/字符数 | chapters，按项目及稿件归属；统一记录和发布页入口 |
| 手动章节整理、纯标题兼容翻译 | 没有完整记录 | chapters，请求/最终分组/审查/校验均记录 |
| 设置页并行模型连通性测试 | 仅当次简要结果 | provider_test，每个真实工作线程记录；设置页入口 |
| 请求参数预览 | 本地占位，没有调用模型 | 继续明确为未发送请求的预览，不伪造对话 |
| 现有字幕/评论本地内容规则扫描 | 没有模型调用 | 保持本地规则报告，不伪造模型过程 |

新公共调用默认记录，业务归属漏配仍进入全局“未归类”，避免未来新增功能静默遗漏。全局顶部“LLM对话”和各功能按钮打开同一抽屉，支持项目、任务种类和具体稿件/任务筛选。

## 数据、性能与操作

- 模型对话使用独立 JSONL 和小型元信息索引；列表不扫描正文，事件按完整行字节游标读取，单次响应最多约512KB。长消息分片保留全文，跨页拼接后再替换流式候选，避免只显示前一片或重复回复。
- 统一脱敏精确配置密钥、常见密钥形态、Bearer、认证字段和认证 URL。现有步骤与评论日志也消费相同清洗函数。不会将整个配置、HTTP 鉴权头或 provider 对象存进对话。
- 模型记录与 progress/正式产物分离。诊断磁盘或索引异常只给警告，不应引发额外模型调用、修改正式结果或放宽取消/平台未知写入保护。
- 抽屉关闭、切换对话和页面隐藏仅停止观察；不会取消模型任务。游标、请求代次和 Abort 控制迟到响应；历史记录不播放成新的流式输出。
- 系统提示、服务商返回的思考与超长内容可折叠；用户消息、最终回复、校验和失败保留。时间统一按本机时区显示；没有返回思考时不推测。

## 章节标题自定义要求

只增加一个可继承、可冻结的 `publish.chapters_instruction`，界面名称为“章节标题自定义要求（可选）”。可写内容审查关注点、标题形式、措辞、术语和命名风格；不另立“审查提示词”等重复入口。B站章节数量、首/后章时长和16字符硬限制仅展示，API不接受客户端规则覆盖。

整理与审查在同一次模型调用中完成，返回与最终分组对应的说明。原语言模式同样审查标题；不能因数量/时间合规就跳过内容审查。无法可靠改写的内容保留候选与原因，自动交付停止在章节待处理；不会改变视频投稿成功状态或重复投稿。

真实21章验收还发现，只有孤立章节名时模型可能擅自补出“发布”等事实状态。现在额外提供冻结稿件/项目总标题辅助理解，并将该上下文纳入缓存验证；最新本地候选已使用“疑似泄露”口径并返回审查说明。硬校验能保证结构、时间、来源和审查回执有效，不能保证每个模型判断都最优或替代B站审核。

## 验证与边界

- 真实稿件仅只读查询平台规则：每P `limit=10, stay=5, space=0, max_title_length=16`，与当前[官方编辑器](https://s1.hdslb.com/bfs/static/player/editor/editor.ab6a7a86.js)吻合。首章从0秒开始、至少1秒，其他含末章至少5秒；10章为9个内部分界。
- 对实际视频21个章节进行了真实模型本地验收：生成10章，保留全部顺序与来源，返回逐项审查说明。仅保存诊断候选，没有写入B站或修改发布记录。
- 浏览器在隔离8611端口使用真实前端/API与固定平台/模型替身：输入一条自定义要求，21章变10章，硬规则、来源、审查说明均可见；同一操作在共享抽屉可回看实际输入、系统提示、模型回复与完成。该UI验收不代表真实平台写入成功。
- 截图与本地候选位于 `data/diagnostics/chapter-adaptation/`。章节界面见 `chapter-review.png`，统一对话见 `llm-conversations.png`；浏览器控制台无警告/错误，1280像素视口未出现页面或抽屉水平溢出。
- 升级前未记录的独立调用无法事后还原；已有步骤与评论的原日志入口继续兼容。新记录从升级后的下一次调用开始完整保留，当前不自动删除历史。

### 最终回归记录

- 后端全量：4230通过、1失败、2跳过，耗时820.02秒。唯一失败为旧 `test_publish_source_credit` 链接筛选测试未声明隔离数据库，且只替换 `Dependencies.fresh` 而仍初始化真实项目依赖；已使用 `isolated_env` 并完整替换该用例不关心的依赖读取，没有修改业务行为来迎合测试。
- 修复后按最终代码重跑章节领域/API/同步/继承、发布文案/来源链接、工作流归属、共享对话/API及LLM正文与响应保护：287通过，37.28秒。该结果为定向回归，不宣称另跑了一遍全量。
- 最后收口旧文字日志的嵌套认证字段脱敏：共享journal、业务归属及评论诊断57项通过；旧LLM八模块214项通过（无跳过），11.48秒。新增测试确认嵌套vendor参数、列表及response_format中的认证信息不进日志，实际发送body及非敏感中文全文不变。这些定向结果包含重叠用例，不能直接累加为全量用例总数。
- 前端全量1176通过；随后本机时区显示修复的重点97项通过，最终生产构建通过（6.25秒）。构建仍提示已有较大分块，可作为独立打包优化议题。
- B站 Node worker 82项通过，覆盖数量、时长、标题、动态规则及确认未写入与结果未知的区分。
- 8611隔离验收服务和临时浏览器页已关闭；没有重启用户8601常驻实例。加载新接口和统一记录需要在现有任务结束后重启后端并刷新前端。

### 章节对话入口的可发现性改进

自动章节状态区、本稿件章节草稿及B站章节编辑区均在标题栏固定提供“查看LLM对话”，使用对话图标与次级按钮底色。删除原先埋在自定义要求之后的入口；读取中、读取失败、空分P、关闭自动章节或页面只读时仍可查历史。已投稿稿件按项目、chapters及稿件ID筛选，项目草稿预览沿用实际接口的项目归属，不因错误的稿件过滤隐藏记录。点击只派发查看事件并阻止冒泡，不触发模型或平台写请求。

实际浏览器验证两个稿件入口均打开正确的项目及稿件筛选，1280像素视口标题与按钮对齐且无水平溢出、控制台无警告/错误。截图为 `chapter-entry-status.png`、`chapter-entry-editor.png`。6文件专项53项通过；最终前端全量1181项通过、生产构建通过（5.87秒）。本轮仅修改前端，无需为此重启后端，刷新页面即可加载。

后续完整回归发现自动文案稿件归属的提前计算变量被设置字段循环覆盖，可能错误读取或保存名为 `source` 等字段名的稿件。已用独立 `publication_key` 贯穿对话归属、读取/创建/保存与流程绑定，并更新旧诊断测试替身的参数合同。实际服务测试覆盖新建和刷新草稿、重复恢复不创建第二份稿件；相关6模块201项通过。只读查询真实数据未发现这些字段名对应的稿件，未做生产数据修改。验证日志位于 `data/diagnostics/timing-setting/backend-publication-regression.log`。
