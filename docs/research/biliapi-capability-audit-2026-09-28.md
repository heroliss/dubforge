# biliAPI 未接入能力盘点与 DubForge 建议

核对日期：2026-09-28。依据：本项目安装的 `@renmu/bili-api@2.15.0` 类型声明与实现，以及上游仓库源码。这里的“支持”指存在方法，不代表当前账号权限、网络和平台接口已经实测通过；本轮未真实创建合集、上传或投稿，也没有升级 SDK。

后续实施更新：用户确认后，已接入推荐标签与校验、稿件查询及状态/基础统计、已有BV文案编辑/追加分P/重排、合集归属调整、官网模板只读导入、话题选择，以及评论和字幕导入。详见 [ADR-0047](../decisions/0047-bilibili-creator-workspace.md)。下文保留初次调研时的取舍，不能据其中“尚未使用”判断当前实现状态；替换/删除分P、写回官网模板、自动互动等仍不在本轮范围。

## 已接入的边界

扫码登录及登录响应适配、单独上传视频与封面、Web V3 投稿、读取单稿件回执、分区与创作声明选项、读取合集及小节、投稿后加入合集均已接入。默认值继承、合集发布模板、AI 文案、任务去重属于 DubForge 逻辑，不是 biliAPI 自带功能。

本轮在合集选择旁加入“新建合集”。SDK 本身没有创建合集方法，因此仅在工作进程中补充网页 `POST /x2/creative/web/season/add` 适配，复用 SDK 的登录、请求和封面上传。名称、简介、封面由用户确认；只创建空合集，不上传视频。需要权限或审核时以平台返回为准。创建成功先保存合集 ID，再独立刷新小节；响应丢失进入待核对，不自动重发。

依据：[上游创作中心实现](https://github.com/renmu123/biliAPI/blob/master/src/platform/index.ts)、[创建合集接口记录](https://github.com/afiuh/bilibili-api-collect/blob/master/docs/creativecenter/season.md#创建合集)。后者是社区记录，不是B站官方开放平台承诺。

## 优先考虑的功能

| 优先级 | 尚未使用的方法／字段 | 可以提供的功能 | 接入边界 |
| --- | --- | --- | --- |
| 高 | `getRecommendTags`、`checkTag` | 在 AI 标签旁增加平台推荐标签，校验不可用标签 | 推荐不等于流量保证；仅建议，不能覆盖用户标签或自动参加活动 |
| 高 | `getArchives`；已用 `getArchive` 尚未展示的 `reject_reason`、分P状态字段 | 导入账号已有投稿、选择BV关联；显示各P转码/审核和退回原因 | “查到同名稿件”不能自动认定是本地稿件；关联要核对账号与分P |
| 高 | `editMediaWebApi` 的 `append`、`replace`、`sortByCid` | 给已有BV追加后来生成的配音版，调整分P顺序，编辑已发布文案 | 显式区分“新增稿件”和“更新BV”；展示变更前后差异，保存回执，不能对失败写入盲重试 |
| 中 | `editMediaSeason`、`getSessionId` | 已有稿件移动到另一个合集、核对远端归属 | 当前已接入的是投稿后“加入”；转移和移出是另一种明确操作 |
| 中 | `getUploadTemplateList`、`editUploadTemplate` | 导入在B站官网维护的投稿模板；可选同步回官网 | 先做只读导入与差异预览；旧分区、版权和默认模板不能直接覆盖本地设置 |
| 中 | `getTopic`、`searchTopic` | 搜索适合视频的话题活动，展示说明后选择 | 选择活动可能附带条件；AI不能自动报名，接口存在不代表可参加全部活动 |
| 中 | `getTypeDesc` | 根据分区给出更贴合平台的简介提示 | 这是简介提示格式，不是平台替用户生成的事实内容 |
| 中 | `getArchives` 中的 `stat`，合集列表中的 `seasonStat` | 播放、点赞、收藏、评论等基础表现面板 | 已用合集列表可扩展返回字段；不是完整后台分析报表，不能据此承诺留存或收入数据 |

这些建议是对 DubForge 工作流的设计判断。相关方法见[创作中心源码](https://github.com/renmu123/biliAPI/blob/master/src/platform/index.ts)及[返回类型](https://github.com/renmu123/biliAPI/blob/master/src/types/platform.ts)。本次只实现新建合集，未暗中打开以上功能或后台轮询。

## 内容采集与互动方向

| 模块／方法 | 有用的延伸 | 当前取舍 |
| --- | --- | --- |
| `reply.list`、`count` | 收集B站评论，接入现有评论翻译、评分和上屏工作区 | 可作为 YouTube 评论之外的第二个来源；分清父评论/回复和分页数量 |
| `reply.add`、`top` | 生成来源说明、配音说明或勘误候选，人工确认后发送/置顶 | 发评论是代表用户对外发言，不能自动执行；删除、举报更不应交给AI无确认操作 |
| `video.info/detail/getInfo/desc/pagelist/playerInfo` | B站来源的视频资料、分P选择、已发表版本检查 | 先确定是否需要把B站作为输入源；与现有 yt-dlp 适配避免重复实现 |
| `video.downloadSubtitle` | 优先导入已有字幕，减少重复识别 | 是“下载字幕”，不是给自己的投稿上传外挂字幕；还要核对语言与时间轴 |
| `video.getDm/getAllDm` 与 XML 转换工具 | 弹幕采集、弹幕时间点分析 | 和普通评论分开建模，避免把弹幕数量当评论总数 |
| `search.all/type`、用户投稿与合集读取方法 | 查找已有视频、按作者/合集批量导入待制作清单 | 需要单独的批量选择与去重界面，不能自动开始下载或发布 |

依据：[评论实现](https://github.com/renmu123/biliAPI/blob/master/src/video/reply.ts)、[视频实现](https://github.com/renmu123/biliAPI/blob/master/src/video/index.ts)、[用户与搜索文档](https://github.com/renmu123/biliAPI/blob/master/README.md)。

## 有接口，但当前不建议优先接入

- `addMedia`、`onAddMedia`、高层编辑入口以及旧投稿/必剪投稿通道：与当前上传、确认投稿分离的边界重复，部分高层调用带重试；不用于失败后自动换通道。
- `BcutASR`：可以作为另一种在线语音识别后端，但需上传音频，另有可用性与隐私成本；已有本地识别工作流时优先级低。[源码](https://github.com/renmu123/biliAPI/blob/master/src/bCut/asr.ts)
- 直播房间、主播、舰长、回放接口：偏直播业务；除非确定要做录播再加工，否则与当前主要流程关联较弱。
- 点赞、投币、收藏、分享、三连、评论点踩/删除/举报：不用于自动增长或自动互动；需要时单独设计明确授权。
- TV 登录、通用下载器、WBI 签名、旧分区、上传线路与分片内部方法：属于基础设施或替代实现，不是直接面向用户的新功能。已有 Web 登录不因此增加更多登录方式。

## 不能从“库里有相关字段”推断已经完整支持

本次核对没有找到现成的“上传外挂字幕”“创建/编辑视频章节”“创建合集小节”“编辑/删除合集”的完整高层封装。创建合集已用独立适配补齐，其他能力仍需另外核对平台接口。杜比、Hi-Res、商业推广、收益/留存明细和 64GB 上传资格，也不能仅凭一个布尔字段或视频播放接口就认定已实现。

建议下一阶段先做“推荐标签＋标签校验＋审核失败原因”；之后独立做“更新已有BV／追加配音分P”，再扩展评论来源和字幕导入。
