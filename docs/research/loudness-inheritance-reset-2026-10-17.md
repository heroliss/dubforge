# 响度恢复层级与同页刷新缺口

## 实际原因

只读核对生产接口确认：全局保存的是统一响度、−14 LUFS；第二个项目《中国全史【无AI】》的已存基础是保持混音音量、−16 LUFS，项目单独覆盖了保留动态。当前绑定模板解析后的最新基础也包含统一响度、−14。因此恢复项目覆盖回到旧基础属于 ADR-0126 / 0162 的既定快照机制。应用最新基础保留明确覆盖，再恢复该项才会回到新基础。

确有同页缓存缺口：版本工作区应用新基础后，独立挂载的项目表单没有回读；反向保存项目参数时，版本工作区也可能继续使用旧默认。只刷新导航不能更新这两处组件的内部默认值。

## 修复

- 两侧通过独立刷新通知互相回读，避免循环通知与整组件重建。保留脏稿、运行中的提交与并发身份，取消旧读取并忽略迟到响应；切项目强制更新。
- 项目默认参数旁提供同一个“查看并应用最新合成设置”入口，先检查变化再确认。字段恢复继续使用项目已存基础。
- 冻结来源标签改为“已存全局值 / 已存模板值”，说明其不代表最新默认。
- 应用差异同时带基础前后值与实际生效前后值；用中文显示响度模式，并说明项目单独模式会保留。没有改变任何覆盖优先级或自动运行策略。
- 帮助页区分出厂值与当前项目的实际配置。

## 验证

- 后端 3 个相关模块 51 passed，包括新的真实 API 场景：旧基础 off/−16，全局更新 uniform/−14，项目覆盖 normalize，版本覆盖 off/−18；逐层应用和恢复后分别核对有效值与来源。
- 前端 12 个相关模块 162 passed，失败、取消、跳过均为 0；含 9 个同页同步回归，覆盖脏稿、提交中刷新、切项目、迟到响应和原提交指纹。
- 类型检查、生产构建通过。未重跑全部前后端套件。首次相关运行发现纯 TS 测试无法解析新增的无扩展名导入，改为项目支持的 `.ts` 导入后，上述相关模块已完整重跑并通过。
- 8611 独立数据与配置启动本地网页：项目表单与版本区域先显示 −16；从项目参数旁入口应用最新基础后，二者都显示 −14 且保留 normalize。再点击项目模式恢复并用 Enter 保存，两个区域都显示统一响度，保存按钮禁用、无草稿提示。全程未手动刷新页面。
- 新入口在 390 像素宽度无横向溢出，控制台无错误。Vue 正则检查的旧帮助页侧边线提示没有改动，不以正则扫描冒充完整视觉检查。
- 验收材料位于 `data/diagnostics/loudness-inheritance-20261017/`，含 `defaults-plan.png`、`after-apply-and-reset.png`、`browser-result.json` 与测试/构建日志。

生产配置仅做白名单字段的只读核对，未修改用户项目或运行成片/发布任务。隔离服务和标签页在验收后关闭。
