# B站原生章节接入核查

核查日期：2026-09-28。目标是用户截图“章节管理”生成的播放器进度条章节点，而不是合集小节、分P、简介中的时间戳或 MP4 内嵌章节。

> 2026-09-29 更新：通过官方网页静态代码已找到原生章节的实际写入路径，详见文末。下文“缺少可验证协议”是此前核查结论，不代表目前仍找不到接口；本轮仍未开启自动写入，也没有试写用户的稿件。

## 结论

此前暂不接入自动写入；后续静态核查已经取得当前网页编辑器的可验证协议，并在 DubForge 中按预览确认方式接入。不能把网上流传的旧接口当作本实现依据：

- 本地安装的 `@renmu/bili-api@2.15.0` 创作中心实现与投稿类型没有章节写入方法或明确字段；[上游仓库](https://github.com/renmu123/biliAPI)也未提供对应使用约定。
- [B站开放平台文档](https://open.bilibili.com/doc)本轮未查到足以完成该功能的写入接口契约。错误码中出现章节内容校验，不足以推断请求地址、参数和权限。
- 播放器元数据里的章节/看点属于读取能力，不能当作作者编辑接口；上传含章节的容器文件也不会自动推断为B站原生章节。

实现仍未在用户稿件上发送实验性写请求；真实写入仅通过发布页的明确预览和确认触发。现有源视频章节资料保留。

## 若后续取得可验证协议

需要确认账号章节权限、每个分P对应的 CID、标题和时间校验、是否支持审核中设置、已有章节的替换规则与回读确认。原声/配音全长版通常沿用原时间轴，但剪辑或区域试片必须裁剪/平移时间。写入失败不能把已投稿成功误报为投稿失败，更不能触发重复投稿。

## 2026-09-29：官方网页实现核查

只请求公开 HTML/JS，没有使用用户 Cookie 或发送远端写请求。读取路径：

1. [创作中心投稿页](https://member.bilibili.com/platform/upload/video/frame)引用的入口脚本指向异步路由。
2. [章节管理路由组件](https://s1.hdslb.com/bfs/static/studio/creativecenter-platform-next/static/js/async/js/creativecenter-v3.2808.087b8a68.js)打开播放器编辑器，并传入 `scene=chapter`、`source_type=editor`、BVID 以及可选 CID。
3. [播放器编辑器 HTML](https://www.bilibili.com/web/player/index.html?scene=chapter&source_type=editor)引用了[编辑器脚本](https://s1.hdslb.com/bfs/static/player/editor/editor.ab6a7a86.js)。以下调用和字段来自该脚本，不是推测的 API。

### 已找到的契约

- 查询规则：`GET https://member.bilibili.com/x/web/viewpoint/rule`，带稿件和分P标识。章节规则包含数量、时长等限制；上限为零时编辑器禁止新增，需查询实际账号/稿件规则，不能仅硬编码默认值。
- 读取现有卡片：`GET https://member.bilibili.com/x/web/allcards`，按 AID、CID 读取。
- 提交章节：`POST https://member.bilibili.com/x/web/card/submit`。网页选择章节类型 `type=2`，携带 AID、当前分P的 CID、序列化的 `cards`（每项为秒级起止时间和标题），以及 App 展示开关 `permanent`。
- 网页另有投稿前的预设路径，但不能由此认定新稿审核中或任意账号都可设置；正式接入优先以稿件回执和查询到的权限为准。
- 编辑器会对起止秒数取整，存在首章节、后续章节最短时长和标题长度等校验，还提供文本编辑器。需要读取实时规则并验证，不能把 YouTube 的任意章节直接无损提交。

### 分P与时间轴

- 当前代码提交时取所选分P的 CID；这说明接入时必须逐P映射，而不是给一个 BV 写一套跨P时间戳。尚未实际验证用户账号的各P是否开放章节能力。
- 在入口语言包中虽找到过单分P限制文案，但当前章节管理入口的禁用判断主要依赖稿件可编辑状态和账号返回的时长门槛；不能把未证实关联的文案宣称为章节的现行通用限制。
- 本项目完整成品渲染沿用原视频时间轴，配音对齐原时间轴，因此同源原声/配音版可复用章节起点。不同剪辑、加片头或变速必须重新映射；区域试片不进入发布清单。

### 建议后续接入边界

原章节 → 按目标成品时长校验 → 必要时人工/AI整理中文短标题 → 投稿取得回执 → 查询每P章节权限及已有章节 → 按CID提交 → 回读确认。章节数量超限或间隔过短时显示需要调整，不静默删章节；有既存章节时先比较，不覆盖用户在B站的手工修改。章节失败单独呈现、可独立重试，不影响投稿成功状态，绝不为补章节重复投稿。

当前实现已加入发布页：源视频章节可载入并可选翻译，发布记录保存独立章节选项；取得 BVID 后按每个 CID 生成同步计划，单次提交并回读核验。账号权限、稿件状态和审核延迟仍以真实 B 站回执为准；失败或结果不明不会自动重复提交。

## 真实账号最小联调

2026-10-13 使用已发布测试稿件完成一次最小闭环：读取规则和空章节 → 预览两条测试章节 → 真实提交 → 回读确认 → 提交空列表清除。B站会把最后一章的结束时间规范为分P总时长，适配器已将其作为平台规范值处理。测试章节已清除，回读结果为空；过程中没有修改视频、简介、合集或制作产物。

## 2026-10-15：平台约束与语义整理

对实际失败稿件只读规则确认：当前每P最多10章、9个内部分界；`stay=5`、`space=0`、标题上限16。官方编辑器的首章从0秒开始且至少1秒，后续章节包括末章至少5秒。标题长度与网页一致按UTF-16计数，不能把“首分界至少1秒”误读为首章起点必须1秒。

本次失败源于21章一对一翻译后仍是21章，而重试保留旧译文。现已增加同一套本地章节整理：模型输出相邻源编号分组和短标题，程序保管时间并严格验证完整覆盖；按实际成片/P读取实时规则后整理，按版本和规则缓存。自动章节与手动候选均能显示整理前后数量和来源，既有未知写入与重复投稿保护保留。详见 [ADR-0165](../decisions/0165-bilibili-chapter-adaptation.md)。本轮没有发送真实章节写请求。
