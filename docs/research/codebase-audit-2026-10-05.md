# 2026-10-05 工程审查与批量导入验收

## 范围和方法

本轮从重启后恢复未完成的批量导入出发，检查了项目登记/目录/回执事务、全局→系列→项目配置继承、参数契约、批量运行确认/重试、浏览器异步响应和前端测试隔离。结合 ADR-0058、0060、0071、0075、0076、0077 做架构审查，不重做已有配置系统或资源调度。

采用 improve-codebase-architecture 的证据驱动审查方法，把恢复规则集中到导入领域与统一配置边界，而非让界面重新拼装可信计划。下面是本轮实际发现并已修复的问题；全量回归不是对所有外部服务、模型质量或实际投稿效果的证明。

## 已修复

| --- | --- | --- |

| `_result` 逐项调用 `crud.get_project`，批量状态刷新产生 N+1 查询 | 状态和历史合并查询已创建 UID，摘要不带完整设置 | 五项目的状态和历史均仅2次 SELECT |

| 步骤数值上下限仅对部分参数生效，外部清单能绕过控件；对象枚举可触发 unhashable TypeError；超大整数可使 math.isfinite 溢出 | 所有步骤数值复用元数据范围/整数规则；枚举验证类型；有限数值判断防溢出 | 配置 API 对非法范围、类型、非整数、超大数值均返回中文业务400且不保存 |
| 分P名称可引用不存在的版本、空发布列表可保存、表情字符长度与发布限制不一致 | 发布列表非空且引用有效，名称键引用有效版本，按 UTF-16 计算80字符 | 非法引用、空数组、41个双码元表情均拒绝保存 |

| 下载样板原来使用列表首个模板，与上方选择不一致；长 JSON 挤占预览 | 样板和 LLM 指南跟随当前选择；解析后收起输入；显示模板名与统一来源徽标；已创建项目可主动一键选中 | 组件契约测试和8611隔离浏览器实测 |

## 保留的设计

- 导入仅创建，不联网抓标题、调用 LLM、下载、运行或投稿。模板共享要求继续放模板，项目 JSON 只写例外。
- 回执和项目同事务；manifest 写入失败不删除已提交项目目录。继续时复核模板指纹和本地来源，不默默切换配置。
- 本次审查时，运行中的步骤固定配置快照且允许编辑，下一个工作流边界核对剩余步骤消费的配置。2026-10-07 用户随后选择运行期间锁定编辑，交互决策由 [ADR-0098](../decisions/0098-runtime-edit-locks.md) 更新；快照与边界检查继续保留。
- 工作流确认、单项目幂等请求、下载重试、GPU 资源组和按需显存协调继续复用现有实现。
- 没有新增账号权限、自动投稿入口或一套平行的“批量配置”。

## 后续审查重点

1. 实际长视频性能需按下载/ASR/语义整理/配音/编码分阶段采样，区分排队、模型首载、LLM响应和工作耗时，不能仅凭单元测试断言速度改善。
2. `configuration.list_templates` 的项目计数仍按模板逐项查询；模板数量显著增加时可改为一次分组计数。当前不为小规模模板列表引入缓存及其失效规则。
3. 测试环境还有 Vue Router 的最小路由夹具警告和 Starlette/httpx 的依赖弃用警告，属于测试支撑维护项，不据此升级整个服务依赖栈。
4. 批量导入按当前单进程模型串行执行，历史默认最近20批。若以后需要多进程服务、批次检索/清理或跨机器恢复，应先设计数据库租约和生命周期，不把进程内 `running` 当成持久任务状态。
5. YouTube可下载性、IndexTTS服务质量和B站真实发布/审核属于外部链路，本轮未发起真实任务；仍由正式运行预检及相应步骤检验。
