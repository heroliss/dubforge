# 评论工作区布局与操作优化验收

日期：2026-10-17。

## 问题与调整

在 1280 像素窗口中，旧布局将左侧预览分配为 720 像素，右侧参数固定 240 像素，导致参数名称、来源与控件多次折行。现改为按工作区实际宽度响应的双栏：同一窗口中左侧约 434 像素、右侧约 530 像素。普通参数在同一行显示名称、来源、恢复与控件；字号范围保留明确的最小、最大两个输入，来源信息不重复换行。预览设置宽度上限，窄工作区改为单列。

评论列表与已选区统一使用图标加短文本的定位、保留与翻译按钮；保留状态有颜色及 `aria-pressed`，解除保留与移除仍是不同操作。上下移动合并为按钮组，保留原可访问名称。预览内的返回列表、上屏起点、精确秒数和重试也按同一层次整理。

只改变布局与呈现，不改评论保存、手动保留来源、模型处理、预览请求或时间定位逻辑。尤其保留 `selection_origin` 在预览请求中的原语义，因为手动超长评论的排版和豁免依赖它。

## 宽度比例修订

用户要求参数栏仅占单行显示所需宽度，将主要空间留给左侧。双栏右侧改为固定 500 像素，取消随窗口增长的 `fr` 分配；普通控件列固定 210 像素。按当前字体和完整来源、恢复按钮计算，最长字段约需 495 像素，保留少量余量；未删减名称或隐藏来源。桌面预览上限提高到 960 像素，窄屏规则保持原样。

1616 像素窗口实际分配为左 800、右 500；1280 像素为左 464、右 500。两者所有字段均保持单行且无溢出，390 像素继续改为单列且无溢出。此修订运行 7 项布局回归及构建，均通过，控制台无错误；未重复完整测试。截图为 `comment-workspace-width.png`，测试日志为 `comment-width-tests.log`。

随后按用户宽屏截图调整：桌面预览上限从 960 提高至 1280 像素，右栏从 500 小幅加至固定 520 像素。2560 像素窗口实测左列 1724、预览 1280、两侧留白各 222，参数栏保持 520 且字段无溢出；390 像素继续无溢出。7 项布局回归与构建通过，控制台无错误。本轮仅修改这两个 CSS 尺寸，不改变生成请求或排版产物。

## 评论条目与整页视觉重整

评论资料改为有独立边界和间距的条目，序号、勾选、作者与发布时间、点赞数、评分与选择状态、正文、操作区分层显示。原文对照有明确标签；定位使用淡蓝按钮，手动保留使用淡绿状态，移除与重排单独分组。已选编辑区采用一致的条目结构，突出上屏位置、时间与双语文字，操作从拥挤的标题行移到正文之后；当前预览评论有边界提示。

页头、原文采集工具条、四阶段处理进度和日志入口一起精修，减少嵌套与重复边框。保留原有评分、翻译、手动保留、排序、草稿、确认与锁定逻辑。宽屏参数栏仍固定 520 像素，预览仍最多 1280 像素。为避免中等窗口左侧小于参数栏，工作区宽度不超过 1140 像素时改为上下布局：左侧至少 600 + 参数 520 + 间距 20 是双栏的空间下限。
