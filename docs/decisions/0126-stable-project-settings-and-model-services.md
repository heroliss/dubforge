# ADR-0126：项目制作设置固定，模型服务变更不否定已有结果

日期：2026-10-08。状态：采用。

## 背景

ADR-0058 的实时稀疏继承使保存全局默认或系列模板同时改变已有项目的制作要求。ADR-0080 虽然已经排除密钥和超时，但模型、服务地址和请求参数仍参与文字结果指纹，调整模型服务会沿依赖使配音和成片显示需更新。这种行为不符合用户对“默认设置”和“已完成结果”的预期。

## 决策

- 全局默认和系列模板作为新项目及主动应用设置的来源。项目创建时保存独立制作基础值，后续解析该基础值和项目单独设置，不实时跟随父层的制作参数修改。模板仍可继承全局，供之后创建或应用时使用。
- 基础值、明确配置字段和来源一起保存；人工覆盖独立保存。明确 false、0、空值及等值覆盖保持原意。默认空发布文案不能被误标为人工指定，以免阻止 AI 补全文案。
- 项目参数的恢复操作回到项目基础值。项目总览和批量入口复用设置应用预览：列出实际前后差异和涉及的步骤，确认后应用当前全局或模板，保留项目单独设置。同一来源也可再次应用。应用不会自动制作或投稿。
- 模型与服务配置属于下一次请求的执行方式。修改 LLM 模型、地址、参数或降级顺序不否定已完成文字；未完成任务及主动重新生成使用新的服务配置。项目内容要求、上游文件、文字编辑、音色、字幕样式和审查处理等改变仍正确影响结果有效性。
- 产物有效性和已确认任务的执行合同分开。运行合同继续核对实际模型配置；本轮执行仍使用冻结快照，运行中编辑锁保留。LLM 中间响应缓存继续绑定实际请求配置，主动重做不能误用另一个模型的响应。
- 服务密钥、Cookie 内容、模型连接池及本机并发存储设置不复制到项目制作基础值。代理、Cookie 文件路径、TTS 服务地址与安装目录、等待超时不进入基础值；下一次执行读取最新服务设置，项目明确覆盖仍优先。这些连接和等待参数不改变已有产物有效性。
- 旧项目一次性捕获升级时当前有效制作基础值，保留人工覆盖、制作状态和全部产物，不把当前设置伪造为历史生成设置。项目恢复清单保存基础值及来源，找回后不跟随另一环境的当前制作默认值。
- 旧结果指纹仅在调整前完整输入严格匹配，或可信成功快照证明非执行输入完整相同时升级。缺少历史的未知指纹、失败或运行中的结果不强行宣称有效；媒体文件和发布回执不改写。

本决定替代 ADR-0058/0080 中已有项目实时继承和模型执行参数决定已有产物有效性的部分，及 ADR-0118 中项目恢复操作的动态继承含义。其余稀疏覆盖、并发保护、输入指纹、原子产物及发布确认规则保持有效。

## 验证

隔离测试覆盖创建后修改默认、模板修改、主动应用、人工覆盖及默认文案语义、旧数据迁移与清单找回、模型变更后产物复用、内容修改仍需更新、执行合同核对和有证据的指纹迁移。前端覆盖同来源应用、差异确认、运行锁及固定基础值说明。
