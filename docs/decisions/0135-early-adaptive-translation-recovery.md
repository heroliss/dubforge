# 0135：大窗口结构失败后立即自适应恢复

日期：2026-10-12

## 背景

翻译默认按 100 条字幕行分窗后，真实任务已经能够完成全部 1498 行，但部分大窗口出现了编号重复、乱序或无编号说明。对同一个 80～100 行窗口继续用同一模型重发完整请求，通常会重复产生相同的结构错误，并消耗等待时间；真正有效的路径是缩小窗口，让模型逐句处理。

## 决策

- 对上下文安全、深度为 0 且至少 80 行的正常窗口，结构/协议校验失败后只保留一次短重试；第二次仍失败即进入既有自适应拆分恢复。
- 子窗口仍使用原有重试上限、绝对源编号、边界参考、交接摘要和逐句校对，不采用失败父窗口的部分输出。
- 小于 80 行的正常窗口及所有恢复子窗口继续使用原有三次重试策略，避免把短暂传输或局部缺行误判为结构漂移。
- 翻译窗口版本写入缓存指纹，策略改变后不会复用旧的窗口结果。

## 后果与验证

结构错误的 100 行窗口最多少发一次重复父窗口请求，预期降低等待时间和模型费用，同时保留一次缺行修复机会。自适应恢复仍有明确的总请求上限，不能替代最终内容质量审计。

相关翻译、恢复、提示词、指纹测试共 209 项通过；Python 编译检查和 `git diff --check` 通过。真实任务 #366 的最终产物为 1498/1498 行，旧运行中 3 个父窗口共触发 12 次结构异常，后续均自动恢复完成。
