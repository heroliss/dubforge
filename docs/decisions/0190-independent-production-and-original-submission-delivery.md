# ADR-0190：制作范围与稿件交付目标独立选择

日期：2026-10-17
状态：已采纳

## 背景

[ADR-0189](0189-automatic-production-to-original-bv-update.md) 打通了自动制作到原BV更新，但将入口表述为“合成并更新”，且更新计划始终追加合成步骤。这把制作起点、制作范围和交付目标混在一起：只修改简介也会要求成片，修改翻译或配音后又像是只能从合成开始，已有项目另发新稿也缺少明确的授权入口。

本决策扩展ADR-0189，保留其固定更新任务、租约、产物身份和未知结果保护，并继续遵循[ADR-0182](0182-original-bv-update-and-recoverable-delivery.md) 的原稿更新合同。

## 决策

### 制作范围与交付目标分别确认

- 制作范围使用本次 `production_steps`，可以从任何一个已选步骤开始，也可以不制作而复用已核验结果。依赖规划只补本次实际消费的缺失或过期产物，不因为选择更新原稿而无条件重做识别、翻译、配音或成片。
- 最终交付分别选择仅制作、准备新稿、发布新稿或更新原稿。更新原稿保留原账号和BV，不改变上游步骤的业务含义。
- 更新视频或追加分P时需要实际有效的成片，按所选版本补合成及其必要依赖。只修改文案、分P资料等时不额外追加合成，也不预检无关的配音服务或解析视频制作参数。
- 未显式传制作范围的视频更新沿用项目勾选；纯资料更新默认空制作范围。推导结果写入本次配方，恢复不能默默扩大为全部步骤。未变化产物继续按输入指纹复用，逐句精调不因更新稿件而被自动覆盖。

### 新BV需要独立且仅本次有效的确认

- 普通新稿仍保留重复发布保护。除历史自动流程关联外，具有远端状态及BV回执的手动发布记录也属于已有稿件；只有本地手工草稿不视为已有BV。
- 已有稿件时，用户可以明确选择更新原稿，或在本次运行中设置 `confirm_new_publication=true`，确认另发新稿、原稿保留。此确认只适用于新稿目标，不写入全局或项目默认，不能用来绕过正在执行任务或未知写入的核对要求。
- 新稿流程沿用请求ID和确认指纹去重。重复点击、重送相同请求不能产生另一份稿件；准备草稿与实际投稿获得新BV仍分别表达。

### 更新字段显式选择，视频替换单独控制

- `recipe.update` 保存来源发布记录、`replace_videos`、可选 `sync_fields` 和原CID到版本ID的映射。`replace_videos` 缺省为 `true`，兼容ADR-0189已保存配方；它只决定是否替换既有视频。
- `sync_fields` 明确本次要同步的标题、简介、标签、封面、创作声明、分区、章节、合集、分P名称、顺序、追加分P等受支持内容。显式空列表表示不隐式修改其他资料；省略此字段沿用原先明确配置字段的默认规则。
- 关闭视频替换后仍可以保留原CID与版本映射，用于分P名称和顺序的来源对应。映射本身不授权上传，也不能反向激活制作依赖。纯资料更新只读取版本定义及身份凭据。
- 追加分P是独立范围：即使不替换既有视频，选择追加仍需制作或核验新增成片。已有分P保留，不能把追加勾选解释为同时覆盖它们。
- 能力目录明确区分当前支持与需官网处理的设置。未适配字段不能静默忽略或显示已同步；本次不承诺自动删除分P或修改平台全部设置。

### 完整分P清单与可证明的章节时间轴

- 原CID、版本ID、原上传回执及产物ID/哈希建立对应关系，证据不足要求明确选择，不能按相同标题、位置或时长猜测。
- 远端写入始终由完整最终分P清单构造。只替换所选项，保留其余文件身份；名称和排序按独立授权应用，新增项使用本次实际上传回执。内部计划可用负编号表示尚未上传的新增项，发送前必须替换成真实CID，不作为公共原CID或远端身份使用。
- 更换视频后的章节使用本次成功成片的剪辑快照映射，再绑定新CID。章节翻译、相邻合并、标题改写和审查继续走统一LLM会话与平台硬约束校验，不能套用旧成片时间。
- 只修改已有视频的章节，也必须证明原上传回执、当前CID和成片时间轴一致。无法核验的分P明确保留原章节并显示未覆盖范围；若没有任何可核验目标且也无其他有效动作，预检阻止空执行，不能把跳过伪装为同步完成。

### 相同值按NOOP处理，状态等待按实际范围决定

- 所选资料已与远端一致时保留明确选择意图，但执行时去掉相同字段；分P名称和顺序也先比较完整最终清单。没有实际差异就只读核对并完成，不重复发送编辑请求，也不把同值当作同步失败。
- 没有选择任何更新内容属于缺少运行范围，应在预检说明；这与已经选择但远端值相同的情况不同。
- 仅文案、分区、封面或分P资料更新，以所选资料写后回读为完成依据，不等待旧视频审核，也不因旧稿仍被退回而宣布本次资料修改失败。
- 实际换片、需要可用视频的章节或合集交付仍遵循审核与转码条件。上传、原稿写入、审核、章节、合集和最终回读分别保存进度，避免单一“发布成功”掩盖未完成范围。

### 冻结授权、实际产物与恢复保持独立

- 确认绑定制作范围、版本选择、账号与BV、来源revision、远端version、完整分P、所选更新字段及资料快照。用于可读展示的 `settings_display`、`scope_options` 及告警不参与业务授权指纹，实际待修改标题和分P名称仍属于业务范围。
- 制作参数继续遵循运行时编辑规则：已开始步骤使用其执行快照，尚未执行步骤按既有规则读取当前设置，并保存实际成功产物快照。交付消费本次实际产物ID与哈希，不使用过期预检值冒充成功成片。
- 制作期间原稿或完整分P已变更，交付前暂停核对；不能把同一确认用于另一份远端状态。子任务继续使用固定 `workflow-update-<workflow_id>` 标识及请求摘要，覆盖任务落库与父流程关联之间的中断窗口。
- 已完成上传、原稿写入、章节或合集结果分别复用。恢复已有子任务不重跑制作，不再上传已完成文件。写入结果未知时只读核对，不自动重发；核对与继续剩余写入分开，不能用新任务ID或新BV规避未知结果保护。

## 验证与边界

隔离回归覆盖任意上游范围、纯资料零制作、独立视频替换与追加、元数据映射、明确新BV确认、手动稿件防重、展示信息与指纹解耦，以及真实协调器到原稿更新状态机的仅简介交付。平台、上传和模型均使用替身，不修改真实B站账号。

本决策证明的是应用内部范围、授权、身份和恢复合同。真实稿件能否修改仍受平台能力、稿件状态、权限及审核约束限制；已修正内容也不意味着审核必然通过。
