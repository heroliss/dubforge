# 0081 — 发布阶段与真实传输进度

日期：2026-10-05。状态：采用。

## 问题与证据

项目总览已有独立的最后发布入口，但项目列表只查询制作步骤，容易把“制作完成”理解成“已发布”。发布页仅在上传、暂停和待投稿状态展示一个百分比。固定版本上传 SDK 已提供线路准备、字节传输与远端分片合并事件，原工作进程丢弃阶段；完整分P完成后也没有立即更新字节进度。暂停后未完成分P必须重传，却沿用旧百分比，造成进度含义不明确。

## 决策

- 发布仍独立于制作 `STEP_ORDER`、产物指纹和自动选中步骤，不因为显示第8段就允许制作按钮直接上传或投稿。
- 工作进程只输出准备、传输、合并三个阶段及有界 `loaded/total` 字节；事件里的上传地址、认证信息和其他 SDK 数据不经过边界。节流仅合并同阶段的中间字节，保留阶段变化和最终字节。
- 本地传输 JSON 的保留键 `_progress` 保存阶段、累计视频字节与当前分P。无需数据库迁移；完整分P回执仍独立保留，恢复时只计入完整分P，当前未完成分P从零重新上传。
- 项目列表通过一次数据库查询批量获取本地最新稿件摘要，不读取凭据、扫描媒体或查询B站。摘要包含状态和白名单进度字段；制作完成与B站上传、待投稿、已投稿、公开、仅自己可见各自显示。
- 发布页、项目总览与列表复用同一个进度组件。百分比始终指视频文件字节，100%不代表封面完成、投稿成功或审核通过。封面、提交、加入合集与核对状态显示实际阶段，不为这些无可靠总量的请求编造百分比。
- 重启、暂停与投稿结果不明的恢复保护保持原有边界，不新增自动重投或隐式投稿授权。

## 验证

领域回归以隔离项目、伪账号和伪网络执行真实上传分支，覆盖多分P字节累计、合并与封面阶段、非有限回调过滤、列表摘要、投稿与合集阶段，以及暂停后只复用完整分P。工作进程测试覆盖阶段变化不被节流吞掉、最终字节不丢失、SDK敏感字段不输出。前端渲染真实组件、发布页与项目列表，覆盖上传、封面、提交、待审核、公开与私密状态。没有真实上传或投稿。
