# ADR-0136：允许保存下一次边界生效的运行参数

日期：2026-10-12。状态：采用。

## 背景

步骤在取得并发槽位、进入 `running` 时复制配置快照。配音和大模型任务可能持续数小时；如果把单次请求时限、步骤超时兜底和服务连接地址与当前步骤的制作参数一起锁定，用户无法为后续运行准备更长的兜底时间，也无法在长任务期间修正下一次调用使用的服务地址。

## 决策

- `llm.timeout`、TTS 服务地址与单次请求时限、下载代理/Cookies 路径以及 `runner.step_timeout_seconds.*` 在运行中允许保存。
- 这些值不会热切换当前 `StepContext`；当前步骤继续使用进入 `running` 时捕获的快照。保存后的值从下一次运行或下一步骤建立快照时生效；当前步骤中后续的单句/单请求不会读取新值。
- 当前步骤实际消费的模型、音色、分离和合成参数继续锁定。后端在统一启动锁内按字段复核，前端锁定只是提示，不能替代服务端门禁。
- 运行时限只控制后续任务；正在运行的任务不会因用户修改数值而延长或缩短，避免看门狗与配置写入产生竞态。

## 验证

后端覆盖运行中保存 LLM 请求时限、TTS 步骤兜底和服务连接字段，同时确认当前步骤的制作参数仍返回 `CONFIGURATION_BUSY`。前端覆盖运行中连接/时限字段可编辑而模型参数保持锁定。

长视频的默认 TTS 与 assemble 活动超时为 43200 秒；项目级覆盖仍可在下一次运行前调整。
