# ADR-0027：总览单动作模型与字幕配音同步更新

日期：2026-09-26

## 问题

项目总览曾同时暴露运行、选用、暂停、强制结束、强制重跑和依赖运行等控件。状态不同时按钮互斥规则难以理解，用户容易把“强制重跑”误当作常规刷新入口。「字幕与配音」页合并了字幕导出和逐句配音两个任务，但旧入口只针对 `tts` 生成依赖计划，上游更新后可能遗漏 SRT 导出，也没有明确的“同步最新并重新合成”入口。

## 决策

- 总览是执行看板，不是完整控制台。普通步骤行保留一个复选框和一个“下一步”动作：运行中可停止；依赖未就绪时准备/更新依赖；待运行、过期、失败或中断时运行；结果已最新时不显示运行动作。暂停、取消后的强制结束和强制重跑等精细控制留在步骤页。
- 状态文案合并为“已是最新/需更新/运行中/失败”等单一标签，不再并排显示完成标签、最新标签和自动链标签。产物数量、过期原因和详细日志仍从步骤页查看。
- 顶部仍提供「运行所选」和依赖计划按钮；依赖计划按钮根据当前缺失/过期状态显示「准备依赖并运行」「补齐依赖并运行」或「更新依赖并运行」。选择状态仍保存在 `auto_steps`，未选任务不参与完成度。
- 「字幕与配音」是一个编辑工作流，同步动作统一提交 `subtitles + tts` 两个目标并包含实际依赖。执行顺序沿用产物依赖计划：更新失效上游、重新导出 SRT、再执行配音。已有最新结果自动跳过；逐句配音按句级指纹只重做失效句，未变化且仍可播放的音频继续复用。
- 「字幕与配音」页的依赖提示合并字幕导出和 TTS 的未就绪项并去重。TTS 自身输入完整但存在待配音句时显示「补齐配音」；两项结果都已最新时只保留次要「强制重合成」，用于明确需要忽略缓存的场景。

## 结果

总览从多套互斥控制收缩为可预测的单动作路径；上游更新后的字幕导出与逐句配音由同一个计划带到最新，不会消费旧 SRT，也不会无差别重复合成全部音频。

## 验证

后端计划测试覆盖上游失效后 `subtitles + tts` 同步计划同时包含翻译/配音/字幕导出；前端构建与既有 Node 测试覆盖依赖计划弹窗和执行请求。
