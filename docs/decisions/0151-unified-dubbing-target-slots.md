# 0151：统一逐句、勾选和全部配音的目标槽选择

## 问题

原生成入口隐式覆盖各句当前选中版本。列表中的「新配音（空位）」实际上立即保存静音声源，混淆了试听/成片选用与生成目标；重新合成全部句子难以保留旧音频进行对比。

## 决策

- 单句、勾选和全部入口均打开同一目标槽窗口，范围不随弹窗期间的筛选、勾选变化。
- 2026-10-16 调整：默认覆盖各句当前选用槽，适用于修复与迭代同一声音。用户明确选择共同新槽时，使用项目已有或选中槽的最大号码加一，所有目标句写入同一新槽。显式整数 `takes` 复用既有任务 API，避免 `null` 逐句递增造成不同槽号。
- 可改为各句当前槽，未选槽的句子写入共同新槽；或指定项目已有槽号，缺失的句子在该槽新增，已有音频明确提示覆盖。
- 影响摘要按目标槽物理版本和满意状态计算。过期文件也算覆盖；新槽不抹去旧满意状态。
- 弹窗是本次运行草稿。成功后后台选用目标槽，失败保留原选择与音频；取消不产生写操作。
- 列表下拉框只决定试听/成片选择，空槽改名为「本句人声静音」。补齐入口继续保留已有有效音频与手动声源选择。
- 提交前重新读取后端状态，核对句子、槽清单、音频版本和运行状态；变化时要求重新确认。后台已有开始锁负责同项目任务互斥。

## 验证

前端验证范围冻结、目标切换与影响摘要、取消、运行锁、状态变更、槽号上限。后台通过正式任务入口配合模拟合成器，验证共同新槽、定向覆盖及失败后的旧音频、指纹、生成快照与满意标记保留，不请求真实 TTS。
