# 0113 — 评论准备按需处理与服务退出恢复

日期：2026-10-07

## 背景

手工合成的自动评论准备在评分 94 条中的 93 条后，继续翻译全部评论。第 40 条译文保存后，开发服务热重载退出；后台任务仍发起下一批请求，DNS 线程池报 `cannot schedule new futures after interpreter shutdown`。一条评分被服务商拒绝已经成功隔离，与服务关闭故障不是同一原因。

此前自动准备每次重新联网采样，恢复可能引入新的评论；自动合成还承担了供阅读的全量翻译。评论失败入口默认打开评分日志，容易将翻译或服务退出错误误认为评分错误。

## 决策

- 应用退出先关闭步骤与评论任务的注册入口，再取消排队、在途和自动重试。两者共享最多 5 秒收尾等待；不强杀进程内计算，取消标记阻止收尾后继续下一步。步骤记为 `STEP_INTERRUPTED`，评论记为 `COMMENTS_INTERRUPTED`，保留正式产物、有效评分、译文与恢复计划。强制结束进程仍依赖原子产物和启动恢复。
- 自动准备复用可核验的采集快照。快照绑定来源、热门顶层排序、采集时间和请求上限，明确空样本也是有效采集。首次、来源变化、扩大采集范围或明确刷新才获取；降低上限只限制本次处理 ID，不删完整评论或 AI 缓存。旧快照仅在历史来源明确匹配时兼容。
- 来源变化时重新采集评论也重建正确的视频资料，防止用旧视频的标题和概要评价新视频的评论。
- 自动合成先评分本次范围内的评论，结合本地检查及视频容量按分数挑候选，只翻译实际版本需要的未完成候选，不适用则递补，数量满足即停止。只显示原文的实际版本无需生成中文。**此项替代 ADR-0066 中自动流程全量翻译的决定**；手工全部翻译仍供阅读，另外提供翻译高分候选。
- 局部评分与翻译使用明确 ID 范围；范围校验在请求前完成。局部评分保留范围外仍匹配原文、规则和背景的评分；改规则仍正常使旧评分失效。不会把缺失译文冒充中文。
- 内容生成局部失败可跳过并递补；网络、鉴权、额度、存储等整体错误仍停止。候选递补共享原有翻译阶段 1800 秒预算和最多 24 次额外隔离请求，不因多次调用重置；连续三条独立内容拒绝跨候选组止损。严格策略仍遇错停止。
- 超过 12000 字的单条原文不截断，保留并标记无法自动处理；默认局部跳过让其他评论继续，严格策略提前停止。
- 自动上屏校验实际分P显示语言，不加入没有输出的默认语言要求，也不自动改项目显示参数。内部 `display_settings` 校验范围不可通过 API 请求体绕过；已有有效缓存译文仍参与查看、保存和确认时的内容检查，即使当前只显示原文。过期译文不误伤新原文。
- 自动准备展示真实的采集、评分、筛选、候选翻译、确认阶段，数量来自实际范围，不猜百分比。诊断入口带评分/翻译动作；失败、暂缓和服务商内容拒绝分别显示。普通重试只补失败与暂缓项，不反复发送已拒绝项。

## 边界与验证

完整流程的自动模式仍按本次冻结规则重新挑选，手工合成优先复用已确认方案；本轮统一的是采集与 AI 缓存复用，不猜测旧方案是人工还是机器生成。未来若复用自动方案，需要记录来源与准备指纹，避免忽视新的评分规则和上屏数量。

隔离 pytest 覆盖关闭注册竞态、排队取消、在途产物保留和恢复、采集来源/范围/空样本、局部缓存保存、候选翻译及递补、服务错误停止、实际显示语言、隐藏译文检查、严格策略和共享预算。前端测试与隔离浏览器检查动作诊断、失败计数、重试编号和页面入口；不调用真实 LLM 或投稿。
