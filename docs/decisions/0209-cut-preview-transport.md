# 0209：剪辑预览共用帧时间轴与独立连续预览

状态：采用。日期：2026-10-19。延续 0207、0208。

## 问题

播放器控件按原媒体秒数定位，而删除跳过依赖低频 `timeupdate` 事后纠正，会导致后退与逐帧落在删除区、接缝重复定位和删除内容短暂露出。当前成片、原片编辑坐标及短片段试听又各有不同零点，必须显式映射。

## 决策

保留一个可见剪辑播放器。原片完整时间轴负责标记、恢复和保存原片坐标；开启剪辑效果预览后，播放器的进度、总时长、快进快退、拖动和逐帧统一使用 `CutPreviewTimeline` 的剪后坐标。先映射到保留媒体帧，再写入 `currentTime`。连续按键使用尚未完成的最新定位目标，避免解码器滞后导致重复操作同一帧。

纯数学工具按帧向外量化删除边界，使用半开区间；媒体总帧数及当前媒体读数单独容忍千分之一帧的舍入误差，删除边界保持严格量化。真实 Chrome 的 `currentTime` 会把 1904.233333333 返回为 1904.233333，不能因此误判回删除区并反复定位同一帧。帧率优先读取当前成片或试听文件实际值，不假定等于原片。

即时播放通过唯一截止计时器和视频帧回调守住边界。切点前捕获一幅安全画面，寻址缓冲期间冻结显示；暂停、seek、清单变化及销毁均使旧回调失效。浏览器主线程调度和解码仍可能带来短暂停顿，不把即时寻址宣传为无缝媒体剪辑。

需要连续核对接缝时，显式生成独立预览文件。默认仅处理最近接缝两侧各约五秒；完整清单必须显式选择。纯删除单来源复用 `segment_cut`；恢复或混合来源使用统一精确拼接。来源、量化后的实际 segments、窗口和渲染版本共同绑定缓存，输出文件未变化才可复用。预览不登记正式成片，也不读取当前制作设置。

短预览的播放器零点属于试听文件，返回原片位置只能经过实际 `segments`。接缝归于下一保留段，不能返回删除前终点。切换预览文件和重新准备预览时保留原片定位；在完整原片时间轴定位到短预览范围外，自动回到即时预览并在媒体就绪后恢复位置。过期响应不得替换现有画面，已排入的过期任务应取消。

## 界面

即时预览与连贯预览共用播放器和清单；明确展示剪后位置、对应原片位置、预览窗口、准备进度和缓存状态。展开剪辑时工作区占用整行，暂停并收起旁边的成片播放器和其他参数，避免双重预览。恢复来源仅在需要恢复片段时显示，旧版清单载入作为次要折叠操作。正式生成另存版本的入口保留在清单末尾。

## 验证

覆盖分数帧率、帧边界、首尾删除、空保留区、跨接缝连续逐帧、迟到寻址、暂停与取消、短窗口源坐标、缓存失效与重启复用；通过实际浏览器检查控件、删除跳过及连贯预览。
