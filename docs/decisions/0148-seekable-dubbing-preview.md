# ADR-0148：单句配音可定位传输与异步同步

状态：已采纳。日期：2026-10-14。

## 问题与证据

在真实 Chrome 中，同一句内通过视频按钮暂停后恢复，视频时钟从 3.86 秒前进到 5.68 秒，单句配音时钟却持续停在 0～0.001 秒。配音处于反复 seeking 状态，尽管文件已完整缓冲，浏览器报告的 seekable 范围仍为 `[0, 0]`。

单句 WAV 接口将 Range 请求当作普通请求，返回 200 和完整文件。同步器发现音频落后后不断写 currentTime，无法定位的音频反复回到开头；同时没有等待已发起的异步定位完成。此前仅检查播放/暂停状态、使用同步定位测试替身，不能验证声音实际前进。

## 决策

- 单句配音支持 GET、HEAD、Range 和 If-Range，沿用 Starlette 的范围解析。单次响应先完整读取短音频快照并关闭文件，再发送内存切片；不让慢速预览占用 Windows 文件句柄或妨碍同名版本原子替换。
- 视频保持唯一播放时钟。音频 seeking 期间不重复定位，不启动新的播放请求；seeked 事件及时重新核对最新视频时间，避免帧调度或后台标签页节流造成等待。
- 保留暂停、跳转、版本替换、释放媒体与旧异步请求失效规则。定位保护不改变句子时间、配音内容或制作产物。

## 验证

后端隔离测试覆盖范围响应、HEAD、无效范围、版本条件与文件替换。前端测试模拟定位尚未完成时仍返回旧时间，检查多个帧及 canplay 不重复发起定位、seeked 能恢复同步。

浏览器验证必须观察实际视频和配音时钟在同一句暂停恢复后连续前进，并确认单句 seekable 覆盖完整时长；仅 UI 显示「播放中」不作为修复成功的证据。

本次真实 Chrome 验证：首句 seekable 从 `[0, 0]` 变为 `[0, 8.106406]`。通过内部播放按钮恢复后，音频时钟从 3.05 秒连续前进到 4.95 秒；另在第 3 句通过点击画面暂停恢复，音频时钟从 2.17 秒连续前进到 4.06 秒，视频同时从 14.38 秒前进到 16.22 秒。验证使用 8611 测试后端，没有重启用户常驻后端。
