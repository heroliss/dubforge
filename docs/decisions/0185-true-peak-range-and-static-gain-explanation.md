# ADR-0185：真峰值可调范围与固定增益解释

状态：采用。日期：2026-10-16。补充 ADR-0172、ADR-0183。

## 问题

成片真峰值的前后端范围固定为 −6 至 −1 dBTP，将保守建议变成不可调整的边界。另一方面，“保留动态，尽量接近目标”容易被理解为必定达到指定 LUFS；当整轨真峰值很高、总体响度很低时，固定增益只能保持或减小音量。短试片的局部测量、当前设置、历史版本设置也不能互相替代。

## 决策

- 真峰值可设范围统一为 **−6 至 0 dBTP**，默认仍为 **−1.5**。共享参数 schema、配置保存、版本校验及音频处理入口保持一致；大于 0 和非有限值继续拒绝。
- 在有效声音处理模式下，选择 **高于 −1 dBTP** 的值时，在参数附近显示简短非阻塞提示。恰好 −1 不提示；关闭最终处理时不把未生效值当作当前风险。全局、项目与版本使用共用组件和一致的悬浮说明。
- `normalize` 名称明确为“保留动态（仅固定增益）”，保留算法语义：`min(目标所需增益, 峰值允许增益)`。仍计入 0.3 dB 内部余量，并在实际 AAC 编码后检查；不为保证 LUFS 而暗中改为动态压缩。
- 静态处理报告附带编码前的 `requested_gain_db`、`available_gain_db` 和 `headroom_db`；`gain_db` 继续表示包含可能 AAC 纠偏的实际固定增益。旧报告缺少新字段时正常显示，不伪造数字。短试片可显示其沿用的整轨方案，但不据局部 LUFS 判断整片达标。
- `uniform` 继续在峰值空间充足时用线性增益，必要时使用动态响度处理。完整无损主轨供试片和成片复用；扩大参数范围不改变已有设置与产物，也不自动重生成。
- 目标 **−16 LUFS** 保持为产品默认，不宣称是 B 站标准。用户认为偏轻时可试听 **−14 LUFS**，两者相差 2 LU；原片仅作同范围对照，不自动决定目标。最终总体响度不替代人声与背景平衡。

## 依据与边界

[FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm) 的 TP 允许范围是 −9 至 0；本产品保留下限 −6，仅开放用户要求的上限。其线性处理在峰值空间不足时可以回退动态；本项目的 `normalize` 则明确选择保持固定增益，不使用这种回退。

[Apple 播客音频规范](https://podcasters.apple.com/zh-cn/support/893-audio-requirements) 给出约 −16 LKFS 的建议，可作为语音内容的参考，但适用平台不同，不能据此推导 B 站要求 −16。DubForge 的默认值是制作取舍；−14 或其他目标应通过同范围试听、峰值和处理方式一起判断。

允许 0 不意味着建议把峰值顶满，也不能保证后续其他平台转码后仍保持相同峰值。程序保留编码后复测及必要纠偏，显示实际测量结果。

## 验证

真实 FFmpeg 隔离样本覆盖 0、−0.5 两种新边界、静态与动态模式对照、调低目标的线性衰减、AAC 峰值纠偏及编码后峰值；配置和前端覆盖默认值、三层范围和提示条件。以本轮诊断记录为验收结果，不以历史测试状态代替当前验证。
