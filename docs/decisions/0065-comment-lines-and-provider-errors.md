# 0065 — 评论逐行协议与服务错误分层

日期：2026-09-29

## 背景

新一轮评论评分中，第一配置返回 HTTP 400 / SensitiveContentDetected，却被当作专属参数不兼容重发；备用配置返回空正文（部分请求仅有 reasoning_content），又被误报为 JSON 校验失败，触发多轮无效格式纠错。旧记录没有保存结束原因，不能据此断言备用配置是审核、预算耗尽还是服务异常。

## 决策

- 评论评分与翻译改用编号逐行文本，不要求模型生成 JSON。翻译为 `编号. 译文`；评分为 `编号. 分数 | 是或否 | 简短理由`。请求同样使用逐行正文与标题化背景，平台长 ID 只保留在程序映射中。
- 每批编号稳定，定向重试、拆分批次均沿用原编号。正文中的换行统一编码成字面量 `\n`，原有反斜杠编码成 `\\`，解析只还原这两种转义。内部存储格式、评分标尺、缓存版本与输入指纹不变，已完成结果继续复用。
- 重复项、坏分数、未知编号和裸换行不能被静默拼接、猜测或截断保存；有效项先落盘，只补失败编号。保留原先三次纠错、最多一次拆半的界限。全局配置中的 response_format 仅在本次评论配置快照中移除，原配置不变。
- HTTP/SSE 结构化错误、明确拒绝、空正文与长度截断，在输出解析之前分类为稳定错误码；reasoning_content 永远不是最终答案。记录 finish_reason、用量与思考字符数；降级链保存各服务商原始错误原因，面板显示响应结束事件。
- 任意 HTTP 400 不再自动剥离全部专属参数。只有响应明确表示某可选参数不支持时，移除点名参数并重试一次，绝不删除 model/messages。不改写输入规避审核。沿用用户已经配置的服务降级链；服务失败不触发评论格式纠错、拆分或自动工作流重启。

## 验证

使用隔离项目、伪模型与 HTTP MockTransport 覆盖：中英文与反斜杠/换行往返、管道字符、重复与漏行、裸换行部分结果保护、编号稳定、既有缓存、内容拒绝不降参数、真实参数不兼容、流式与非流式的空响应/截断/拒绝、SSE 错误、降级链错误保留。测试不调用真实 LLM、不上传或投稿。
