# ADR-0098：运行期间按影响范围锁定编辑

日期：2026-10-07。状态：采用；替代 ADR-0075 中允许运行期间编辑设置的交互决策。

## 背景

正在执行的步骤使用启动时的设置快照，而修改勾选项只会影响下次运行。两种行为同时出现在界面上，会让用户难以判断当前流程究竟采用哪一套设置。用户要求运行期间禁止修改勾选项和设置，仅保留能够实时生效的显示偏好。

## 决策

- 编辑门禁由领域层统一判断，界面禁用仅作提示。项目正在排队、执行、停止收尾、逐句配音或上传投稿时，拒绝修改该项目的执行勾选、设置和可编辑产物。
- 项目设置只检查本项目；系列设置检查绑定项目；全局执行设置检查所有项目。其他闲置项目仍可编辑，创建独立项目或空模板不受无关项目影响。
- 远程等待审核与审核状态查询不占用本地执行资源，允许编辑下一次使用的设置；已确认的发布快照继续保持冻结。
- 检查与短暂写入使用任务启动的共同门禁，避免“检查时空闲，保存时已开始”的竞争。停止、取消等明确运行控制保持可用；流程内部必要的写入保留已有执行身份授权。
- 全局设置的实时例外使用明确白名单。目前只有 LLM 输出的显示追赶距离；保存时同时刷新已打开的显示组件。混合提交显示偏好和执行设置时，整批仍按执行设置检查，拒绝后不部分写入。
- 前端共享同一作用域的状态查询，暂停隐藏页面轮询并清理订阅。首次核对和查询失败时暂时禁用编辑并解释原因；后端保留最终检查。

## 仍然保留的保护

每个步骤的配置快照、结果输入指纹与自动流程边界检查继续存在，用于检测外部文件修改、重启后设置变化及历史流程恢复。保存等待超时、轮换连接密钥等不改变产物内容的配置仍不使制作结果过期。

本机请求总时限沿用用户保存的 1800 秒。个人配置包含密钥，继续由忽略的 `config.yaml` 保存，不写入仓库。

## 验证

覆盖项目、系列、全局的作用域隔离，运行与排队状态，单句配音、上传投稿和审核等待的区别，显示白名单及混合提交拒绝，执行勾选保存，以及界面锁定和共享查询清理。完整验证结果记录在[验收文档](../research/runtime-edit-locks-2026-10-07.md)。
