# ADR-0119：分P文件对应关系与状态驱动的发布布局

状态：已采纳，2026-10-08。

## 背景

发布页原来分别展示分P名称编辑行和可选成片列表，已选名称与实际文件缺少直接对应关系。用户难以判断一个成片是否就是一个分P，也容易把多个成片版本当成多条投稿。已投稿记录继续占据完整的草稿表单，当前文件列表和项目设置又可能与当时的确认内容不同，增加核对回执和恢复未完成任务的成本。

## 领域关系

一个发布草稿引用同一项目的多个视频产物。每个 `draft.parts` 元素包含唯一的 `artifact_id` 与分P标题；一个视频文件对应一个分P。数组顺序就是 P1、P2 等投稿顺序，调整顺序仅调整这份引用清单，不改动或重新合成文件。

全部分P属于同一个稿件，正式新稿投稿后取得一个BV号，共用账号、稿件标题、封面、简介及发布设置。分P名称只决定B站显示的分P标题。程序不按选项自动切片，也不因同时选择多个版本而分别创建多个BV。多项目的合集顺序发布仍按 ADR-0115 独立管理。

## 决策

### 显式展示视频对应关系

`PublishPartsEditor` 将每个已选分P呈现为一张卡：P序号、可编辑的B站分P名称、对应成片的版本名与效果、实际文件名、大小、定位入口和当前审查提示。草稿按 `artifact_id` 与候选的 `id` 匹配，不按显示名称或列表位置猜测。

候选区单独标为「可添加的视频」。加入后明确显示「已加入 Pn」，不提供第二个重复加入入口；未加入的文件标明下一分P编号。上移、下移、移除使用明确文字与可访问名称，并在组件与父页面两层核对权限、重复引用及数组边界。组件只发出操作事件，不写网络或直接修改父组件的草稿。

需要审查修订的候选保留可核对、可选的能力，并展示明确理由。页面确认区与服务端上传预检共同阻止使用已知未满足当前规则的文件，避免把审查标签混同为B站审核结果。

### 按状态组织页面

| 发布状态 | 页面重点与可操作范围 |
| --- | --- |
| 本地草稿 `draft` | 顺序展示准备视频、投稿资料、确认发布、进度与回执。视频、名称、顺序、账号和资料可以编辑，项目运行锁仍生效。 |
| 已上传 `uploaded` | 优先展示上传状态，已确认视频清单默认折叠。账号、封面和文件保持冻结，文字资料仍可保存，再确认正式投稿。 |
| 排队、上传、提交、加入合集、状态核对 | 优先显示进度和回执；原确认内容放在只读折叠区，按状态提供暂停等已有操作。 |
| 暂停或上传失败 | 优先显示错误与进度，确认区提供继续发布；沿用已确认清单并复用已完成分P。 |
| 已投稿、审核通过或退回、待加入合集 | 优先显示BV、审核说明、退回原因与合集结果。复制草稿、审查修订等次级操作放在对应状态的操作区。 |
| 投稿结果待核对 `unknown` | 明确提示可能已投稿成功；先在B站核对并关联BV回执，保留禁止重复投稿与复制的约束。 |
| 来源项目不可用的独立记录 | 只读展示当时保存的稿件信息与平台回执，不重新解释为可编辑草稿。 |

`PublishResultPanel` 统一状态、错误、上传阶段、BV回执、审核和合集说明。稿件标题位于编辑区顶部；主要阶段使用一致的面板层级。视频准备、文案生成、保存以及正式发布各有明确位置，其他发布方式默认折叠，减少并列按钮造成的选择负担。

### 冻结内容只采用记录证据

已确认分P按 `snapshot.parts` 展示文件路径、大小、时长及配音标识，不使用今天候选的版本名、审查状态或本地存在性替代旧记录。快照缺少文件信息时显示「原文件信息未记录」，不把缺失证据解释为上传失效。

已确认稿件资料使用确认快照中的设置与来源；当前项目的继承值不能倒推旧稿件内容。来源项目不可用且仍是本地草稿时，只展示草稿当时保存的文案与覆盖项，未记录的继承值保持未知。已上传且尚未正式投稿的文字编辑仍基于该记录保存的设置，保存后由原有接口更新稿件记录。

### 区分未读取、刷新与文件缺失

首次读取前、读取失败和刷新期间保留全部已选分P。界面使用单独的读取状态与错误信息，不因候选暂时为空就宣称文件丢失。候选读取完成后，缺失或已不在当前列表的选项保留原分P行，引导还原文件后刷新，或移除后选择其他视频。明确缺失或状态尚未确认的候选不能新增。

本地缺失提示只影响草稿核对，不推翻既有远端上传或BV回执。确认上传时仍由服务端检查文件可用性、内容指纹、审查状态和确认范围。

### 保存与发布分别表达

资料编辑区提供「保存资料」与「放弃修改」，并说明只作用于本地草稿。「上传并投稿」是主要发布动作，执行前沿用原有的预检、确认范围、权利说明及AI声明流程；「仅上传文件」保留在次级操作区。界面引导未保存资料、文件信息未读取、文件缺失、审查待处理、账号、标题或封面未准备的用户回到对应阶段。

账号连接、校验和已有BV管理继续位于「设置 → B站账号」。项目发布页提供清楚的跳转入口，不重复建立账号管理工作区。账号读取失败明确表达读取错误，不解释为登录失效。

## 兼容与边界

本次调整复用原有发布API、草稿结构、确认指纹、上传断点、投稿与回执处理，不新增数据库状态或另一套文件清单。草稿保存不会启动制作、上传或投稿；前端的准备状态引导不替代服务端校验。关闭页面不会停止已确认的后台发布任务。

新稿和审查修订草稿仍产生新BV，原稿保留。原BV的视频替换仍需B站创作中心操作；追加分P保持已有视频，不能当作替换。投稿结果不明时维持人工核对优先的恢复路径，不能利用复制草稿绕过防重复约束。

## 验证

真实组件测试覆盖分P与文件映射、顺序变化、标题与文件名不同、重复添加、越界操作、未读取与缺失、冻结快照缺项、运行锁和审查提示。发布页状态测试核对各状态的布局、可操作范围、资料保存、主次发布动作及回执恢复约束；视觉验证由页面整体完成。
