# 0030 — 获取视频时整理视频信息

日期: 2026-09-27

## 背景

「获取视频」此前只保留基础 `media/meta.json`（标题、文件名、大小），用户需要在别的页面或
工具里反复查看标题、来源、作者和描述。为了在下载完成后马上给用户可参考、可复制的材料，
需要自动整理中文标题和内容概要，并集中显示平台元数据。

## 决策

1. **来源元数据随下载采集**：yt-dlp 在 `after_move` 阶段用 `DUBFORGE_META_*` 前缀输出
   JSON 标量，包括视频 ID、标题、作者/频道、上传日期、时长、播放/点赞数、页面链接、
   extractor 和多行描述。结构化解析失败只降级为空元数据，不影响视频文件下载。
2. **新增用户信息产物**：`artifacts/download/video_info.json` 保存 `title_original`、
   `title_zh`、`summary_zh`、`description`、`source`、`summary_status`、`summary_note`
   和生成时间。旧 `meta.json` 继续保留给项目列表和旧逻辑使用。
3. **LLM 只做增强**：网络视频在拿到标题/描述后调用 LLM 生成中文标题和可确认的概要；
   本地视频没有内容证据，只生成基础信息，不猜测剧情。LLM 失败、超时或输出无效时，
   中文标题回退原标题，概要留空并记录状态，下载步骤仍成功完成。
4. **升级与幂等**：已有视频但缺少 `video_info.json` 时，普通重跑会跳过下载并补生成/
   登记该产物；重新下载会基于新的 yt-dlp 元数据刷新信息。产物写入继续走原子替换。
5. **前端展示**：获取视频页在视频预览后新增「视频信息」区块，分区展示中文标题、
   内容概要、来源信息和作者描述；标题、概要、来源、描述均可一键复制。窄屏纵向堆叠。
   产物注册表同步声明该文件。

## 后果

- 下载步骤可能额外发起一次轻量 LLM 请求；失败不会破坏视频链路。
- 本地导入无法在转录前提供可靠内容概要，界面明确说明该限制。
- 网络来源缺少描述时，系统不会编造概要，只展示已确认的来源元数据。

## 测试

- `test_run_ytdlp_collects_structured_source_meta`：解析 JSON 标量和多行描述。
- `test_download_generates_video_info`：生成中文标题、概要、来源、描述并登记产物；
  信息文件缺失时跳过下载也能补齐。
- `test_download_video_info_survives_llm_failure`：LLM 失败时下载仍完成并降级。
