# 0024 — 所有配音统一为后台步骤任务

## 原因

列表原先由页面循环请求单句合成。刷新后当前 HTTP 请求可能继续完成，但后续句子不会再提交，也无法使用步骤的统一进度和控制。

## 决策

- 单句、合成所选、补齐配音和重合成均由现有 Runner 执行 `tts` Job，共用并发限制、日志、配置快照、暂停、取消和超时处理。页面一次提交整个选择，不保存执行队列。
- Job 保存本次句号、目标版本及逐句结果。刷新或切换页面后重新读取任务。后端退出仍按既有崩溃恢复规则标为中断，保留已完成版本，不自动重启第三方合成请求。
- 所选句子按时间轴去重执行；选中版本覆盖，空位新增。只检查所选句子的依赖，只有成功生成才改为选用该配音。手动选择任务不续跑其他步骤。
- 顶部进度衡量本次任务，按预估朗读时长加权，并计入服务端当前句的真实进度；剩余时间沿用成功工作量和本次平均速度估算。错误与复用音频不贡献成功测速量。未知单句进度不模拟百分比。
- 顶部和逐句进度使用同一前端平滑插值工具。插值只追赶已收到的进度，不靠固定时间虚构完成量。
- 后台配音期间保留视频、播放位置和试听操作。工作台轮询逐句结果（约 1.5 秒），新音频按带版本的 URL 接入现有时间轴；只替换相关语音，不重建视频。此规则替代 ADR 0021 的重合成前释放全部媒体；下载或音轨分离重建上游媒体时仍暂停预览。
- IndexTTS 缩时重试在临时文件中挑选结果，本句结束后才替换正式音频。单句音频响应读完即关闭文件，网络发送使用内存快照，避免 Windows 上慢速媒体请求阻止覆盖；长视频和背景音继续流式读取。
- 本次所选任务完成不代表整份文稿已配齐；音频是否可用于成片继续由产物依赖判断。失败句和成功句一同保留；任务失败不掩盖为旧版本仍可用。

## 验证

覆盖断开客户端后继续、同一任务在列表和步骤中可见、句内进度、暂停/继续/取消、单句失败后继续、版本选择、无效请求和旧库迁移；保留原有字幕编辑与成片测试。
