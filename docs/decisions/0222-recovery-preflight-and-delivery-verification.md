# 0222 恢复前检查与实际交付核验

日期：2026-10-20

## 背景

配音服务是独立进程。后端重启后，原请求的结果可能未知；直接反复恢复会各产生一条失败任务，但不能解除服务占用。恢复界面同时显示上次失败与新请求，也容易造成误解。发布后的章节交付还可能把模型服务不可用误报为章节内容校验失败。

## 决定

- 制作预检在实际需要生成或修复配音时检查未知请求，并提供等待、无其他任务时重启配音服务的说明。预检不删除占用记录，不把正常在途请求或只复用已有音频的计划当作故障。
- 恢复必须沿用原任务、批次、目标槽和发布回执；先确认服务器已受理，再观察真实新任务或发布后处理状态。确认中、提交中、已受理和实际执行分别呈现，旧失败留在历史，不混作当前进度。
- 未知发布/更新写入必须先核验；恢复不新建另一个稿件绕过原回执。已完成视频上传、更新、审核只处理后续未完成阶段。
- 发布交付的完成以平台回读为准，包括 BV、分P CID、审核、合集归属/顺序和章节。源章节与剪辑后时间范围按通用映射处理，不设置项目专属判断。
- 显式恢复重新计算本轮耗时，保留历史失败与过程；排队拒绝给出可恢复错误并释放占用。
- 强制重启前未收尾的历史阶段按旧终态或“已中断”结束，结束时间采用旧活动时间，不把恢复间隔记为工作时间，也不把未确认的工作标为完成。
- 配音排队期间可能尚未形成固定生成范围。文稿数量与本次生成、复用数量分别呈现；缺少尚未准备的范围不应引发界面异常，真实接口错误和损坏数据仍须说明。步骤进度与配音统计均以当前 Job 为边界，不能混入上次任务的句数或失败。
- 首次读取步骤状态时显示正在读取，接口失败或缺失状态时说明尚未核对；已有真实快照保留。只有已读取且明确待运行的状态才显示待运行。
- 同一稿件较新的独立更新已核验后，共享导航采用该结果；正在执行、未知写入、其他稿件或缺少先后证据时，不用历史成功覆盖当前处理状态。

## 验证范围

隔离 pytest 与浏览器夹具验证恢复即时反馈、作用域、防重与失败可解释性。真实运行单独保存请求意图和回执，平台读写均通过已有发布协议，遵守两阶段确认与未知结果保护。

实际长任务记录在 `data/diagnostics/autopublish-20261020/`；本目录的配置/数据库备份仅本地保存，不入版本库。恢复受理及暂停批次细节见 ADR 0223。
