# ADR-0186：过程预览与完整产物分离

状态：采用。日期：2026-10-17。补充 ADR-0001、ADR-0132。

## 问题

翻译逐窗口完成时直接写入正式 `translate.txt`。重新翻译的后续窗口失败，会将上次完整结果变成部分结果；单纯使用临时文件再原子改名只能保证文件字节完整，不能保证业务结果完整。强制重做启动及强制结束收尾也会删除上次结果。

界面中还有相同的证据边界问题：状态请求失败只能证明本次读取没有成功，不能证明执行线程已中断或请求未送达远端。

## 决策

1. 翻译窗口的过程快照保存到 `cache/translate/progress_<job_id>.json`，独立原子写入，不登记为产物、不参与下游输入和制作指纹。窗口响应缓存继续按原指纹校验和复用。
2. 所有窗口完成并通过取消检查后才原子替换、登记正式译文。强制重做穿透窗口缓存；开始、失败、取消和强制结束都保留已有完整译文。步骤状态与指纹继续约束自动流程的下游使用，保留文件不等于本轮已完成。
3. 普通产物读取始终读取正式文件。只有显式 `?preview=true` 的翻译预览才能读取最新任务的部分快照，并通过响应头标记部分结果和完成数量。新任务不能读旧任务快照。状态列表仅检查快照存在性，不在轮询里反复解析长译文。
4. 初次运行还没有完整产物时，界面也可显示本轮部分结果；首个窗口完成前明确显示等待，失败后仍可查看已完成部分。过程文件清理失败不能否定已完成的正式结果。
5. 导航状态按来源保留最后成功结果、核对时间及错误类型。网络错误、超时、HTTP/格式错误分别呈现；一个来源恢复不能掩盖另一个来源仍然失败。连接失败不提供“后台已停止”的保证。

## 后果与边界

- 保持现有 runner、配置快照、窗口缓存与原子文件工具，不增加第二套执行状态机。
- 部分译文是查看与诊断资料；配音、字幕导出仍使用正式译文和步骤门禁。
- 已被旧版本删除的完整译文无法由本改动恢复；本改动保护之后执行的任务。
- 正式文件和多份旁车文件尚非一次文件系统事务；状态仍在完整步骤结束后公布成功。跨文件原子提交需要单独设计，不能把过程快照当作解决该问题的事务系统。
- 发布预检的项目占用仍保护本稿件，但耗时哈希不持进程级全局锁；上传流在事件循环读取，磁盘与数据库操作在线程执行，取消等待当前写入结束后再清理。
