# ADR-0084：制作结果可查看更新原因

日期：2026-10-06。状态：采用。

## 背景

输入指纹能回答结果是否仍符合当前制作要求，却不能从摘要还原修改了哪项参数。项目列表的「需更新」也混合了制作要求变化、上游过期和文件缺失；配音步骤还可能只是部分句子缺少有效音频。

## 决策

- 保留现有指纹与按实际产物解析的依赖规则。将指纹的输入表示抽成同一个函数，更新说明复用它，不另建一套失效算法。
- `StepRun.input_snapshot` 保存最近一次成功正式制作的脱敏输入快照。执行器先用本轮冻结的配置和项目覆盖计算实际指纹，再捕获快照；运行中改设置不能改写本轮生成历史。失败、取消、试片、仅合成选中句子及缓存跳过不补造全量成功历史。
- 自动评论准备和评论筛查在编码前最终确定，版本渲染器按实际安全方案捕获输入，成功后才提升这份快照。常规版本的有效性检查使用同样的评论筛查规则，避免工作区保留被排除评论就误报成品需更新。明确多选组合包含流程默认成品时，默认流程指纹和整批方案指纹各自核验。
- 快照只保留允许公开的制作参数和输入摘要。连接凭据、Cookie、代理、完整本地路径和字幕正文不保存、不返回；未知自由内容以摘要表示。快照随恢复清单保存，旧数据库增加空快照列。
- 按需只读接口返回已核实的前后差异、来源、上游变化、缺失文件和实际依赖下游。列表轮询仅返回轻量状态，详情不触发制作或改变项目。
- 历史只有指纹、快照损坏或快照范围不对应当前结果时，不猜旧参数，不将当前配置当作历史生成配置。最近失败时若保留上次成功快照，说明只比较上次成功输入，当前文件仍需核验。
- 项目列表、流程总览和步骤页共用详情界面。配音按有效选用音频报告待补句子；独立审查修订成片仍按自身配方核验，不因为常规文字步骤需更新就要求重新制作修订成片。
- 更新说明直接合并到需更新标签：悬停或键盘聚焦按需读取最多三条简要变化，点击打开完整对比，不重复放置说明按钮。摘要和详情共享同范围在途读取与短时缓存；关闭、切换项目或输入状态变化时取消旧读取，迟到响应不能改写新上下文。项目的制作状态与旧结果有效性独立展示；有失败或运行步骤时，其它已失效结果仍显示需更新标签及原因入口。项目列表的需更新筛选可与失败等制作状态重叠；权威结果仍有效、仅失败或运行的步骤不冒称需更新。

## 验证

隔离测试覆盖参数与模型变化、与制作无关的设置、上游及文件问题、脱敏、旧数据缺历史、失败与试片不覆盖成功记录、运行中改设置、清单恢复和详情接口只读性。前端验证三个入口、差异与来源展示、未知旧值及配音缺句文案。
