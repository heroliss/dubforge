# 0227 按当前目标判定本地制作完成

日期：2026-10-20

状态：已实现，隔离验证；生产后端待所有任务空闲后载入。

## 问题

项目空间原来通过 `selected_steps` 判定制作完成。未保存历史 `auto_steps` 时，该函数默认包含所有步骤，导致按目标制作已经完成、所选成片均有效的项目，仍因独立字幕文件没有导出而显示“待处理”。前端的同一文件又明确提示字幕导出可选，因此卡片状态、完成筛选和实际目标不一致。

简单过滤字幕也不正确：历史接口可能明确选择独立字幕导出；而成品展示的 `assembly_state` 只核对已有成品，新加入目标但尚未生成的版本不会让其他旧成品失效，不能据此直接认为全部当前目标完成。

## 决策

新增只读 `project_execution.production_completion`，`dependencies.project_status` 仅改变本地制作完成的读取合同：

- 所有真实 running/queued 步骤仍优先显示 processing，不能让已有成品遮住当前活动。
- 明确保存的历史 `auto_steps` 列表保留原有精确选择语义，包括独立字幕导出、空列表和所选步骤失败。供旧链/批量执行使用的 `selected_steps` 本身不修改。
- 没有历史明确选择时，读取当前已保存设置，通过既有 `production_selection` 和 `bind_recipe` 获取本地目标及发布替换/新增分P确实消费的额外版本并集，按已解析版本的真实依赖闭包核对。
- 每个目标版本必须独立通过 `assembly_versions.is_current`，不能借其他历史成品的展示 fresh。实际消费的上游步骤还需各自新鲜，改识别/翻译等生产者设置时仍显示待处理。
- 纯原片版本沿用 `uses_source_directly` 与实际输入就绪检查，不要求制造一个不存在的编码产物或 AssemblyResult。全部目标均直用原片时，历史编码/配音/导出失败不属于当前合同；任一目标需要字幕、配音、评论、剪辑、音频处理或审查静音时，仍保留编码失败与成片证据检查。
- 纯资料原稿更新不因空生产集合冒称制作完成：本地制作维度仍检查已保存本地成片目标。发布状态、章节终态与此维度分开，不从 publication=published 推断本地完成。
- 未能确定目标、设置/引用不可核实时保持待处理；当前目标中的失败显示 failed，未采用的历史失败不阻挡当前目标。读取不执行完整 workflow 预检、不调用模型或平台、不创建任务/产物、不修改配置或指纹。

## 范围

本次只调整通用状态判定，不改变成片/语音/字幕的业务指纹、缓存命中、正式产物、执行调度和发布权限。项目列表已有状态计数与筛选直接使用后端 status，得到正确 done 后自然进入“制作完成”；独立字幕文件依旧保留自己的步骤状态与入口。

实测现场列表6项目一次读取8.655秒；单项目0bab6c已有0.405秒与本次0.330秒（36,636字节）的只读证据。该耗时差不能直接归因某一个项目或 freshness 子调用。本轮不禁用新鲜度、不引入持久“完成”缓存、不在独立生产Domain进程启动恢复/profile；性能另行用有边界证据定位。

## 验证与部署

隔离 `DUBFORGE_DATA_ROOT` 测试覆盖可选导出、显式导出、未生成新目标、未采用旧版本、设置失效、上游设置变化、文件丢失/改写、活动/失败、源片直用、纯资料更新和发布额外版本。对真实 `_project_view` 检查 done 与 subtitles=pending 同时成立，读取前后参数及已有成片指纹保持不变且没有新Job。

生产后端尚未载入本修改，也没有为UI状态重启活跃服务。待剩余实际任务全部完成、全局空闲，再与服务owner控制台交接安排载入，并只读验收项目状态与已有交付回执；不得因此重跑已完成视频或单独导出字幕。
