# ADR-0212：项目空间返回快照与读取复用

日期：2026-10-19。状态：采用。

## 背景

项目空间在每次路由进入时重新等待完整项目摘要。长配音项目和多个成片版本会重复读取相同音频记录、计算排布；并发轮询进一步放大磁盘访问。界面因此在返回时长期空白。

## 决策

- 前端 Pinia 只保留项目列表数据快照，活动项目和归档项目分别存储。返回时并行读取工作区身份与完整列表：身份核对后先显示该目录上次的卡片，同时后台更新。选择、弹窗、轮询与组件生命周期一起销毁，不保留整个页面实例。
- 工作区身份由实际数据目录计算，只读接口 `/api/projects/context` 不扫描项目产物。完整列表响应携带同一身份；两者不一致时禁止将列表保存到错误目录的快照。旧后端或身份读取失败时降级为实时列表。
- 创建、导入、改名、归档、恢复及删除使相关快照失效；离开页面后到达的写操作回执不能用旧数组覆盖新页面，也不能写入另一工作区。缓存只用于展示，执行与删除权限继续由服务端实时核对。
- 后端合并同一工作区与归档范围的在途列表请求，结束即释放，不对新鲜度结论设置跨请求 TTL。手动刷新和写操作后的刷新携带 `X-DubForge-Refresh: fresh`，独立读取以免加入写操作前的请求。批量读取已有数据库摘要，减少每个卡片重复查询。
- 同一依赖读取内复用配音记录解析和排布计算。缓存包含设置、台词和文件身份，文件变更、替换或删除后重新核对；返回对象隔离，避免调用方修改共享结果。

## 验证

隔离测试覆盖重复工作量、并发合并与失败释放、文件变更和删除、工作区身份、返回快照、迟到响应与写回、活动/归档范围隔离。真实项目只读测量；浏览器在 8611 隔离服务中验证慢列表响应期间的返回显示与后台更新，保留截图和诊断记录。
