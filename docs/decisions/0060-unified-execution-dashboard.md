# 0060 统一执行看板与单次运行确认

日期：2026-09-28

## 问题

总览的发布行沿用独立发布时期的固定提示，未读取执行终点。自动流程单独轮询完整配置且吞掉读取错误；评论处理和准备发布资料期间，制作步骤均空闲，界面可能允许竞争运行。等待审核仍出现新建流程入口，重复稿件阻塞直到启动才提示。运行检查需要打开、检查、确认、再确认，信息却分散。

## 决定

- 总览以「自动运行」为主入口；「仅运行勾选制作步骤」归入手动制作区域。完整流程按各步骤生效配置和版本依赖运行，手动勾选不扩大或缩小它的范围，也不授权投稿。不新增配置副本。
- `/workflow/status` 返回轻量本地摘要：当前执行终点和来源、本次任务冻结终点、制作游标、阶段、关联稿件状态及既有流程稿件标识。它不扫描成品、不调用模型或平台、不携带完整配置/凭据快照。
- 导航 store 统一轮询摘要，总览、侧栏及步骤页共用状态。制作、评论、发布准备阶段均视为流程占用；等待审核不再显示新建运行。当前默认终点与历史任务终点分开显示。
- 发布状态优先显示本次关联稿件；尚未创建稿件时根据流程阶段显示尚未开始、等待制作完成、准备资料或流程待继续。开启自动投稿只是执行策略，不伪装成已开始上传。
- 运行抽屉打开即只读预检，终点和当次权利确认变化后重新检查。抽屉展示账号、分P顺序、可见范围、定时和合集，是唯一的完整范围确认；确认按钮明确区分仅制作、准备草稿和制作投稿，不再重复弹确认框。启动与恢复的后端校验、指纹和权利边界不变。
- 预检可以取消并丢弃晚到响应；启动请求同一预检沿用 UUID，网络失败重试不新建运行。启动回执即时更新看板，旧轮询不能短暂回退为空闲。
- 预检提前展示已有流程、等待审核、制作占用和既有稿件等阻塞；恢复预检校验运行记录归属。最终启动锁内仍保留原有校验，不能依赖页面状态判断安全性。
- 已进入发布阶段的失败仍到发布页处理，投稿结果不明绝不自动重投。批量运行沿用相同终点名称，并在意图改变时重新检查。

本决定调整 ADR-0027 的总览主操作位置和 ADR-0052 的确认交互；保留 ADR-0058 的单一设置继承、后台调度与明确投稿授权。

## 验证

领域测试覆盖轻量只读摘要、当前配置与冻结任务的分离、既有流程提前阻塞、恢复归属，以及制作到发布集成、停止、重启、未知回执不重投。真实 Vue 组件和 store 测试覆盖不同终点、确认范围、双击、请求重试、检查取消、旧响应隔离、阶段衔接及等待审核入口。所有数据与外部服务均使用隔离测试；不对用户实际项目制作或投稿。
