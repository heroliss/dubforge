# ADR-0061：下载失败保留源视频与可诊断重试

- 状态：已采纳（2026-09-28）
- 背景：网络读取超时暴露了下载重建时提前删除旧源视频、错误详情只写入任务记录、全局下载归档可能让缺失文件仍被跳过的问题。

## 决策

1. 网络视频先下载到 `media/.download-*.tmp/` 独占目录，取消、失败只清理该次临时结果。下载器成功返回、结果位于该目录且为最终视频名、ffprobe 确认有效视频流及正数有限时长后，先改为 `.tmp` 文件，再在同一磁盘原子替换正式文件。校验不做全片解码。
2. 强制重跑下载不提前删除既有视频、资料或产物登记；失败状态阻止把旧产物当作本次已完成结果。成功后更新元数据与登记，再清理旧容器格式。若旧格式被占用，源定位优先遵循 `meta.json` 的安全文件名。
3. 不再使用全局 yt-dlp 下载归档或外部 yt-dlp 配置；复用只能由本项目实际文件、状态和输入指纹决定，归档中的 ID 不能证明源视频仍然存在。
4. 使用 yt-dlp 原生有界重试：连接读取超时 30 秒，HTTP/分片错误最多各重试 5 次，指数退避 1–10 秒；保留一次下载过程中的续传，不跳过缺失分片。本次最终失败后清理临时下载，后续手动重跑不承诺跨任务断点续传。仍受步骤总时限及取消控制。
5. 保持 `DOWNLOAD_FAIL` 错误码，按超时、限流、登录验证、403、代理连接、格式和磁盘错误提供中文提示。原始错误和重试事件写入步骤日志，去除结构化进度、URL 参数及 URL 凭据。前端不再对所有历史失败笼统承诺“正式产物会保留”。

## 验证

隔离测试覆盖普通/强制重建失败、取消/强制结束、校验失败、路径越界、空文件、旧格式切换、原子替换失败、归档不误跳过、已安装 yt-dlp 参数解析、错误 API 与实际步骤页渲染。真实短样片仅在测试临时目录生成以验证 ffprobe；不访问用户视频或发布账号。

## 取舍

- 替换前需要额外磁盘空间存放旧视频和新下载/合并的临时文件。
- 本修复不能恢复此前已被旧逻辑删除的源视频，也不能保证外部网络恢复。
- 重试参数依据 [yt-dlp 官方文档](https://github.com/yt-dlp/yt-dlp#download-options)，并以本机安装版本的参数解析测试验证。
