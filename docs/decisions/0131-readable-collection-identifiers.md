# 0131 — 合集显示名称与稳定 ID

## 决定

发布批次、发布设置和顺序发布页面优先显示从B站账号资料读取的合集名称；同时保留 `ID <season_id>`，以便用户在改名、同名或旧记录场景下核对目标。小节名称作为次级上下文显示。

合集名称是显示快照，不是远端对象身份。顺序发布请求仍只使用账号、合集 ID 和小节 ID；显示快照单独保存在批次方案中，不进入制作或发布指纹，因此B站改名不会让批次失效。

旧批次和读取不到名称的记录继续使用“合集 · ID <season_id>”回退文案，不猜测名称，也不把导入序号当合集名称。

## 原因

单独展示类似“合集 9202389”的数字不能帮助用户识别目标，而仅显示名称又无法处理同名合集或平台改名。名称加稳定 ID 同时满足可读性和可核对性，并兼容已有只保存数字 ID 的数据库记录。

## 2026-10-15：统一全流程与恢复预检的展示资料

全流程、任务恢复及批量流程的预检复用 `settings_display`，单稿件发布预检也返回相同结构：账号名称、分区路径、合集名称和小节名称，以及对应账号和目标 ID。前端优先以名称帮助识别，ID 保留在补充信息；缺少名称时明确提示“名称未载入”，不推测平台对象名称。

`settings_display` 是预检结果的独立展示字段，不写入发布设置或冻结投稿快照，也不进入运行、恢复或发布确认指纹。合集改名、补充名称或名称读取时间变化不会改变用户确认的业务目标。

在线预检直接复用原本需要读取的平台元数据，不为显示名称增加网络请求。元数据读取成功时仅原子保存账号相关的名称快照；离线检查和重启恢复可读取该快照。缓存按数据目录、账号 ID、账号版本及当前授权凭据的不可逆摘要隔离，重新登录或切换账号不能沿用其他授权的资料；缓存不含凭据原文。显示快照读写失败、结构损坏或缺少目标时降级为空名称，不阻断原有预检。

展示字段使用 `source` 和 `fetched_at` 区分本次平台读取与最近读取快照。缓存名称只用于识别，不代表合集当前存在、权限有效或投稿目标已经核验；这些判断继续由原有在线预检负责。顺序批次保留既有 `scope_display` 历史快照，并可从匹配账号和目标 ID 的子项目计划中获得统一展示资料，不在批次列表中逐条发起额外平台请求。
