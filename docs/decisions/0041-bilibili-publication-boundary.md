# ADR-0041：独立发布中心与可替换的 B站通信组件

日期：2026-09-27。状态：采用；真实账号联调待完成。

## 证据与选择

- 用户的实际账号支持一个稿件多个分P，共用基本/更多设置，并加入合集。以当前账号实际能力为准，不用旧的合集规则阻断它。
- 视频制作和平台投稿具有不同生命周期：标题、标签、合集调整不应让字幕、配音、合成过期。
- biliup 的常用高层上传入口包含提交稿件。当前选择 `@renmu/bili-api`，独立调用单文件上传、Web V3 投稿、合集与状态接口；不接入其高层自动投稿入口。
- npm 最新版本为 2.15.2；2.15.1 在上传链路加入 `rejectUnauthorized:false`，2.15.2 增加线路黑名单并保留这一改动。固定使用 2.15.0；锁文件把 `fast-xml-parser` 覆盖到 5.7.0，处理依赖审计发现的问题。升级必须重新检查证书校验、SDK 请求结构、分P、合集及失败恢复，不能只改版本号。
- 新版分区使用 `human_type2`；兼容字段 `tid` 留在适配层，不在页面让用户选择两遍分区。

## 领域与界面边界

1. `dubforge.publishing.service` 是发布资料、继承、校验、上传状态与回执的领域入口，不依赖 FastAPI。`app/api/publishing` 仅封装 API。SQLite 新增独立表，不写制作步骤配置或指纹；不向 config.yaml 添加账号信息。
2. `workers/bilibili` 是 Node 通信进程，通过有界 JSONL 与 Python 通信。每次调用核对账号 MID；视频分片并发限制为 3，稿件操作按队列串行执行。Cookie 仅通过匿名 stdin 管道传递，不在命令行、第三方日志、API 响应或 LLM 请求中出现。
3. Windows 当前用户 DPAPI 加密保存凭据。非 Windows 平台不退化为明文。重启不会自动重投；服务退出会取消上传/扫码，已发送的投稿不能被撤回。
4. 一个 DubForge 项目的一组显式选择成片形成一个稿件，文件顺序即分P顺序。也可显式加入已登记的原声原片（MP4/MOV/MKV），不为发布而重复转码；外部本地引用必须与项目原片路径精确匹配，不能传入任意文件路径。稿件归入一个所选合集小节；合集模板是 DubForge 的发布默认值，不等同于创建/修改 B站合集。
5. 设置优先级为本稿件覆盖、合集模板、账号默认、全局默认、视频资料/内建默认。`false` 和 `null` 是明确选择，不能被后层的默认值覆盖。尚未上传的草稿跟随模板，确认上传后的继承基线固定。

## 三个显式动作

后续交互更新见 [ADR-0049](0049-confirmed-upload-and-submit.md)：新增经过一次确认的「上传并投稿」主操作，仍保留仅上传与上传后独立确认投稿；底层副作用边界不合并。

- 保存：只保存本地资料；新草稿分P为空。封面可手动上传，或由用户点击导入已采集的 YouTube 平台封面。
- 上传：预检发布权利、新版分区、声明、标签、文件归属/哈希、16 GiB 上限及 10 小时时长。确认稿件修订号与快照指纹；开始传文件前重新读账号能力。早期预检失败回到可编辑草稿，不发送视频。完成文件上传仅表示“待确认投稿”。
- 投稿：再次明确确认账号、分P数量、可见范围、合集和发布时间，重新校验声明与账号设置，直接调用一次 Web V3 接口，不重试、不切换其他投稿接口。响应丢失进入“待核对”，禁止重投/复制，用户填写 BV 后按有序 CID 列表核对回执。

上传后允许修改标题、简介、标签、声明、定时等稿件资料，递增修订号并要求新确认，不重传视频。账号、模板、分P、顺序和封面固定；更换这些内容需复制新草稿。父级默认值变化不反向改写上传快照。

完整分P上传结果逐个保存；中断后只复用已完成分P，未完成分P重新上传。不承诺跨进程分片续传。成功回执先持久化，再加入合集；合集失败只重试合集，查询状态不能吞掉“待加入合集”。已有回执的记录不允许进入重新上传路径。仅自己可见的通过状态与公开发布分开显示。

项目删除经领域提供的保护上下文检查发布任务，并统一先取得发布锁、再取得平台资料锁，避免与草稿读取的锁顺序倒置。删除源项目后发布回执仍保留，不删除 B站稿件。

## 创作声明的适配

后续变更：[ADR-0050](0050-advisory-ai-declaration.md) 将下述 AI 声明的本地强制要求改为建议及一次提醒。枚举与接口兼容性校验仍保留，平台要求未改变。

声明优先读取平台返回的明确枚举；缺少枚举时使用同一作者在 [biliLive-tools PR #454](https://github.com/renmu123/biliLive-tools/pull/454/files) 公布的版本化映射：-1 无需标注、1 AI、2 虚构、3 营销、4 个人观点。接口返回其来源，不假称全部选项是当前账号实时返回。

该集成仅在 `copyright=1/3` 传创作声明，转载通道不传。DubForge 对含 AI 配音与旧格式配音成片要求 AI 声明；不能把“转载＋AI声明”当作已生效。用户需核对官方页面适用类型，选择其他创作声明不表示获得转载授权。映射、分区、账号限制及多P合集的最终行为仍需受控真实联调。

## 范围与验证

- 第一版包含扫码连接、资料/模板、多P上传、单次确认投稿、现有合集选择、基础水印互动、可见性/定时、状态/回执与恢复保护。
- 不包含自动创建合集、商业推广/付费活动、章节/CC字幕上传、杜比/Hi-Res、64 GiB 权限探测，也不在合成完成后无人确认自动投稿。这些不能用空控件冒充支持。
- 域测试以隔离数据与伪账号/网络执行，工作进程测试执行实际调度分支，前端测试渲染真实 Vue/Naive UI。审计检查证书校验没有被关闭，npm 审计为零已知漏洞（不等于无风险）。没有用用户账号真实上传/投稿；浏览器连接不可用，尚未完成截图视觉验收。
- 本轮最终验证：后端全量 707 项通过（两条既有依赖弃用警告），前端 148 项、通信组件 11 项通过，生产前端构建通过。安装脚本语法检查通过。未启停 8600 常驻实例。
- 上游为 GPL 项目，对外分发前核实并遵守许可证要求；单独进程不是免除许可证义务的理由。
