# ADR-0099：LLM 思考参数预览与主动取消网络请求

日期：2026-10-07

## 问题

步骤选择 low 时，适配模型的 reasoning_effort 会覆盖专属 JSON，thinking 会被移除；未适配模型保留 JSON。原界面只在帮助文字说明，容易误以为所有模型都已降为 low。自定义 JSON 的 model 还能改变实际使用的模型，适配判断必须按最终值进行。

停止原来仅设置协作式取消事件，同步 HTTP 读取需要等到下一条数据才检查。模型静默思考、等待响应头或接口回退到非流式响应时，都可能长时间无法停止。

## 决策

- 保留 low / follow_profile 和旧 fast 别名；不增加全局配置，不改服务商适配边界。按最终 model 判断是否支持 low。
- 参数 schema 附带安全的思考摘要，仅含配置组名称、启用状态、适配能力和白名单思考字段。表单按当前未保存的档位、模型选择逐个展示下一次请求的生效值与覆盖关系；运行中的任务仍使用启动快照。
- 专属 JSON 的其余字段保留，选择跟随模式时不覆盖思考参数。连接测试使用原始专属 JSON，说明这一差异。
- 同步流水线接口保持不变；HTTPX AsyncClient 在请求独立事件循环中执行网络 I/O，调用线程每 100ms 检查取消信号。取消时取消网络协程并关闭响应、客户端和事件循环。
- 响应头、SSE、JSON 整体读取及两种非流式兼容回退均使用同一取消机制。取消和步骤超时直接抛回执行器，不进入网络重试、协议修复或模型降级链。
- 取消日志和 LLM 对话明确记录“本地请求已取消 / 服务端未确认”。当前 Chat Completions 适配器没有服务端取消确认，不能把断开连接表示成服务端已停算或已停止计费。

## 验证

新增异步模拟传输覆盖响应头等待、静默 SSE、JSON 读取、stream 回退和专属参数回退，核对协程取消、流关闭、无重试/降级和无网络线程残留。真实 TCP 检查仅使用 8611 测试端口，在返回响应头前后观察对端 EOF/连接重置。

新增安全摘要与最终模型覆盖测试；前端使用真实 ParamControl / StepView 渲染，检查 low 覆盖、跟随 JSON、未适配模型、降级链和取消事件。既有流程及参数测试继续运行。

落地验证：完整后端测试 2222 项通过（2 条既有第三方弃用警告），完整前端测试 431 项通过，前端构建通过。8611 的真实静默连接测试确认取消后对端收到 EOF/连接重置。应用前确认所有项目均无运行任务，更新构建后恢复 8601 服务，实际 API 已返回新的参数摘要。
