# 0228 批量逐句读取复用项目参数解析

日期：2026-10-20

状态：已实现、隔离验证；生产后端尚未载入。

## 证据与边界

项目列表6项现场耗时8.655秒。只做两次串行普通项目GET后，旧项目68d3b9单项9.540秒（响应6,331字节），中国全史32777f为4.443秒；Unity0bab6c此前0.330秒。列表已有最多4线程和在途读取合并，仍需等最慢项目；这个慢点发生在服务端核验，不能归因前端渲染或响应体积。

只读SQLite元数据查询6项目和步骤/产物合计0.0584秒。最慢项目1642句、1642个take侧车，其params只有48字节；中国全史params为10,335字节，另一个历史项目29,043字节。因此重复解析不是已证实的9秒主要原因，不能把下面局部收益宣称为生产列表整体已恢复。

源码确认 `render_lines` 逐句调用 `selection`，每次默认 `crud.project_params→json.loads`；依赖解析的逐句 `effective_config→overrides` 也重新解码同一个项目JSON。这是可以在保持业务结果的前提下独立消除的重复工作。

## 决策

- `Dependencies.read_project_params` 在当前依赖读取对象内保留原JSON字符串和解析后的只读参数。原字符串变化即重新解码；不同冻结project传入时按其真实字符串核对，不借用另一个项目对象的覆盖值。
- 没有Dependencies的 `render_lines` 也只在本次函数调用解析一次，再用已有 `selection(..., params=...)` 传给逐句选择。
- `line_settings.overrides/effective_config` 增加可选只读params；依赖配置循环、实际朗读读取和TTS指纹/旧缓存核验复用当前快照。独立调用未传params时仍按原语义自行解析，兼容只提供cfg/arts的旧读取上下文。
- 不修改 `crud.project_params` 的返回隔离语义，不建立跨请求持久缓存，不把参数解析结果当作freshness/可复用结论；文件身份、指纹、当前目标、改写/删除/替换检测全部保留。没有修改完成scope合同、制作产物或业务指纹算法。

## 验证

隔离合成512句、377,696字节的同一参数JSON：原调用方式解析1024次，优化路径1次；一次实测0.774638秒与0.005365秒，声源选择和逐句有效参数完全相同。耗时仅作局部证据，不作为不稳定的测试断言；测试严格断言次数和结果等价。

另外覆盖：独立调用不共享可变结果、同Deps原JSON变化、不同冻结project、新Deps读取已保存修改、错位句identity与坏JSON回退、同输入指纹完全一致及实际逐句设置更改后正常失效。关联覆盖/朗读/依赖/列表/时序/旧缓存/目标合同回归均使用隔离数据。

生产未重启、未读生产媒体作profile或全量哈希，未调用模型/平台，也没有重跑视频。旧侧车缺少可直接核验的line_snapshot时，`dubbing_edit.recorded_line`仍会按原语义直接读取项目JSON，此路径本次未优化。剩余慢点中，多路逐句文件身份复核与历史快照处理只是候选，尚缺函数级耗时证据；不得为了提速跳过核验或扩大跨请求缓存。所有Python改动仍等待当前视频交付完成、全局空闲后统一载入，再有边界地验证真实列表耗时。
