# ADR 0093：实时输出与历史补齐的显示策略

日期：2026-10-07。状态：已采用。

## 问题

步骤页的逐字动画只按文字长度追赶，未判断模型请求是否结束，也未处理后台页面暂停动画的情况。后台期间模型已经完成，回来后仍可能从旧前缀缓慢播放完整输出；已收到完整响应但缺少时间戳时还可能显示“生成中”。历史补读以有效事件数是否等于500判断，也会漏掉因过滤记录而不足500条的后续页。

## 决策

- 只在页面与LLM对话面板可见、步骤仍运行、请求未结束、历史已补齐时，对新的思考/输出增量做平滑显示。完成、取消、失败及首次历史加载直接显示已收到的内容；完成状态不依赖时间戳能否解析。
- 隐藏页面或关闭面板时暂停对话读取与动画，回来时先同步已有内容，再按字节游标补齐后台新增记录。模型在后端继续运行，不发送模型取消或重跑请求。
- 使用接口的 `more` 标记补读分页，兼容旧接口的500条约定；游标不推进时停止立即补读，避免半行尚未写完造成空转。
- 请求串行化，登记分页定时器；离开页面时取消前端日志请求、清理动画和定时器、移除可见性监听。已取消或卸载后的响应不能再更新内容。
- 运行日志在历史、结束或不可见状态也直接同步；保留用户向上滚动时停止自动跟随的行为。

## 验证

真实步骤页组件以隔离的请求、时钟和动画帧验证大段完成输出直显、首次空记录后完成、后台恢复后新增内容动画、短页的 `more` 补读、游标停滞、取消及结束状态、关闭面板与释放迟到请求。新增8项回归，步骤页70项通过；不调用模型、不启动浏览器或生产任务。SSR测试显式调用状态同步函数，不把SSR渲染当作浏览器挂载测试。

前端完整439项测试及生产构建通过，常驻服务返回的首页已与最新构建一致。
