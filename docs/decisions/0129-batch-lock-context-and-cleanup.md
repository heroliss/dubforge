# ADR-0129：顺序批次锁定范围与失败清理

日期：2026-10-09。状态：采用。

## 背景

顺序发布批次会提前登记所有尚未完成项目的租约，以冻结已经确认的制作方案和发布顺序。原有界面只展示“批次运行中”，排队项目看起来像当前项目正在执行；当后台线程池拒绝入队时，数据库可能已经写成运行中，项目也会暂时保留租约。

## 决策

- 批次仍对所有未完成项目保留执行租约。排队项目允许查看项目和批次进度，但不能单独运行步骤、启动自动流程、修改制作资料或归档；这样不会让已确认的批次计划与后来修改的项目状态混用。
- 项目批次状态同时返回项目位置、项目自身阶段、批次总阶段、项目状态和锁定范围（`current` 或 `queued`）。前端用同一套中文说明展示“第 n/total 项”“等待前项完成”“正在处理”或“停止收尾”，并提供批次进度入口。
- 租约错误必须包含可操作的恢复路径：先查看批次；批次暂停或停止并完成后台收尾后，项目才恢复单独运行和编辑。
- 后台执行器入队失败时，立即清理运行句柄、项目租约和子流程绑定，并将批次落为 `attention`，保留原确认资料，要求重新检查后继续。不能留下数据库运行状态而没有后台执行线程。
- 批次正常完成、暂停、停止、失败和服务重启仍统一走原有 finally/recover 清理路径；清理失败时宁可继续锁定并要求重新核对，也不能误报为空闲。

## 验证

覆盖排队项目位置与锁定范围、详细锁定错误、暂停/停止释放租约、线程池入队失败清理，以及项目总览和统一运行入口的批次提示。未改变批次对外投稿、排序和稿件回执的安全边界。
