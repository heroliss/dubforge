# 嵌套批次按完整登记关系识别工作流身份

日期：2026-10-20。状态：采用。

统一批量运行的合集分组由顺序发布子批次执行，子批次再启动工作流线程。原先父批次仅识别直接工作流和子批次调度线程，未识别子批次的工作流，导致合法任务在获取视频前被自己的占用保护拦截，随后显示批次暂停。

- 顺序发布子批次统一提供 `child_owned(uid)`，只识别该项目当前租约中登记的精确工作流 ID。
- 父批次识别孙工作流时，核对当前父租约、子租约、子计划中的父批次 ID，以及父分组的类型、项目和子批次 ID；父、子和分组必须仍处于活动状态。
- 不移除占用检查，不把身份从请求参数传入，不给任意工作流继承父批次权限。外部启动、无关流程和关联已失效或暂停的批次仍拒绝操作。
- 修复只改变内部执行身份识别，不改变已确认的配方、发布目标或回执。已有失败流程仍使用原 ID 恢复，避免新建重复任务或稿件。
- 回归必须保留真实工作流线程和 Runner 入队、执行、产物登记及收尾；仅替换物理下载或外部平台边界。直接把工作流启动替换为完成状态，无法验证跨线程门禁。
