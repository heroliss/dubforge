# ADR 0171：运行中的逐句配音更新

日期：2026-10-16。状态：采用。补充 ADR 0022、0132、0147。

## 决策

- 普通项目、模板与全局制作参数继续按步骤冻结。只为用户明确保存的逐句声音参数增加运行更新入口；原文、译文、时间、结构、声源和槽位不借此解锁。
- `PUT workbench/lines/{id}/params` 默认 `execution=auto`：空闲时只保存，不创建任务；已有 TTS 任务时，参数和排队意图在启动锁内同一次项目数据库写入中提交。`execution=save` 仅保存下次使用，不能暗中改变本次后续句。
- 逐句 revision 从 0 递增，可通过请求中的 revision 乐观并发检查。按句合并重复更新，正在请求的设置不可变；请求中再次修改，完成后只额外执行最新一版。
- 当前请求结束后、下一个普通句开始前优先执行精调队列。按 2026-10-16 最新交互约定，修复和精调默认覆盖当前选用槽；缺少当前配音才选合适空槽。新槽用于用户在生成操作中明确选择的声音比较，不因精调自动增长槽位。成功后需重新试听，旧满意记录不再适用于新音频；失败保留原声音和满意标记，继续原批任务，不自动无限重试。
- 新 WAV 及其声音元数据先写不占配音槽的私有候选；全部就绪后发布到目标槽，选槽、产物索引、队列成功和任务目标回执在同一数据库事务提交。发布期间的临时回滚副本只用于失败恢复，成功立即清理，不作为用户版本保留。元数据、回执、提交失败或取消恢复旧文件及纳秒时间戳；manifest 副本重建失败不回滚或误报已提交的成功选择。
- 失败更新可用 `execution=retry` 明确重试已保存设置，不递增设置 revision、不创建新任务；只附着仍接收更新的当前任务，重复点击排队中的重试不会再添一次请求。新槽已满等本句错误也只标本句失败，不能阻断原批次。
- 本次运行原先选择“统一使用项目参数”只影响原计划。运行中显式精调代表更新后的用户意图，排队请求使用保存时的逐句覆盖与本次冻结的项目底值；声音快照记录实际 revision 与来源。
- 最后一轮精调检查和停止接收共用启动锁。进入最终排布/缩时后 `auto` 明确拒绝，用户仍可选择仅保存供下次使用。停止先到不再提交新请求，停止期间的 `auto` 不会另起任务；成功结果提交也复核取消状态。
- 持久队列存于独立项目控制键 `_tts_live_updates`，不参与音频内容指纹。进程重启后的旧请求显示中断，只能经用户明确继续/重新生成恢复，不能偷偷运行。文字时间身份不符的旧精调拒绝执行。
- 没有运行中逐句更新时，仅使用执行上下文里的接收门闸，不向项目写空队列；普通合成和纯时间修复不应改写任何项目参数。旧轮控制记录不再覆盖新一轮的运行状态，历史回执仍留在原 Job。
- 工作台、句子参数接口与列表统一展示 saved / queued / running / done / failed / interrupted，区分设置 revision、正在运行 revision 和待处理 revision，便于判断“已保存”和“已应用到声音”。

## 验证

隔离服务替身覆盖当前句冻结、未来句更新、同句更新合并、请求中再修改、跨句状态保存、失败保留旧槽、停止与最后关闭竞态、仅保存、统一项目策略、历史满意保留及重启中断显示；不调用真实模型，不改用户运行服务。
