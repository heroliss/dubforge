# 0165 按平台约束整理视频章节

日期：2026-10-15。状态：采纳。补充 ADR-0142、0163、0164。

## 问题与证据

项目 a0d290 的源视频有 21 条章节。原实现强制标题一对一翻译，再到提交预检读取规则，导致 21 条译文必然超量；重试复用旧标题缓存后仍然失败。该次没有生成章节修改计划，也没有发送章节写请求，视频投稿已成功。

2026-10-15 对该稿件首P仅执行规则读取，实际返回 `limit=10, stay=5, space=0, max_title_length=16`。当前官方播放器编辑器脚本也以此为默认值。首章从 0 秒开始、至少 1 秒，首个内部分界因而至少在 1 秒处；其余章节（含最后一章）至少 5 秒。10 个章节对应 9 个内部分界，不能误将所有章起点向后移动 1 秒。标题按网页 UTF-16 长度计数，非 BMP 字符占两位。

证据：[官方编辑器脚本](https://s1.hdslb.com/bfs/static/player/editor/editor.ab6a7a86.js)。文本编辑器的最少两章约束没有推广到所有 API 写入路径，现有单章与清空能力保持兼容。

## 决策

1. 源视频资料与发布候选分离。保留完整源目录，对实际上传成片映射后的章节进行平台适配；剪辑不同的P分别整理，相同时间轴和规则复用合格结果。
2. 模型是章节编辑：按主题合并相邻源章节，翻译或改写短标题。只能输出连续分组的首尾源编号和标题，不得输出或决定时间。必须完整、顺序覆盖每一条输入；不能仅截取前十条、漏章或重新排序。
3. 程序以源分界及实际成片时长计算整数秒，遵循网页 `Math.round`。首章补齐0秒，末章到视频结尾；检查数量、首章1秒、其他章5秒、末章、重叠和UTF-16标题长度。默认安全上限10章/16位，实际稿件更严格的规则优先；规则禁止章节时不尝试靠模型绕过。
4. 自动任务先逐P读取实时规则，再生成和校验方案；正式修改计划和提交前再次使用网页协议检查规则与远端版本。模型输出不合格最多两次带具体校验错误修正，仍失败则保留来源和已完成P，不发送无效写入。
5. 缓存键包括整理器版本、映射后章节、成片时长、翻译策略、有效规则、自定义标题要求和视频总标题。保存方案再次本地校验后才复用。旧 `translation` 仅是一对一标题，没有平台适配证明，不能当作新方案缓存。已完成P不重写，写入结果不明仍只读核对，明确重试只补章节而不重发视频。
6. 中文翻译开关仅决定标题语言。两种模式都让模型审查全部最终标题，不能因形式合规就跳过内容审查。只提供一个可继承、可冻结的 `publish.chapters_instruction` 自定义要求入口，覆盖内容关注点、格式、表述和术语；平台硬限制仅展示，不作为用户可改参数，候选API也不接受自定义规则覆盖。通用本地候选与项目草稿消费同一领域逻辑，手动同步保留预览、确认和回读。
7. 页面展示规则、输入/结果数量、各章来源与实际时间。自动交付结果可以展开；手动编辑优先保留远端已有章节，远端为空时可以载入本次自动任务保存的整理结果。草稿生成不直接写B站。
8. 整理和标题内容审查在同一次模型请求完成，返回可核验的审查回执与指向实际输出分组的问题原因。模型无法准确改写的条目保留候选并交人工核对，自动任务不提交。审查结论不冒充B站审核通过。版本升级使无审查回执的旧候选重新规划；新增空要求不改变旧发布记录身份，仍可独立重试章节。
9. 全部模型对话通过 ADR-0166 的统一底层与页面展示，包括请求、回复、返回的思考、校验和重试；不再以只有字符计数的阶段信息代替对话。

## 取舍

硬校验能保证结构与时间合法，不能证明每次语义合并都最优；因此保留完整源章、来源映射、可编辑候选和失败重试。不会用机械丢弃、强行截标题或模型虚构时间作为无提示兜底。

平台权限、数量和间隔仍可能随账号/稿件变化；默认约束用于提前整理，不能代替最终实时预检。当前没有增加另一套配置开关或任务状态机，整理诊断沿用 execution 与 Publication.chapter_sync。
