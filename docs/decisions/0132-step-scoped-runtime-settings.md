# ADR-0132：按步骤冻结运行设置并分离更新维度

日期：2026-10-09。状态：采用。

## 背景

项目运行时把整个项目、全局设置和模板统一锁定，导致排队任务及尚未开始的步骤无法调整。与此同时，设置变化会被误解为所有下游产物都必须重做，用户无法区分“本步设置变了”和“上游文件真的换了”。

## 决策

- 排队任务保持可编辑。步骤取得并发槽位时，在启动锁内将状态从 `queued` 切换为 `running`，随后读取全局配置和项目参数，形成不可变的执行快照；这一刻之后只锁当前步骤实际消费的设置路径。其它步骤、其它项目、全局默认和模板仍可编辑。
- 运行快照不保存密钥等原始敏感配置。`Job.task_data.execution_snapshot` 保存脱敏输入快照和配置摘要，成功的 `StepRun.input_snapshot` 保存本次可用于新鲜度比较的历史输入；登记的 `Artifact` 同时记录 `job_id` 与配置摘要，manifest 也保留这两个关联字段。
- 更新状态拆成两个独立维度：`settings_changed` 表示当前步骤设置相对上次成功执行发生变化，`upstream_changed` 表示输入产物、文件或上游登记摘要发生变化。下游只在上游执行成功并产生不同产物摘要后标记需更新；上游仅设置变化不会向下游传播。排队中的上游可以继续使用已有产物，真正运行时再按快照决定新产物。
- 全流程同样按阶段取快照。评论准备阶段读取当时的评论设置，合成阶段按确认的版本选择重新解析当前制作设置；发布阶段继续使用已确认的发布合同，避免账号、封面和分P意图在制作完成后悄悄改变。
- 运行控制、归档、删除、模板绑定和发布提交等资源操作继续使用项目级门禁。它们与制作设置字段锁是两类状态，界面分别呈现。

## 结果

设置表单从后端收到活动步骤及锁定路径，只禁用相交字段；保存请求仍在服务端启动锁内复核，避免轮询延迟造成竞态。新鲜度报告同时显示“本步设置已改”和“上游产物已变”，为以后选择沿用旧设置重做产物或采用新设置重做保留明确边界。

## 验证

覆盖配置与项目参数路径门禁、排队到运行的快照边界、设置变化不传播到下游、产物摘要变化传播、产物审计字段、全流程阶段设置读取，以及前端构建和新鲜度双维度展示。
