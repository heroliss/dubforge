# ADR-0005：转录短语锚点与最终字幕语义整理分层

## 状态

已采用

## 背景

ASR 返回的标点并不等于最终字幕边界。项目先把标点和短时长切点变成可供模型参考的短语锚点；若完全依赖 LLM 重新切句，又会失去稳定的词级时间轴，且每个视频都增加额外请求。

## 决策

1. `transcribe` 只负责识别文字和保存词级时间戳。它在强/软标点、明显停顿或约 2 秒的识别后短语安全时长上限处整理锚点；这个上限只作用于 Whisper 返回结果的后处理，不会把音频切成短块，也不会削弱识别上下文。软标点仍允许下游模型重新合并。
2. `split` 负责最终字幕边界。启用 LLM 时，按 `asr.segmentation_mode` 选择把连续短语时间轴或全部词级时间戳、长停顿提示和少量窗口上下文按 token 预算整体交给模型；模型根据语义、停顿、字符数和时间轴自主决定合并或拆分，程序只负责最终硬约束和失败回退。
3. 显示长度按可见字符估算，标点和空白不计数；英文单词作为不可拆 token，避免为了满足上限在单词中间断开。
4. LLM 请求按 `split.llm_context_tokens` 分窗，而不是按字符数、行数或时间长度机械切块；默认 200,000 token，界面允许按服务商能力调到 1,000,000，并预留提示词和输出空间。每个窗口只发一次请求，输入用“开始秒-结束秒: 片段”时间轴纯文本，输出用“序号. 开始秒-结束秒: 片段”；序号从 1 连续递增用于校验完整性。开始时间需要有序但允许少量自然重叠；长停顿只作为输入 `# 停顿` 注释。程序不再发送无时间轴拼接原文，校验限于结构和时间；模型可修正明显的 ASR 识别错误，产物文本作为后续翻译和双语字幕的源文。原始标点随词级/短语级时间轴一并发送，供模型理解语义和边界。

## 结果

- ASR 不会因逗号把句子切得过碎；拆分结果更接近自然字幕节奏。
- 本地规则始终可以完成拆分，LLM 不可用时仍保留完整时间轴。
- `asr.pause_threshold_seconds`、`asr.max_segment_seconds` 控制短语锚点；`split.max_split_length`、`split.max_segment_seconds`、`split.context_lines`、`split.context_gap` 和 `split.llm_context_tokens` 控制最终字幕重组。
