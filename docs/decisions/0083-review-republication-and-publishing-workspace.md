# ADR 0083：审查修订重发与发布页操作顺序

日期：2026-10-06。状态：已采用。

## 问题

已退回的投稿仍绑定原成片。复制草稿保留旧产物ID，用户需要手动找到每个分P的修订版；凭文件名或配音标志猜测对应关系可能选错版本。发布页同时展示多种操作，没有把准备、确认和后台进度的顺序说明清楚。

「上传并投稿」已经支持确认一次后自动上传并提交新稿，但「仅上传」和「追加到已有BV」容易与修订原视频混淆。当前稿件管理只支持文案、排序、追加与合集管理，不能替换原BV中的视频文件。

## 决策

- 从原发布记录建立独立的审查修订草稿，通过修订记录中的 `source_artifact_id` 精确匹配原投稿各分P的产物。保持原顺序和分P名称，不依赖文件名、当前列表顺序或仅凭是否配音。
- 创建前展示逐P映射，检查当前修订有效性和文件完整性；任一分P缺失、失效或匹配有歧义时整单阻断。草稿创建仅写本地，不调用B站。
- 保留原稿件账号、封面与已确认的投稿资料。新草稿不继承原稿的回执、上传记录或目标BV。创建动作校验版本与预览指纹，并支持重复请求复用，避免双击生成重复草稿。
- 明确区分两条路径：修订成片创建新稿会得到新BV；保留原BV的视频替换需到B站创作中心完成。追加分P保留旧视频，不能解释成原视频已修订。
- 发布页按准备视频、投稿资料、确认发布、进度与回执组织。核对摘要紧邻主要按钮；保存资料和仅上传作为次操作，继续保留未保存设置、上传锁定、未知回执与外部提交确认的保护。
- 「上传并投稿」只在用户确认预检快照后启用后台自动提交。全部文件上传成功且正式投稿前复核通过才提交；上传100%与审核通过分别显示。
- 对追加到已有BV的已上传文件，在准备变更及正式发送前同样执行当前内容审查门禁，防止正常提交被阻断的旧文件经追加路径发布。

## 验证与边界

隔离领域测试覆盖逐P来源匹配、无效和多匹配阻断、冻结资料保留、预览失效、幂等创建以及追加路径审查。前端测试覆盖步骤布局、状态保护、修订草稿预览及一次确认后的自动发布动作；浏览器只验证本地界面和安全预览，不执行真实上传或投稿。

本地规则与修订记录不代表平台审核通过。新BV和原BV修改是不同操作；当前应用不会自动删除、覆盖或替换旧投稿。
