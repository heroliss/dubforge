# 0187：统一工作阶段与独立评论工作区

日期：2026-10-17。状态：采纳。

## 目的

手动工作区是自动流程的分段操作入口。相同制作意图应使用相同参数优先级、依赖预检、缓存、重试与产物判定，区别在于人工决定停靠与确认、自动流程按已确认计划继续推进。导航不能把后台实现细节机械地拆成每项一页，也不能把实际评论处理藏在获取视频或成片步骤中而不给入口。

## 决定

1. 前端 `WORKFLOW_STAGES` 是用户工作阶段的唯一顺序与名称来源：获取视频、音轨分离、语音转文字、语义整理、翻译、字幕与配音、上屏评论、合成成片、发布到B站。项目空间卡片、侧栏、总览、阶段前后导航、设置栏目及自动执行记录共用该映射。
2. 保留已有执行器任务键、产物指纹和历史计划。字幕导出、旧配音计划等任务归入字幕与配音阶段；评论仍调用既有采集与 `comment_preparation.prepare` 引擎，手动确认和自动确认均经已有方案保存边界。用户工作阶段不是新增 `StepRun`，不得把 `comments` 或 `publish` 塞入制作任务勾选集。
3. 评论工作区 `/projects/:uid/comments` 位于配音后、成片前。已有资料允许提前编辑，不把字幕或配音完成作为不必要的硬依赖。获取视频保留视频资料、概要和章节，只留评论概览与入口。内容审查跨多个阶段，列为跨流程通用规则。
4. 评论采集、准备目标数量、评分、翻译、手选、排版、确认及 LLM 日志沿现有 API 与组件执行；切换诊断不卸载草稿。刷新评论原文时尊重未保存草稿及确认保存互斥。采集数量从项目配置初始化，本次输入不暗中修改配置。
5. 设置保留全局、模板、项目及版本来源，按阶段顺序显示。字幕导出并入字幕与配音的子组，评论在成片前；通过独立 `stage` 查询参数定位栏目，保留 `section` 大类及模板身份。栏目切换保留草稿，写入或结果接收期间的路由切换受保护。
6. 评论导航从真实轻量进度投影采集、评分、翻译、准备及方案保存状态。草稿完成不等于方案已确认；明确保存的空方案也是保存事实；“已保存”不宣称已核验当前规则、内容或成片布局。历史失败不能抹除已有方案，重启不复活内存任务。准备与保存通过签名进度元数据区分同秒操作。
7. 导航与工作区共享轻量读取，合并在途请求并短时复用结果，缓存有界且不缓存完整评论正文。完整工作区只按资料版本变化重新读取。旧后端缺少摘要或读取失败时标为待核对，不推断为未准备或已完成。
8. 自动流程的执行记录将配音、字幕导出等内部任务合并为同一工作阶段，完成状态仍由真实游标覆盖的所有任务判定，不因某个内部任务完成就整阶段变绿。恢复游标、授权及后台调度保持原语义。
9. 旧下载页评论锚点、评论诊断链接、字幕页、旧配音计划链接继续兼容；其他页面的评论入口统一指向新工作区。
10. 项目卡片固定展示九个可点击阶段，编号与详情页一致；工作阶段完成数量与所选制作任务就绪数量分开显示，九个入口不代表每轮必须执行九步。评论摘要随项目列表一次返回，复用真实任务与保存状态，不为每张卡片追加请求或完整配置、新鲜度及媒体检查。发布成功与本地产物过期分别保留。

## 验证边界

隔离测试覆盖评论真实状态、同秒准备/确认、已保存空方案、历史失败共存、阶段顺序与索引、设置筛选与旧键、栏目忙态与草稿、请求合并和取消、菜单及旧路由。网页验收仅使用 8611 与测试项目，不触发真实下载、模型、配音或投稿。真实生产视频的制作和发布不作为本次导航重排的验收手段。
