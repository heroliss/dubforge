# ADR-0110：运行中配音预览的媒体同步与请求生命周期

状态：已采纳。日期：2026-10-07。

## 问题

配音合成期间，工作台会把原声回退切换为新生成的配音，或替换同一句的音频版本。旧播放器无条件保留尚未触发 ended 的音轨，视频时钟已经进入下一句时仍可能追播旧声音；单句定位也曾先按连续范围启动音频。浏览器的 play 请求异步完成，暂停、跳转、替换媒体后的旧成功或失败可能影响新的播放。

## 决策

- 视频仍是唯一时钟。新音频加载元数据后按当前时间接入，不从零追播；缓冲及拖动期间暂停音轨，恢复时重新对齐。除用户主动定位外，不改写视频位置。
- 切换声源时先停止旧音轨，再启动新音轨。单句试听先确定范围再定位，不短暂播放范围外的台词。
- 每个音轨的请求都有独立代次。暂停、跳转、替换及新播放使旧请求失效；旧失败不能暂停新播放或污染重试状态。被释放媒体的迟到成功立即暂停。同一组当前请求失败仍记录各轨，用户再次播放时重建失败媒体，不在帧循环中无限重试。
- 视频播放请求同样保留代次和节点身份。取消后迟到的原生播放事件不能激活音轨，旧节点的播放完成后立即暂停；同一节点上新发起的正常播放继续有效。
- 元数据尚未就绪不启动音频；元数据加载错误和同步播放异常均停止整组并提供重试提示。
- 连续预览中，已经超过实际音频末尾的旧续播仅在没有后续人声时允许最多 350 毫秒时钟余量，防止卡住的旧声音无限追播。单句试听和视频片尾仍等待已开始的音频自然结束。依据实际时长仍处于时间轴内的重叠保持 ADR-0107 的规则，与成片一致，不靠预览截音隐藏排布问题。
- 视频节点替换或组件卸载时释放全部旧媒体和事件，保留最后有效位置。seeked 和 timeupdate 也触发同步，降低仅依靠动画帧造成的恢复延迟及后台节流影响。

## 验证

时间轴测试覆盖连续播放旧尾音、真实音频重叠、元数据迟到、版本替换、请求失败迟到、暂停后视频请求迟到、单句范围及加载错误。真实 Vue 生命周期集成测试覆盖运行中增量音频、视频节点替换、拖动完成与卸载清理。使用隔离数据和 8611 测试服务验证浏览器播放，不中断用户正在执行的配音任务。

## 边界

此调整修复播放调度，不能消除音频文件本身过长造成的真实重叠。已有时长提示、缩时重试、译文调整和声源选择继续负责这些内容问题；不重新生成现有配音，也不使项目步骤统一过期。
