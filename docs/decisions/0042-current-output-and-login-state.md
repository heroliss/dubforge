# 0042：成品组合的当前版本与扫码登录状态

日期：2026-09-27

## 背景

用户明确要求同组合重生成覆盖成品，替代 ADR 0029 / 0033 中每次增加时间戳版本的交互。发布草稿已经引用产物 ID，因此不能通过先删旧索引再生成来实现覆盖。

## 决策

- 完整的三个布尔维度决定组合身份。每种组合复用最新已有成品的文件名；首次仍使用原时间戳格式，兼容旧项目。历史文件不自动批量删除。
- 先渲染暂存文件，再检查取消状态和发布占用，原子替换当前成品并更新原产物记录的摘要、大小、更新时间。强制重跑保留正式成品及索引。
- 发布服务统一管理文件替换与发布入队的互斥边界；正在发布时不能替换。未上传草稿保持引用，预检摘要变化必须重新确认；已冻结的恢复任务拒绝上传变更后的本地文件。
- 界面直接显示已有组合，生成清单及确认框区分新增与覆盖。试片仍然独立，不替换正式成品。
- 登录状态区分获取二维码、等待扫码、手机待确认、账号校验、加密保存、已连接、过期和失败。取消不允许被迟到的回调覆盖。
- 通过 Cookie 登录状态接口 `/x/web-interface/nav` 校验登录和 UID，不将空间资料接口或昵称字段作为登录是否成功的依据。登录过程仅对短暂网络故障进行有限的幂等读取重试，不重试验证限制、不关闭 TLS 校验、不重试投稿。
- QR 图案使用零内边距的 SVG，白色留白由外层容器负责，避免全局 `border-box` 与组件固定尺寸冲突。

## 验证边界

回归用例使用隔离文件、数据库及模拟 HTTP 响应，不自动对真实账号扫码、上传或投稿。真实手机扫码仍需用户重新验证；失败时保留阶段与脱敏错误码，不宣称已定位过去那一次外部失败的唯一原因。

## 后续修正：扫码成功凭据的新格式

用户再次扫码，已确认阶段出现 `PUBLISH_QR_RESPONSE`，将问题范围缩小到凭据解析。当前适配只解析 URL 查询参数；上游 SDK 的 `poll()` 还会丢弃响应头。[其他实现的 2026-08 兼容修复](https://github.com/public-clis/bilibili-cli/pull/27) 记录了相同的新格式：`data.url` 仅含 `crossDomain?ticket=...`，凭据由 `Set-Cookie` 下发。

- 轮询保留原始响应头；优先接受完整的登录 Cookie，其次兼容旧版 URL 参数，再按需兑现官方跨域票据。
- 票据只发送到明确允许的 HTTPS passport 主机和 crossDomain 路径，不跟随 302 跳转、不自动重试票据兑换、不记录票据/URL/原始响应头。
- 兑现票据时显式提供浏览器 UA：SDK 登录类的 headers 覆盖了基类默认 UA，不能假设继承。
- 对新旧格式、轮询直接 Set-Cookie、302 响应头、缺失凭据、非法目标、风控及敏感信息不泄露补测试；最后仍校验登录状态和账号 UID 后才保存加密凭据。
