# ADR-0003：试配工作台作为可跳过的管线节点

> 2026-09-24：步骤选择与连续执行规则由 ADR-0016 更新；所有步骤均可按需选用。

- 状态：已采纳（2026-09-20）
- 范围：工作台、单项目自动续跑、多项目批处理、管线状态展示

## 背景

试配工作台的主要用途是让用户在批量配音前试听少量句子、调整参数并确认声音效果。但批量视频翻译需要无人值守，不能因为手动试配节点而阻塞自动链。

## 决策

工作台保留在完整管线定义中，顺序为“配音计划 → 试配与参数确认 → 批量配音”，但不进入 runner 的可执行步骤集合。自动续跑和多项目批处理使用 `STEP_KEYS`，因此会自然跳过工作台。

工作台状态有三种主要结果：

- `pending`：还没有试配确认，也没有完成批量配音；
- `done`：用户完成试配并确认当前配音参数；
- `skipped`：批量配音已经完成，但用户没有走试配确认流程。

批量配音完成后，项目列表和管线页显示“已跳过试配”，不会把可选节点误报成未完成。若用户之后想精调，可以重新打开工作台并强制重合成样例。

## 影响

- 必需步骤进度不包含工作台，自动任务可以连续执行；
- 前后端 API 都返回同一条 10 节点管线，避免工作台在不同客户端位置不一致；
- 工作台样例音频仍与批量配音共享句级缓存，减少重复合成；
- 更换配音参数会使旧确认按输入指纹失效，避免沿用过期的声音结果。
