# ADR-0180：评论字体测宽与预览成本

日期：2026-10-16
状态：已采纳

## 背景

评论使用字幕的通用保守 em 估算换行。实际 FFmpeg 验证显示，微软雅黑长评论在最大宽度 100% 时可能仅利用六七成可用宽度，原因是估算字宽显著大于渲染字宽。单次预览还重复探测画布和计算当前排版。

## 决策

- 评论采用字体感知的测宽和完整换行；可用系统字体度量时优先使用，缓存有界并释放字体资源。字体不可用、复杂文本或不支持的系统保守回退，不改动其他字幕的默认排版规则。
- 最大宽度仍是上限，不对短评论拉伸或强制两端对齐；100% 使用扣除边距后的可用区域。0 自动的最新语义见 ADR-0181：同样使用扣除边距后的可用区域。
- 单帧预览与布局提示共用一次画布探测和排版结果，继续复用正式渲染器。进程内最多两个评论预览同时执行，超出直接提示稍后重试，不建立后台等待队列。
- 同页面保留既有交互：参数连续变化 500ms 防抖，时间轴拖动到松手才渲染；最多一个在途请求，后续仅保留最新状态，过期帧不能覆盖新状态。
- 使用 `font-metrics-range-v5` 标记实际排版算法变化；不改变用户文字、选择、已保存参数或当前未确认草稿。

本决策补充 ADR-0179；字号范围、软高度、边距和位置锚点语义保持不变。
