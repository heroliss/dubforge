# ADR 0176：配音运行中追加显式生成请求

日期：2026-10-16。状态：采用。补充 ADR 0171、0174。

## 问题

“生成本句配音”在项目已有 TTS 任务时被前后端整体锁住。用户可以保存逐句精调并等待执行，却不能用同一生成操作为另一个句子确认目标槽并加入待配音列表，操作语义不一致。

## 决策

- 空闲时生成启动新的 TTS 任务；合成期间显式生成附着同项目当前任务，不启动并行模型请求、不打断当前句、不清除原制作链。复用持久逐句更新队列、句间领取边界和候选声音的原子提交机制。当前请求完成后优先依次处理显式请求，再继续原范围，以便长任务期间及时验证人工修正。
- 仍使用生成确认窗口，核对文字、参数、选用声音、满意记录与目标槽。确认后的显式目标槽随请求保存；新槽同时纳入项目待执行槽清单，防止后续操作把预留槽误当作空位。
- 同句同意图已等待或正在执行时不重复请求模型；目标冲突须明确说明，不能默默换槽。已完成句可以再次明确生成。主计划外的句子与未设置逐句覆盖的句子同样可以加入。
- 本轮项目制作参数保持执行快照；追加请求使用明确保存的本句参数。运行中的请求保持固定，新的精调意图在之后的请求边界处理。取消或最终排布关闭接收后不再追加，不因页面上的旧状态另起一轮任务。
- 接收回执带请求标识；工作台返回当前任务已接收的标识，前端据此消除乐观排队状态。只比较任务编号不足以保护同一任务中刚接收的追加请求，旧轮询结果不得将它撤回。
- 接收后及时关闭确认窗口，显示等待状态；后台工作台读取和导航刷新不阻塞确认完成。提交结果未知时先核对，不自动重发覆盖请求。
- 普通全部重做、选槽、文字修改等操作继续遵守各自门禁；开放的是明确的生成请求。没有活动任务的保存操作仍不自动合成。进程中断后的旧队列只展示中断结果，须由用户明确继续或重做。

## 验证

领域测试覆盖追加、目标槽、重复提交、未精调句、取消与关闭竞态及原任务隔离；前端测试覆盖运行中按钮、确认、回执与旧轮询。浏览器验收使用 8611 端口、独立项目目录和可控模型替身，观察当前句完成后逐一处理追加句，不调用真实模型或发布平台。
