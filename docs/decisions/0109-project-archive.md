# ADR-0109：项目归档与制作状态分离

日期：2026-10-07

状态：已采纳

状态更新：归档项目也保留独立制作基础值，不再随全局或系列制作参数自动变化，见 [ADR-0126](0126-stable-project-settings-and-model-services.md)。归档与恢复规则不变。

## 背景

完成或暂时搁置的项目继续占据日常项目列表。删除会失去项目资料、产物与发布记录，而制作完成、失败、需更新等状态描述产物有效性，不能承担收纳功能。

## 决策

- 项目增加可空的 `archived_at` 管理字段，不改变制作状态、参数、输入指纹或文件位置。旧数据库与旧清单默认未归档。
- 项目空间默认显示当前项目，可切换已归档项目；提供单个及批量归档/恢复。批量按项目执行，逐项展示失败，已成功项目不因其他项目失败而回滚。
- 项目列表 API 默认 `archive=active`，支持 `archived` 和 `all`；领域层 `crud.list_projects()` 默认仍返回全部，目录冲突检测、重复导入提醒、配置迁移等内部操作不能忽略归档项目。
- 归档与任务启动共用短锁和完整运行占用检查。排队、制作、后台收尾、资料生成、上传及投稿中的项目不能归档；归档项目的编辑、新制作、新发布与制作恢复入口要求先恢复。
- 已归档项目可按 UID 查看原有资料、成片、日志和发布记录。远程审核状态查询与已投稿流程的审核查询恢复继续可用，它们不生成或替换制作产物。
- 归档/恢复操作幂等，只更新管理字段并原子写入项目清单。普通项目快照保存不得覆盖 `archived_at`，避免后台回执用旧快照取消归档。数据库重建从清单恢复归档状态。
- 全局默认和系列模板继续被归档项目继承。归档不冻结设置、不清理磁盘、不保证恢复后产物仍与当前设置匹配；恢复后按既有指纹机制说明需更新原因。

## 影响

日常项目列表只加载所选范围，归档列表不参与制作状态轮询。用户可先收纳再恢复继续处理，无需移动文件或生成重复项目。存储回收仍使用明确的产物清理或项目删除操作。
