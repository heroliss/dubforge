# ADR-0032：配置事务、运行目录与有界轮询

日期：2026-09-27

## 问题

- 设置接口逐键读写 YAML，一次提交可能部分成功；参数表为每个字段重新解析配置，同一响应也可能混入不同版本。
- 数据库引擎只初始化一次，但项目文件路径每次读取 `server.data_root`，与“修改后重启生效”的约定不一致。
- 原子写共用固定临时名，并发写同一文件会相互干扰；项目清单的旧快照也可能晚于新快照落盘。
- 日志接口每次 `readlines()` 完整日志，只为返回末尾几百行，内存与读盘开销随文件增长。

## 决策

1. 配置模块提供 `update_config` 整批更新：锁内读取最新配置，检查点分路径及已知配置段结构，全部有效才原子替换一次。`set_key` 复用同一入口；API 继续执行既有参数取值校验。无效提交不改变文件，未触及的扩展键保留。
2. 参数接口、语言能力和表单结构共用一次请求的配置快照。不开跨请求缓存，外部文件修改在下一次读取仍能生效；空配置段回退默认值，非法对象结构返回中文 `CONFIG_ERROR`。
3. 数据库引擎初始化和重置互斥。引擎发布时绑定绝对数据目录；数据库与项目文件始终使用相同目录，设置页写入的新目录在下次引擎生命周期生效。不自动迁移旧项目。
4. 字节原子写使用同目录下独占的随机 `*.tmp` 文件，继续复用 Windows 瞬时占用重试与异常清理。清单写入从读取数据库到原子替换串行化，且不重新创建已被移走/删除的项目目录。锁作用域是单服务进程，不承诺多个独立进程同时写同一工作区。
5. 日志尾部倒序按 8 KiB 分块读取，单请求最多读取 1 MiB，兼容 UTF-8 和常用换行。仅当字节上限妨碍返回请求的完整尾部时设置 `truncated`，前端提示完整日志仍保存在磁盘。接口先校验步骤键，文件消失按无日志处理。
6. 项目列表及依赖计算复用已有项目对象和步骤快照，避免为解析目录再次查询数据库。

## 验证与限制

新增隔离回归覆盖整批失败不落盘、8 线程并发保存、临时文件隔离及失败清理、目录重启切换、单例初始化、清单串行写入和目录移走、中文/空日志/超长单行与字节预算。参数接口测试要求整份响应只读取一次配置；十万行日志测试要求取末尾 200 行只读取 8 KiB。

本轮新增 56 项后端回归，全量 `uv run pytest -q --tb=short` 为 533 项通过；前端 62 项 Node 测试和 `npm run build` 通过。测试使用隔离数据与配置，未启停 8600 常驻实例，也未进行真实外部模型/GPU 负载压测。现有测试依赖有两条弃用警告，不影响通过结果。

本决策保持 ADR-0002 的原子替换和 ADR-0016 的请求内快照方向，不改变产物指纹、步骤幂等及取消语义。随机临时名不能防止断电残留；清单是数据库的恢复副本，不是跨数据库和文件系统的事务。1 MiB 限制只影响日志预览，不截断磁盘日志。
