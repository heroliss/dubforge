# ADR-0078：可恢复的批量导入与批量运行

日期：2026-10-05。状态：采用。

## 背景

ADR-0071 已将项目创建与单项成功回执放在同一数据库事务内，但浏览器只通过 sessionStorage 找到批次。关闭标签页或重启后，回执仍在而界面无入口。批量运行在部分启动失败时又会清空全部检查项，用户无法直接补启动失败项目。

## 决定

- 导入领域增加只读最近批次摘要与明确确认的继续操作；以已有持久化冻结计划为唯一输入，不要求重新提交原始文本。每批保留 UTC 创建时间；已有数据库仅补时间列，不重建或删除回执。
- 继续操作复用原创建循环与事务边界：跳过已成功条目，复核未创建条目的当前模板指纹和本地文件。模板改变后不能偷偷采用新设置，须把失败项转成新清单再预览。已成功但后来删除的项目不重建。
- 摘要不回传完整配置；状态/历史以集合查询核对项目存在性，避免每项独立查询数据库。历史默认20批，领域上限100批。
- 进程内执行状态只决定“创建中”的显示与轮询，不替代持久化结果。重启后状态变为可继续；读取历史不自动创建、下载或运行。
- 保留会话存储的快捷恢复，但校验其结构；没有会话存储时仍可从最近导入找回。迟到轮询不能覆盖新批次或最终回执；慢轮询不堆积请求。
- 批量运行首次确认冻结启动请求。收到成功回执的项目从待启动集合移除，失败或无回执项目保留，安全重试沿用同一批次 UUID 和原检查输入。单项目异常按稳定错误码记录，不妨碍其他项目启动。配置变化仍要求重新检查，不绕过工作流预检。
- 解析成功后收起原始输入，优先展示项目、模板名、稀疏覆盖和错误；完成后由用户主动选择“选中已创建项目”，接到现有批量运行，不新增运行配置或隐式自动投稿。
- 参数校验仍集中在统一配置边界：所有步骤数值遵守元数据范围/整数约束，枚举拒绝对象或数组，发布分P引用必须有效，标题采用平台的 UTF-16 长度限制。清单与手动设置使用同一规则。

## 保持的约束

继承链仍为全局默认 → 系列模板 → 项目覆盖，不复制模板默认值；步骤快照、ADR-0076/0077 的重试及资源调度不变。运行中编辑的交互决策随后由 [ADR-0098](0098-runtime-edit-locks.md) 更新为按影响范围锁定。单进程内导入串行化，未引入后台队列/多进程调度。导入只验证格式与本地引用，不对外网链接或发布权限作成功保证。

## 验证

覆盖进程中断后的重连与继续、回执与项目同事务、删除不复活、历史查询次数、模板漂移、部分失败补启动、未知网络结果冻结请求、非法参数的中文业务错误及实际导入界面验收。完整验收记录见 [审查记录](../research/codebase-audit-2026-10-05.md)。
