# ADR 0232：首个稳定源码版本与显式运行依赖

日期：2026-10-20

状态：已接受

## 背景

DubForge 的完整工作台包含 Python 领域库与 HTTP 层、Vue 网页、Node.js 发布工作者及外部媒体工具。项目数据、账号、配置和模型环境有各自的生命周期。单独构建一个 Python wheel，不能代表已经交付了可直接使用的完整工作台。

首个稳定版本还需要消除隐式目录发现、散落版本号和 Windows 深层媒体目录的读取差异，让安装、恢复与维护都有可复核的边界。

## 决策

1. **以 Windows 完整源码发行作为 v1.0.0 的交付形态。** 安装脚本读取锁文件、构建网页，按需选装识别、分离和发布能力；配音服务与模型单独准备。源码包不包含真实配置、运行数据库、账号、视频、缓存或虚拟环境。不把源码压缩包称为独立 EXE 或包含模型的整合包。

2. **后端版本采用唯一常量。** `dubforge.__version__` 同时提供 Hatch 打包、健康响应和 OpenAPI 版本。前端显示其包版本，发行检查要求前端包与锁文件和后端常量一致。uv 对本地动态 editable 项目可以省略 `version`，检查器同时核对唯一项目条目和 `source = { editable = "." }`，不伪造锁文件字段。

3. **运行依赖由明确设置解析。** HF 缓存按 `paths.hf_home`、`HF_HOME`、自身数据目录的顺序选择；外部配音服务按配置或通用安装发现规则连接，不再探测特定旧工作区。显式填写的目录继续有效，升级前可填写已有缓存位置复用模型；程序不替用户移动或删除模型文件。

4. **ASS 渲染保持原读取器。** 字幕与评论共用 `utils.ffmpeg.ass_file_filter`。Windows 将已写出的内部 ASS 绝对路径规范为扩展长度路径，并分别处理滤镜选项与滤镜图两层转义；不通过 shell 拼接命令。其他平台保留内部相对文件名。短路径、长文件路径及特殊目录字符用实际可见字幕/评论帧比较，避免为了修复路径读取而改变正常画面。

5. **媒体 GET 与 HEAD 保留相同业务合同。** GET 出现在 OpenAPI，HEAD 单独注册且不重复进入 schema；保留 Range、缓存和错误行为，避免客户端文档生成出现重复 operation ID。

6. **发行验收与生产数据分开。** CI 使用新配置、数据库、临时目录及模型缓存。真实冒烟固定 8611，只核验自己启动的进程、版本和空项目列表；Windows 虚拟环境的转接进程必须通过父子身份验证，退出只能作用于本次持有的进程。安装脚本另用 PowerShell 5.1 解析与隔离伪仓库验证分支，不在测试中安装真实依赖。

## 结果与边界

- 安装、打包、健康接口和界面有统一版本约束；依赖锁文件保持可审阅。
- 测试模型边界使用确定性替身；真实 FFmpeg 媒体回归与模型推理、平台审核分别报告。
- Windows 长路径验证覆盖 ASS 文件路径超出传统长度的情况，不声明任意超长进程工作目录或真实 UNC 网络共享均已验收。
- 用户配置、已有项目与发布回执继续保留，历史 ADR 作为维护依据保存。仓库公开性与开源许可证不由发行流程自动更改。
