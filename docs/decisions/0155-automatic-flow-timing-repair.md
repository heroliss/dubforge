# ADR-0155：自动流程修复历史配音时间冲突

状态：已采用。日期：2026-10-15。

后续更新：修复开关的配置归属与界面已由 [ADR-0167](0167-timing-repair-as-dubbing-setting.md) 调整为普通配音设置；本文的有限修复、同槽历史及人工精调保护仍适用。

## 问题

默认「继续已有配音」只补缺音频，预检却把已有配音的排布冲突当作必须手动
处理的问题。缩时执行器只处理本轮新生成句，即使绕过预检仍不会修复旧声音。
这使自动流程无法完成本来可通过邻句滑动和有限缩时解决的工作。

## 决策

声音参数更新意图与时间修复意图独立。本次运行增加默认开启的
`repair_timing`，它不是项目音色设置，也不进入声音输入指纹。关闭时保留
严格复用语义；开启时先按当前声音排布，只对仍不足且可复现的句子缩时。
此项替代 ADR-0153 中「历史配音只提示新槽，不自动修复」的限制。

统一配音计划将普通生成与 `kind=repair` 分开计数。预检不调用模型；可修复
冲突安排 TTS，不能因音频存在、步骤最新或普通生成数为零而跳过。总览完整
流程、项目空间勾选链、挂起恢复和顺序批次使用相同计划及确认指纹。

修复必须有匹配句子身份和文件版本的完整 IndexTTS 生成快照。沿用实际声音
参数，连接地址、单次超时与缩短重试列表使用当前运行策略。不能用项目后来
选择的新音色或逐句参数填补快照。缺失必要参数时明确说明无法安全自动复现。
保留手动原声、静音选择和人工播放位置；位置仍作为固定排布约束。

先滑动，后处理不足最多的一句，真实模型结果返回后重新排布。时长因子仅
采用比实际因子、已成功尝试因子更小的配置值，不重复已完成尝试。服务失败
尚未返回的因子可在恢复后重试；不把提交过请求误记为已经完成。

沿用 ADR-0154 的同槽音频历史，首次改变前保存完整声音；只选用更短结果，
不创建新槽、不裁声音、不改源稿与用户参数。声音改变后的满意标记需要重新
确认。原生成意图指纹保留，实际使用因子与尝试记录如实更新。

预检能执行修复时允许开始；运行中重新检查新增冲突。用尽因子、人工位置
不可行、引擎不支持或快照不完整时保留音频和报告，暂停成片与后续发布，
不为了自动完成而输出已知重叠声音。

## 跟随交互

切换到跟随预览时同步读取当前播放句并选中、滚动，不等待下一次换句。
显式开启合成跟随时接入当前任务最新完成结果；已有同任务单句试听原位接管，
切换合成与预览保持媒体位置。准备尚未完成的单句不能绕过音频和 seek 门禁。

## 验证

隔离模型检查旧声音修复、精调参数和原声保护、同槽恢复、有限尝试、非单调
长度及服务故障后恢复。真实协调器和 Runner 覆盖显式/默认配音意图、已有
TTS 最新但冲突、新建勾选链与恢复链、纯原声版本及关闭修复。前端播放器
联动验证切模式立即定位且不倒回句首。
