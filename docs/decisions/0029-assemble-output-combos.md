# 0029 — 合成成片输出组合（结算页）

日期: 2026-09-26

## 背景

此前合成成片只产出单一 `final_<时间戳>.mp4`，是否烧录字幕由 `assemble.burn_subtitles`
决定。用户希望在合成成片步骤自由组合「配音/原声 × 烧录/不烧录字幕」，一次生成多个版本，
并让该步骤成为最终结果结算页：清晰列出每个成品的生成位置，同时引用上游原视频与字幕文件
的位置。

## 决策

1. **组合模型**：三个维度中「画面」恒为源视频，可自由组合的是音频（配音/原声）与字幕
   （烧录/不烧录），共四种成品：
   - `dub` 配音 · 不烧录字幕
   - `dub_hardsub` 配音 · 烧录字幕
   - `src_hardsub` 原声 · 烧录字幕
   - 原片（原声 · 不烧录字幕）＝ 源视频本身，**永不合成/复制**，UI 直接展示源视频位置。
2. **产物命名**：新成片按组合后缀命名 —— `final_dub_*` / `final_dub_hardsub_*` /
   `final_src_hardsub_*` + 微秒时间戳，`output/` 内多版本并存。旧命名
   `final_<时间戳>.mp4` 不再产生，已有文件在前端归入「历史版本」。
3. **任务语义**：新增任务 `scope=outputs`（`POST /steps/assemble/outputs`，body
   `{variants: [...]}`）。该任务：
   - 绕过 fresh/skip（与 trial 同理），但 **force=False**：不删除旧产物、不标记下游
     stale、不更新下游链；
   - 每次运行共享一个时间戳；同批多组合共用一次配音铺轨（`dub_full.wav` 仅生成一次）；
   - 原声烧录版单独走 `_mux_original_sub`：视频重编码烧字幕，音轨直接映射源视频自带的
     音频（无音轨时跳过音频映射），不使用铺轨配音。
4. **无任务参数的普通运行**（总览下一步动作、强制重跑）沿用旧配置语义：
   `burn_subtitles=true → dub_hardsub`，否则 `dub`，仅命名改为带组合后缀。
5. **指纹**：组合清单不参与 input fingerprint —— 新增组合属于「补生成」，不应把已有
   成品判为过期；重新合成仍由用户显式触发。
6. **UI**：新增 `AssembleOutputsPanel`（成品清单）：字幕输入位置、原片引用卡、
   三个组合卡（勾选 + 最新产物路径/大小/版本数）、一键合成所选版本；原片位置只在原片
   卡片展示一次。宽屏两列网格，窄屏单列。「产出预览」可下拉切换原片、全部组合和历史
   版本；实际产物路径可直接点击调用系统文件浏览器定位。区域试合成面板放在产出预览后。

## 后果

- 「原生+不烧录」不再产生重复资源；结算页是唯一的成品入口。
- force 重跑（删除本步产物）仍会清掉全部组合版本，语义不变。
- 旧文件与新命名共存时，产出预览不再自动混淆组合；用户可在选择器中精确选择原片、
  新组合或历史版本。结算面板按组合精确归类，不受影响。

## 测试

- `test_assemble_outputs_combos_create_multiple_versions`：双版本并存、补生成不删旧版、
  原声版保留源音轨。
- `test_assemble_outputs_rejects_invalid_variants`：`src`/空/未知/非列表一律
  `ASSEMBLE_VARIANTS`。
- 既有 full/burn 用例补组合命名断言；前端 `groupFinalVideos` 分组测试。
