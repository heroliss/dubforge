# 0023 — 合并字幕校对、配音与导出

日期：2026-09-24

## 背景

用户需要在试听时修正文句和起止时间，并让字幕与成片使用相同结果。独立的字幕导出页面使校对与导出割裂，也容易误以为必须先配音才能导出字幕。

## 决策

- 界面统一为「字幕与配音」，在翻译后、成片前。每句提供原文、译文和起止秒数的编辑入口，保留原文在上、译文在下的列表顺序。
- 字幕导出和配音仍是两个独立可选操作，总览可分别勾选自动执行；内部保留 `subtitles`、`tts` 任务键，兼容已有工程和产物。旧字幕页面链接重定向到编辑页。
- 校对稿存于项目 `params.subtitle_edits`，随 manifest 原子写入。原始 `split.txt`、`translate.txt` 不反向改写。`subtitle_document` 是字幕、任务准备、试听和成片共用的读取入口。
- 只有语义整理时即可校对原文和时间，选择导出原文；有译文后才开放译文校对和配音。导出字幕不要求 TTS 或分离音轨。
- 每句修改记录上游基准内容和差异。上游改变时保留修改，显示待核对；严格消费者拒绝使用有冲突的校对稿。句号消失时显示失效记录，用户可清理。保存带版本检查，禁止旧页面覆盖新稿，并与运行任务共享编辑锁。
- 时间必须有效、结束晚于开始且与相邻句子不重叠。手动时间在 SRT 中精确保留，优先于最短显示时长。只改时间会调整铺轨位置，保留音频完整长度，不自动拉伸或截尾。
- 人工校对仍代表同一句，保留声源、版本选择和独立声音设置。修改译文使本句旧音频过期；修改原文不使配音失效；手动改时间保留音频和满意标记。上游重新分句仍按原有身份规则使旧音频失效。
- 校对差异进入相关任务指纹；没有校对时不新增指纹字段，兼容旧缓存。没有指纹的旧字幕/成片也会在相关修改后标为过期。

## 取舍

保留独立后台任务便于报告错误、缓存和按需运行，但用户只面对一个编辑页面。当前支持逐句文字与时间修正，不引入拆分、合并、拖动波形等更复杂的编辑功能。

本决策细化 0022：人工移动同一句的时间与上游重新生成句子不同；前者保留音频，后者继续校验原始句子身份。
