# 0166 统一记录与展示全部模型对话

日期：2026-10-15。状态：采纳。关联 ADR-0164、0165。

## 问题

语义整理、翻译与评论已有实际对话，概要、发布文案、自动章节等调用却只有等待状态或字符计数。底层 trace 可选，新增调用容易遗漏记录；步骤与评论的展示实现也不一致。

## 决策

1. 在公共 `chat`、`chat_validated`、`test_provider` 自动捕获现有 trace 事件。嵌套和校验重试共用一次逻辑会话，服务回退使用独立请求编号；`chat_json` 通过公共校验入口覆盖。记录失败不改变调用、取消、重试或最终业务结果。
2. 业务只声明 context：项目、操作种类、用户可读名称和任务/发布记录归属。实际模型工作线程中绑定，不能依赖上下文变量自动跨线程。遗漏归属的未来调用仍在全局显示为未归类；无实际调用不生成空记录。
3. 完整对话放在数据目录的独立 JSONL 日志，轻量 SQLite 仅索引元信息。阶段进度仍是现有 execution 的诊断投影，不存模型正文。旧步骤和评论日志继续兼容，并共享递归脱敏。
4. 请求消息、返回的思考、流式正文、最终回复、校验与修正、取消、回退和错误均沿现有事件协议展示。只显示服务商实际返回的思考，不构造未返回的过程，也不把思考当作最终正文。
5. 统一只读列表和游标 API，按项目、操作和记录归属筛选，支持历史分页。长事件分片并保留全文，每次 API 响应有字节预算；前端先拼合完整事件，再用完整回复替换增量，避免跨页截断或重复。
6. 统一清洗已知精确密钥、认证字段、Bearer 与含认证的 URL。既不保存整个 provider/config/headers，也不把提示词中的凭据原样复制到诊断。正文保留内容不受模型任务输出预算影响。
7. 全局布局提供“LLM 对话”入口；概要、文案、章节与模型测试按相同接口打开同一抽屉。步骤、评论与全局抽屉复用事件聚合及展示组件；旧步骤专有的动画与质量信息保留。关闭或隐藏只停止观察，不取消模型任务；迟到响应不能覆盖另一条对话。

## 边界

本次升级前未记录的独立调用无法事后恢复。已有步骤/评论历史继续从原入口读取。记录表达请求和模型输出，不等同于结果质量或平台审核证明；业务授权和发布回执仍独立。

日志保存在用户的数据目录，当前不自动删除。列表不扫描全部正文，正文按需分页；观察器存储异常显示警告，不能因诊断异常重新请求模型或重复平台写入。
