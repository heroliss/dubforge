# ADR-0085：预览传输断连停止与页面请求消重

日期：2026-10-06

## 背景

成片预览反复拖动后可能没有画面，同时项目刷新与复制草稿变慢。隔离复现发现，当前 Starlette FileResponse 的文件读循环未监听请求断连，而 Uvicorn 可以在断连后静默忽略 send；旧 Range 被浏览器取消后，服务仍读取文件剩余部分。多个大媒体请求挤占线程读取资源，取消 DOM 请求不足以取消服务端工作。

页面还存在全局页继续轮询旧项目、完整项目与步骤状态重复计算、同一请求反复解析逐句选择、成片工作区读取重叠，以及复制草稿后串行再读详情等额外负担。

## 决策

- 媒体路由复用 Starlette 的 Range/If-Range 解析，补充断连监听、读流取消和受保护的文件关闭。单个响应（包括 multipart）保持同一个文件句柄；每个事件循环使用独立的四个媒体读取额度，与同步 JSON 路由的默认线程额度分离。GET/HEAD、首尾/开放 Range、错误范围和现有路径白名单、版本、缓存语义保持一致。
- 视频预览缓冲时显示状态，长时间缓冲或错误时提供用户主动重新加载。先释放旧请求，再加载同一内容版本并恢复位置；不自动播放或循环重试。只加载元数据的暂停视频也应视为初始就绪。
- 后台列表、版本和时间轴读取合并慢请求，最多补读一次最新内容；页面离开取消，版本变化废弃旧响应，写成功后不允许旧读取覆盖。全局页面暂停旧项目轮询，保留侧栏项目快照；重新进入立即刷新。
- 导航使用轻量项目投影，完成/失败状态由已读取的步骤最新性推导，避免另算全部依赖。完整项目与步骤 API 保留原协议。仅展示历史成品的面板不读取用于生成的评论方案。
- Dependencies 快照仅在单次请求内复用路径解析、配置、版本登记和逐句选择结构。继续检查文件存在/大小和明确要求的严格哈希；参数或选择变化重建结构，新请求仍读取新配置。不同成品的必要审查检查不缓存合并。
- 复制草稿一次返回完整可编辑详情，客户端等待时锁定按钮，列表异步刷新。带请求 UUID 和来源 revision 的复制在服务端持久去重；响应丢失后的同请求重试不再创建或覆盖草稿，不同请求仍允许有意再复制。

## 验证

测试覆盖断连后读取有界并关闭文件、媒体额度隔离、multipart 同句柄、Range 与 HEAD；覆盖请求内复用不掩盖删文件/篡改/配置变化；覆盖复制并发与响应丢失重试、草稿编辑保护；覆盖媒体错误、缓冲超时、恢复位置及不自动重试，以及页面请求合并与旧响应取消。

本机 HTTP 与界面验收见 `docs/research/performance-validation-2026-10-06.md`。仅使用 8611 验收实例；不重新生成生产产物或实际复制、上传、投稿。
