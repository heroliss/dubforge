# 0206：按源时间轴生成成片与恢复来源的虚拟试听

> 正式成片的边界由 [0207：在已有成片上执行正式删除与恢复](0207-existing-output-timeline-edits.md) 扩展：除了从当前工作稿完整制作，也可以显式建立冻结来源的正式剪辑版本。

## 背景

成片删除方案以原视频时间为坐标。当前正式成片已经包含它自己的删除范围，因此把同一范围再次映射到成片播放器会产生“跳过没有生效”或重复跳过的问题；如果用户恢复一段已经从当前成片中删除的内容，单纯 `seek` 也无法从旧 MP4 中恢复不存在的画面。

## 决策

剪辑编辑器保留一个可见的当前成片播放器和一个完整的原片时间轴。当前版本实际成片的剪辑快照作为 `baseCuts`，编辑中的删除清单作为 `draftCuts`，两者都使用原视频时间坐标。

按两个方案的边界把试听计划拆成源时间段：

- `draftCuts` 中的区间不进入试听；
- `baseCuts` 已保留、`draftCuts` 仍保留的区间使用当前成片；
- `baseCuts` 已删除、`draftCuts` 恢复的区间使用原视频或经过校验的其他成片作为恢复来源；
- 恢复来源必须匹配源文件指纹和时长，并且实际保留所需区间，不能静默回退到不匹配的文件。

无恢复区间时，新增删除可以直接在当前成片播放器中跳过。存在恢复区间时，不用两个 `<video>` 频繁切换 `src` 或依赖浏览器 `MediaSource` 拼接；这些方案容易造成解码等待、声音重叠、字幕错位和接缝抖动。系统生成一个短的、可取消的虚拟试听片段，旧预览在新片段完成前继续保留。试听任务使用 400ms 防抖、单飞和原子写，结果带有 `base`、`draft`、恢复来源哈希和源指纹，过期结果不能覆盖新草稿。

虚拟试听只用于核对。正式成片始终从当前项目统一的原视频、字幕、配音和评论重新生成，不把其他版本的画面、字幕或声音永久拼进正式输出。恢复来源和虚拟计划不参与正式成片指纹。

## 结果

用户只需要看一个成片播放器；下方原片完整时间轴负责定位、标记删除和恢复。时间轴上可显示保留、删除、恢复试听和来源不可用状态。每个成片版本仍保存自己的源时间删除方案，因此版本之间可以互相作为恢复来源，同时不会破坏原片坐标或历史快照。
