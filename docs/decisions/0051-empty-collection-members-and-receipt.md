# ADR-0051：空合集成员兼容与加入结果核对

日期：2026-09-28。状态：采用，已完成用户授权的真实补入验证。

## 根因

B站新建空合集的小节实际返回 `episodes: null`、`section.Episodes: null`、`section.epCount: 0`。旧代码只接受数组，把空合集误判为响应不完整；随后通用异常转换把本地兼容错误显示成“B站请求失败，请检查网络”，掩盖了真实原因。视频投稿本身已成功，记录正确停在 `collection_pending`，无需重传或重投。

## 决策

- 提取 `collection-join.mjs` 负责合集成员解析、重复检查、单次加入和回读验证。兼容顶层 `episodes`、嵌套 `episodes` / `Episodes` 数组。显式 null 列表只有在成员数明确为零时才视为空；缺字段、数量/列表冲突、错误小节或合集仍拒绝写入。
- 重试先读取成员，目标 AID 已存在则只返回已加入，不重发添加请求。单次写请求显式禁用自动重试和重定向，设置超时。
- 添加接口返回后再次读取目标小节，只有找到目标 AID 才返回 `joined: true`。读取失败或暂未出现均留在待核对，不假报成功、不自动重发。Python 同样要求严格的布尔成功回执。
- `CollectionJoinFailure` 区分登录、读取合集、读取成员、输入校验、提交关联与回读核对阶段，并区分未发送、平台明确拒绝和结果不明。保留脱敏业务原因及错误码，不输出 Cookie、请求头、URL 或堆栈；本地已知原因不再误报网络。
- 所有合集关联失败都明确提示“视频已投稿”和“无需重新上传或投稿”。仅重试合集，不调用上传、封面或投稿接口。

## 验证

隔离测试覆盖实际空合集 null 结构、正常数组/嵌套数组、已存在成员防重写、数据矛盾/目标不符、平台业务拒绝、写超时不重试、回读未确认、错误脱敏与本地成功回执校验。

用户授权后，仅对已发布稿件 `BV1Rpae6TETi` 执行一次补入合集操作。工作进程回读确认成功；另外通过稿件详情独立确认合集 ID `9189472`、名称“越南旅行”，原声与配音两个分P的 CID 及标题均保持不变。本地 `collection_joined=true`，原错误已清除。没有上传视频、重复投稿或修改创作声明。

最终只读查询确认状态为 `published` / “开放浏览”。后端全量 875 项通过（2条既有第三方弃用警告），前端 188 项、B站工作进程 43 项通过。前端测试出现非阻断的测试 WebSocket 端口占用提示，不影响通过结果；未启停用户常驻服务。
