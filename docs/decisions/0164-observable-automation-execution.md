# 0164 自动流程的分层进度与有界执行诊断

日期：2026-10-15。状态：采纳。关联 ADR-0014、0015、0081、0158、0163。

## 问题

制作步骤、评论任务、自动流程、发布与章节各有实际业务状态，却缺乏通用的过程表达。内存阶段结束即丢失，页面重复展示与不可见过程并存，等待、自动重试、需要处理容易混淆。增加一套有自己调度能力的“通用进度任务”会产生第二个状态真源。

## 决策

1. 保留现有任务、工作流和远端回执作为业务真源，新增 execution 作为只读诊断投影。统一 schema、state、phase、中文 label/detail、completed/total/unit、attempt/max_attempts、elapsed/inactive、next_check_at、有限 metrics 和 history。
2. 以 Job.execution、WorkflowRun.execution 及现有发布/章节快照承载；诊断与产物、配置指纹及外部操作授权分离。诊断写入失败不能触发重复正式操作。父任务终态覆盖陈旧活动阶段，读取时计算耗时，结束耗时冻结。
3. 真正阶段切换与结束立即保存，同阶段数量/流式活动一秒节流，历史最多 24 项；模型只存活动阶段和计数，不复制提示词、思考或结果正文。心跳、回执和诊断列分别写入。
4. 统一三层 UI：整体阶段/项目位置、当前叶任务工作与等待、折叠最近过程。保留 ADR-0015 的明确估算 LLM 进度，下载字节和编码时间等实际计量明确范围，平台审核与加载总量未知不伪造百分比。
5. 所有长时间或外部阶段给出具名活动；瞬时本地检查/保存归入相邻阶段，不创建冗余后台任务。总览、步骤页、项目列表和批次消费相同叶任务，按当前 run/job 归属，不能借用同项目其他任务。
6. 完整产物登记与收尾后才完成步骤，再启动下游。StepRun/Job 终态同一数据库事务公开，并与停止共用提交边界，不能半边成功。发布绑定实际成功的版本快照与产物。自动重试预算属于本次操作，不因步骤耗时长而归零。
7. 停止审核核对同时持久暂停关联后处理，后台调度和逐次章节写入前都检查。明确的旧停止状态幂等迁移，不能因加列默认值恢复已停止操作。显式继续解除；外部结果不明只核对，暂停/停止不抹除已完成产物与回执。
8. 排队资源准入不得长期占满通用 worker；保留全局线程上限和每资源额度，队列中的取消与关闭可回收。配音服务资源准备使用任务项目配置，支持本机可启动服务冷启动。
9. 发布文案生成采用现有 in-flight 占用事实，接入统一字段门禁，仅冻结当前使用的 publish 路径；无关制作字段和其他项目仍可编辑。

## 取舍

统一诊断不是完整事件存储，也不提供不可观测第三方内部的进度或立即取消保证。仅 24 项历史保证响应有界，完整模型和任务日志继续使用现有入口。独立元数据刷新取消、ASR 检查点等能力不因有展示层而自动存在。

详见 [覆盖矩阵与证据](../research/automation-progress-audit-2026-10-15.md)。验证使用隔离数据和服务替身，不以正式外部写入作为回归测试。
