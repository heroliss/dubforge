# 0202 稳定的双播放器定位主导权

## 状态

已采用。

## 背景

成片参考播放器与原视频剪辑播放器共用一组定位联动。浏览器的 `seeking`、`timeupdate` 事件没有携带“用户操作”或“联动代码写入”的来源信息；两个播放器互相写入 `currentTime` 时，会产生异步事件回流，表现为拖动回弹、抖动或松手后跳回。

## 决策

- `VideoControls` 对一次定位提供 `seek-start`、`seek`、`seek-end` 生命周期；鼠标拖动、键盘定位和逐帧定位都走同一事件契约。
- 拖动期间由显式发出事件的一侧持有 `activeSeekOrigin`。另一侧的 `timeupdate`/`seeking` 只更新显示值，不反向改写主导播放器。
- 每次联动写入记录期望时间，并保留一个很短的迟到事件保护窗口。用户明确开始拖动另一侧时立即交接主导权，同时清理上一轮的期望值。
- `seek-end` 使用最终媒体时间再同步一次，然后延迟释放保护锁；联动关闭、项目切换和卸载时立即清理全部状态。

## 结果

拖动任一时间轴时，拖动来源稳定保持主导，删除段映射仍在源时间轴和成片时间轴之间生效；播放中拖动、快速切换另一侧、键盘与逐帧定位不会被对侧异步时钟抢回。
