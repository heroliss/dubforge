# ADR-0053：统一文件定位与已生成成品状态

日期：2026-09-28。状态：采用。

## 问题

总览文件路径不能直接定位；字幕、环境与配音日志的路径也各自使用不同交互。缺失成品被移入独立折叠区域，改变了用户熟悉的列表位置。更关键的是，自选的评论版使用 `comments:` 专用指纹，列表却按默认不带评论成片核对，因此文件与制作输入均未变化也显示“需重跑”；其他旧组合或试片缺失也会干扰整体判断。

## 决策

- 共用 `FilePathLink` 与本机 `/api/files/reveal` 入口：只选中文件，不执行；目录直接进入；缺失路径打开最近现存父目录，不创建目录。拒绝跨站请求、相对路径、网络共享与控制字符。原有产物下载/读取白名单保持不变。
- 项目文件清单给出绝对路径及用途说明，优先复用步骤注册表；按已知文件类型说明日志、评论、配音版本和试片，不读取文件正文来猜用途。
- 成品仍按原有组合顺序显示，当前记录是否存在不影响分组与位置。缺失在原行标记，并可单独确认“删除记录”；磁盘文件恢复后刷新即可解除缺失标记。用户主动删除记录之后不再承诺通过刷新找回。
- 清理缺失记录校验记录版本、项目归属、安全路径及实际缺失状态；文件在确认期间恢复则拒绝。只删除索引和更新原子项目清单，不删除磁盘文件、修改发布草稿或远端稿件。合成与发布占用仍拦截清理；锁顺序统一为发布门禁再制作门禁，与全流程启动一致。
- `Dependencies.fresh()` 继续服务执行器与计划的默认方案跳过判断；`display_fresh()` 服务状态界面，按最近正式任务的明确组合、输入指纹、上游可用性及该组合的最新文件校验。展示字段 `fresh` 与执行字段 `default_fresh` 分开，附具体标签和原因。试片不能代替正式合成；新任务保存方案专用输入指纹，旧任务按原有指纹算法兼容验证，绝不重写真实项目状态来消除警告。
- 已完成评论版沿用当次确认的评论快照，编辑评论草稿不使既有成品过期。改变实际制作输入、字幕或编码设置仍会提示更新；无关旧组合或试片的缺失仅在各自记录中提示。

## 验证

隔离测试覆盖中文/空格路径、文件与目录定位、缺失父目录、非法和跨站请求、文件用途；删除记录的确认、版本变化、文件恢复、并发占用、草稿引用及同名历史清理；旧评论指纹兼容、默认方案不可误跳过、真实输入变化、缺失当前文件及试片与正式任务隔离。前端真实组件测试检查路径入口、说明列、缺失行顺序、单独确认和防重复点击。

只读浏览器核对真实项目的总览与成品列表；不实际删除用户记录，不重生成或投稿。系统资源管理器调用在测试中模拟，不干扰用户窗口。
