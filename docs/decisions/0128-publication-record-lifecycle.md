# ADR-0128：草稿回收与发布记录归档

日期：2026-10-08。状态：采用。

## 问题

多份草稿和完成的发布记录长期占用工作列表，增加选错草稿和辨认状态的成本。直接删除发布记录会丢失原 BV、投稿回执、流程引用及防重复依据；本地记录管理也容易被误解为删除 B站稿件。

## 决策

- 发布状态和本地管理状态独立。归档或回收不改变原有上传、审核状态，也不清除 BV、账号、冻结快照、上传资料及流程引用。
- 已有远端证据的发布记录可归档，默认工作列表隐藏；仍可在已归档列表查看和恢复，且继续用于原稿关联、审核核对和防止重复投稿。
- 未发送、无远端证据的草稿可移入本地回收列表，保留数据库行和内容，支持恢复。此操作不删除项目成片、封面和 B站稿件，也不使用 Windows 回收站。
- 正在上传、提交、后台收尾，结果未知或被活动流程及发布批次引用的记录不能归档或回收。服务端核验实际执行归属和修订号，界面展示可用动作及具体原因。
- 回收草稿不再作为普通发布候选；原流程若仍引用它，须明确恢复或重新处理，不能因列表隐藏而默默创建另一稿件。归档远端稿件仍参加原稿识别，不能借归档绕过防重复规则。
- 项目发布页和全部发布记录页使用同一组生命周期动作与列表范围。常用列表只显示当前记录，已归档与已回收放在次级位置；操作前说明本地作用范围，成功后同步当前选择。

本决定扩展 ADR-0116 的记录管理，保留其项目发布入口和远端回执边界。项目及模板文件回收仍按 ADR-0117 处理，与发布草稿的数据库回收分开。

## 验证

隔离测试覆盖数据库增列、归档与恢复、草稿回收、修订冲突、活动引用和未知回执门禁、归档后的原稿识别、回收草稿的候选过滤及内容完整保留；不调用远端删除、上传或投稿。
