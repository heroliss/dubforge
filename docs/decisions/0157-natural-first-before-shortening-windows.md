# ADR-0157：先完整原速有界排布，再进入局部缩时分析

状态：已采用。日期：2026-10-15。

## 问题

运行中的工作台排布是只读派生，不会改变后续合成输入，也不会提前请求缩时。
但原算法在最多9句的窗口间按源字幕间隙中点固定分界，分界并不是真实声音
障碍，可能将邻窗可用时间隔开，错误地要求声音缩短。

手算实例：10句源时间依次为0–1至9–10秒，实际音频均为1秒，视频12秒。
最大位移2秒、间隔0.08秒时，旧算法给前9句的右界只有8.96秒，原速却需
9.64秒。实际可将全部起点放为0、1.08至9.72秒，完整末尾10.72秒，最大
位移仅0.72秒，不需任何缩时。此实例说明边界限制问题，未作运行验证。

## 决策

在每个真实硬障碍之间先调用已有有界保序最小平方位移求解器，对完整实际
音频尝试原速排布。成功时直接采用；失败时回退既有局部窗口的缩时容量建议。
保留最大单句位移、源句顺序、安全间隔、视频边界与人工固定位置，不扩大
位移上限、不跨原声/静音/未知音频障碍、不修改源稿或音频。原声与配音边界
也预留安全间隔；未知音频不猜测长度或末尾空位。原速尝试为线性开销。

`tts.placement.window_lines` 从严格的原速联动句数上限，改为原速不可行后
的局部缩时分析窗口，默认9、范围3～15保持不变。此项替代ADR-0153的严格
窗口限制；UI和配置说明同步改名。原速阶段实际联动句数可超过窗口配置，
报告如实显示实际段范围；每句移动仍硬受最大位移约束，不产生无限累计延后。

运行中继续预览已有音频的排布，界面注明“预览排布”。正常批次常规合成
完成后才执行缩时，每次返回重新尝试完整原速排布；失败收尾只更新报告。
更换策略版本使字幕/成片重新核对，声音输入指纹不因排布策略改变而失效。
不会自动把历史已经缩短的声音重新生成回原速，已有声音仍由用户选择。

修复另一个兼容性问题：保留旧音频时明确区分空重试历史与未启用保留。
没有`duration_retry`的旧音频仅使用自身生成快照中的真实因子；无法核验
则报告不可自动修复，不用当前配置猜历史。新结果较长时不覆盖较短旧声音。

## 本次检查范围

新增接缝导致多余缩时、真实障碍、安全间隔、位移边界、未知视频尾部、回退
窗口，以及旧音频空历史保留的pytest回归用例。按用户要求仅写入、不运行
测试或模型；进行Python语法静态检查及前端构建。运行时音质与完整回归未验证。
