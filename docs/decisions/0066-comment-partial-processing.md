# 0066 — 评论部分成功、逐条隔离与失败重试

日期：2026-09-29

后续调整：自动成片中的全量翻译已由 [ADR-0113](0113-comment-preparation-and-interruption.md) 改为候选按需翻译与递补；手工全部翻译仍供阅读，本文的逐条隔离、有效缓存与严格停止原则继续适用。

## 背景

评论评分的一批输入同时被火山方舟与智谱拒绝。智谱通过 `finish_reason: sensitive` 返回，需要归类为审核拦截而非空正文。此前只要一批失败便停止整个步骤，且新增评论使前端隐藏全部旧候选，即使多数评分和译文仍有效。

翻译不仅服务于上屏，也让用户读懂评论。因此自动流程保留全部评论翻译，不缩减为只翻译候选。

## 决策

- 正常请求仍为小批量逐行文本；内容拒绝、空回复、截断等单项生成问题才缩小批次，必要时定位至单条，原文、背景与评分要求不改写。格式错误使用已有有界纠错，不叠加第二轮格式修复。
- 单条失败保存独立状态与原始错误，保留原文；不将其冒充低分、不编造译文。有效评分和译文立即原子保存。鉴权、限流、网络、存储和取消等整体故障仍暂停。
- 增加统一配置 `comments.failure_policy`，支持全局→系列→项目继承；默认 `skip` 局部失败继续，可选 `stop` 严格暂停，自动流程冻结实际策略。
- 每次操作最多额外24次隔离调用；连续三个独立请求被审核拒绝则止损。未测项明确标为待处理，不能推断它们也被拦截。没有任何可用结果时仍失败；有可用结果则显示部分完成和明确计数。
- 失败缓存绑定原文、规则/背景（评分）、模型配置指纹。相同配置不会自动重复撞已知失败项；明确“重试未完成”或更换服务配置后再试。凭据仅参与不可逆指纹，不写入记录。成功缓存仍沿用既有有效性规则，不因换模型强制重做。
- 评论列表分别显示评分/翻译状态；已有有效评分不因新增评论被全部隐藏。提供“仅用已完成评分”，只更新候选、不请求模型、不自动勾选上屏或发布。
- 自动流程翻译全部未完成评论供阅读，再从有效评分中选择满足语言与长度要求的评论上屏。中文/双语不能把未翻译原文冒充中文；高分候选缺译文时按分数递补可用项。零条可用仍暂停，不默默省略评论。
- 上屏长度与阅读文字分离：内置中文 240、原文 600 字符限制，统一在 `comment_studio.OVERLAY_TEXT_LIMITS` 定义并通过 API 告知界面；不是平台投稿限制，当前不新增可调配置。后端自动候选、保存和渲染共用文字校验；前端按 Unicode 码点计数，避免表情在边界被误判。
- 批量“使用前 N 条可用评论”先排除当前语言下的超长、缺字项，再按分数递补。逐条显示具体原因与超出量；仅看分数合格不等于可上屏。人工精简草稿后可重新纳入，不改完整原文或译文。
- 自动流程共享的上屏列表还须满足本次各分P冻结的评论语言设置，防止主方案中文可用，但双语分P到合成时才因原文超长失败。
- 手动草稿仍可保留不合格项供编辑，但这些项不进入预览、时间轴和保存请求。确认弹窗说明实际保存数与排除数；全部被排除时禁止确认，避免误清空已有方案。保存后仅保留确认内容，弹窗明确告知排除草稿的编辑不保存。

## 验证

隔离测试覆盖逐条定位、部分保存、失败缓存、配置/原文变化、严格暂停、连续拦截止损、请求预算、取消、全量阅读翻译、缓存生成候选、统一继承与冻结、无有效上屏项暂停及前端意图传递。

只读实测原失败批次的第6、10条，在保留相同背景和规则后，智谱均能单独评分。这证明不能凭文本直觉认定第6条就是触发源；也不保证其他单条必然通过。探测结果未写入项目评分，未运行制作或投稿。
