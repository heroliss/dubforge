# ADR 0086：翻译窗口结构失败后的有界拆分恢复

## 状态

已采纳。2026-10-06 用户关闭服务并授权更新后，恢复实现已应用到正式代码，完整后端回归通过；项目 `99211e` 的独立翻译重试任务 #276 已完成。

后续调整：[ADR 0089](0089-proactive-text-windows-and-meaning-preservation.md) 增加主动小窗口、正常窗口的边界参考及独立策略缓存；本文件的有界失败恢复继续使用。

## 背景

项目 `99211e` 的任务 #269 有 316 句原文。模型三次均完整返回，却连续把 194 写为 204，并出现空译文与跨句内容搬移。原文编号和时间有效，响应正常结束，没有截断或超时证据。继续发送相同的完整窗口不能有效恢复；按物理行重新编号或拼接结构错误响应则可能把错误内容送入配音。

## 决策

- 保留 ADR 0010 的严格编号、顺序、非空、摘要协议和局部补缺策略。首次正常请求与 `window-v6` 缓存键保持兼容，不因为增加失败恢复路径而使已有成功项目过期。
- 同一窗口的三轮输出校验耗尽后，仅当最后一轮为已分类的编号结构或输出协议错误，且错误码为 `LLM_OUTPUT_INVALID`，才启动自适应拆分。单纯缺行、空译文仍用原补缺策略；网络错误、取消、未分类异常不扩张请求。
- 超过 40 行的失败窗口拆成连续、每窗最多 40 行的子窗口；不超过 40 行则按估算 token 量近似二分。保留绝对编号、原文和时长，串行重译并传递成功摘要；绝不采用失败响应的部分译文或摘要。
- 子窗口前后各最多两句原文作为理解参考，初次请求、局部补缺及校对均保留该参考；它们不属于待返回编号。最后子窗口继承父窗口的最终标志，其他子窗口必须交接。
- 对恢复后的叶窗口，再用原文与候选逐条紧邻的请求核对内容。校对响应必须完整覆盖全窗，不拼接不同轮次的部分结果；校对失败即停止，不采用未经校对的候选。合并父窗口不重复校对。
- 最多拆分两层，单句不继续拆分。每个原窗口最多 33 轮输出校验请求（原父窗口三轮，加翻译与校对共享的三十轮恢复额度）。成功缓存不耗额度；传输重试仍由已有 LLM 后端单独管理。达到上限时停止新增请求并给出未完成范围，保留有效子窗口缓存。
- 校对请求含原文、候选和边界参考，发送前按 90% 上下文预算守卫；重试只附加固定短提示，预算同时覆盖重试，避免完整错误诊断使请求膨胀。超过预算以 `LLM_CONTEXT_BUDGET` 停止。
- 子窗口缓存使用 `window-adaptive-v4`，绑定深度、最终标志、边界原文、交接摘要及原有输入、模型、提示词指纹。非最终窗口缓存必须包含有效非空单行摘要。只有全部子窗口校对完成并严格覆盖父窗口编号后才原子保存父窗口结果；子窗口失败不会登记整步完成。

## 后果与验证

结构失败可以自动缩小任务，而无需用户更改全局上下文参数。请求数有明确上限，正常一次成功的任务不增加模型调用。成功子窗口可以恢复复用；失败的父窗口仍会先走原有重试，再尝试其子窗口缓存。

新增 44 项回归覆盖串行摘要、绝对编号、边界参考、缓存、取消、错误分类、校对门禁、共享额度和上下文守卫，与原翻译测试共 127 项通过。应用后的完整后端回归 1,716 项通过（255.71 秒）；8611 端口的隔离服务启动、页面及静态资源检查通过。完整验证及真实模型对子窗口的效果见 [失败调查](../research/translation-failure-2026-10-06.md)。

编号通过和模型校对都不能证明语义完整或无重复。尤其 0.10 秒的单词片段可能使模型提前搬移信息。正式任务 #276 已生成对应全部 316 个源编号的非空译文，抽检的 154、194、204、205–208 对应改善；44–45 仍把“坐火车”提前到上一句，46 的源时长仍只有 0.10 秒。小窗口改善了结构恢复，但不能声称自动校对已彻底解决移句；仍需评估模型与源切分质量。本次不修改生产原文或其时间轴。
