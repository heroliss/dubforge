# ADR-0007：步骤级超时兜底

## 决策

每个可执行步骤都有独立的 `runner.step_timeout_seconds.<step>` 配置。计时从步骤取得并行槽位、进入 `running` 后开始；排队等待和用户主动暂停不计入。默认值按步骤常见耗时设置，项目步骤页可以覆盖全局默认，设为 `0` 可临时关闭。

超时后执行器发出协作式取消，终止已登记的外部子进程，步骤以稳定错误码 `STEP_TIMEOUT` 失败，并走已有的临时文件清理和自动续跑停止流程。步骤实现必须在循环、子进程等待和外部请求边界调用 `ctx.check_cancel()`，以便尽快退出。

## 原因

无人值守的多项目队列不能因为单个下载、模型服务、GPU 推理或转码任务永久无响应而无限占用并行槽位。步骤级兜底比一个全局固定时长更适合不同工作量：配音和分离通常远长于字幕生成，而排队时间不应误算为步骤本身耗时。

## 限制

Python 线程无法安全强杀任意阻塞调用。已登记的 ffmpeg/yt-dlp 子进程可以立即终止；第三方同步 HTTP 或 Python 库仍需等其自身读超时或返回到取消检查点。此时数据库状态会在安全收尾后变为超时失败，不会把未完成产物登记为正式结果。
