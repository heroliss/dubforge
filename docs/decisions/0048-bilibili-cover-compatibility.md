# ADR-0048：B站封面格式适配与创建失败诊断

日期：2026-09-28。状态：采用，已完成用户授权的真实创建验收。

## 问题与证据

用户选用的平台封面实际为 WebP。安装的 biliAPI 2.15.0 中，`readFileAsBase64` 只映射 JPEG、PNG、GIF，其余类型标记为 `application/octet-stream`。使用原 WebP 调用真实封面上传接口返回业务错误码 `-400`；转换成 PNG 后，封面上传及同一创建链路成功。

原实现还存在两层诊断信息丢失：工作进程将具体异常压成固定代码，后端再用同一条通用文案替换错误，无法区分登录、封面和创建阶段。此前模拟测试不能证明真实 WebP 封面可上传。

## 决策

- 保留原始封面、选择标识、预览与发布快照。只在远端上传前，将 WebP 生成兼容 PNG；JPEG/PNG 不转换。
- 创建合集与视频投稿共用 `publishing.covers.upload_path`。派生图片按原文件 SHA-256 与转换版本缓存，使用固定数量锁合并重复转换；不修改第三方包，不重新下载平台封面。
- 复用既有 FFmpeg，限制单帧、线程、解码协议、运行时间与输出尺寸；输出验证后原子写入，错误不得留下最终文件。
- `CollectionFailure` 分离登录校验、输入校验、封面上传、创建请求和回执阶段。只输出有界的业务文案、数字错误码、HTTP状态、已知网络错误；凭据、地址和堆栈不输出。后端持久化脱敏消息并向页面保留阶段诊断。
- 未发出创建或明确业务拒绝允许人工重试；网络异常/不完整成功回执依然保留待核对，禁止自动重发。

## 验收

用户明确授权创建，并指定名称“越南旅行”、简介“越南旅行视频合集”，封面沿用原选择。创建前读取列表确认无同名合集；修复后的单次创建返回合集 ID `9189472`，再次读取列表和详情核对名称、简介、归属及默认小节“正片”，均一致。仅创建空合集，未上传视频、投稿或改动已有稿件。

后端全量 844 项测试通过，前端 180 项、发布组件 38 项通过。新增覆盖真实 FFmpeg 转码、缓存/输入变化、不改原文件、错误不发布半成品、分阶段诊断与敏感信息剔除、API及数据库错误保真。浏览器工具本轮连接不可用，最终状态通过真实平台接口读取核验。
