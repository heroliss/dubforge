# ADR-0214：项目模板入口与统一混合批量运行

日期：2026-10-20。状态：采用。

## 决策

- 项目卡片提供模板选择与应用最新设置，复用基础应用预检、版本指纹及确认流程；应用保留项目覆盖，不自动执行。卡片使用批量SQL摘要，模板目录在展开时共享读取，不增加逐卡片配置轮询。不可读取的设置明确显示待核对。
- 多项目只有一个「批量运行」入口。生产范围、发布终点、账号、合集、分P、原稿目标继续以各步骤保存的项目设置为准，预检不创建另一份配置，也不提升既有草稿、上传清单或确认任务的授权。
- 按实际账号、合集、小节分组，与模板名无关。适合保序发布的同合集项目使用既有可靠顺序发布协调器，组内顺序经用户确认；其余项目使用独立流程。同合集组内等待审核与入合集证据，最后核验排列；不同组独立推进。不能只凭投稿请求成功标记合集顺序完成。
- 持久化父批次与分组，并登记子任务归属。父批次统一提供进度与按组/整批暂停、停止、恢复；旧顺序发布记录仍可恢复，统一父批次的子记录不再重复展示。任何手动单项运行仍受父批次占用约束。
- 确认目标与授权被冻结；排队中的普通制作参数可编辑，步骤启动时冻结实际快照。账号、交付终点、版本结构、分P与原稿范围等目标变化须离开原计划重新检查；不能借普通参数变化重建一份扩大授权的发布计划。
- 创建前先持久登记请求UUID，明确区分创建中、创建失败和就绪。网络中断不等于没有创建，重试与查回沿用原UUID。创建失败是持久终态，重启将未完成创建终结且阻止晚到工作线程复活；已有父/子登记回执丢失时找回原任务。启动也使用幂等回执，重启不自动继续外部发布。

## 验证

隔离pytest覆盖三项同合集加两项独立项目、跨组失败隔离、组内顺序、发布授权、占用与排队参数边界、轻量列表、创建并发及丢失回执。前端覆盖统一入口、模板目录共享与目录切换、应用差异确认、分组预检、暂停恢复、迟到响应和子记录去重。浏览器验收仅使用8611和专用诊断数据库，以伪平台边界保留真实批次协调器；不向B站执行真实投稿。
