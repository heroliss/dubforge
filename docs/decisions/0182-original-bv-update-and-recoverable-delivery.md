# ADR-0182：保留原BV的更新任务与可恢复交付

日期：2026-10-16
状态：已采纳

## 背景

审核退回后的修订视频应优先替换原稿对应分P，保留原BV及其历史。ADR-0083已经区分新投稿与原稿修订，但当时只能创建新BV，原稿换片仍需到官网处理。视频替换也会产生新CID；继续沿用旧上传回执设置章节，或给剪辑成片套用源视频时间，会把章节写到错误分P或错误位置。

更新原稿并非单个编辑请求。上传、提交原稿、转码审核、章节和合集可能分别成功或失败；页面需要表达当前实际完成范围，并能在重启或网络中断后恢复。

## 决策

### 独立冻结计划，保留原发布历史

- 使用独立的 `PublicationUpdate` 保存来源发布记录、账号、BV/aid、确认指纹、远端版本、完整原分P、新成片身份与摘要、本次文案差异、章节与合集范围，以及各阶段执行断点。
- 原发布记录中的制作快照和上传文件身份保持历史含义，不改为本次新成片；更新任务单独保存新上传回执及最终分P。原记录可以刷新平台审核状态等观察信息，并展示最近更新任务。
- 预览只读取和保存本地方案；用户一次明确确认后才执行所选范围。新成片、文案字段、章节和合集可以分别选择，不选中的资料保留远端值。未适配字段按能力目录说明边界，不能以“统一同步”暗示全部平台设置都已支持。
- “更新原稿件”放在发布步骤中的原记录内，作为保留原BV的主要入口；另发新稿和官网手工操作保持独立语义。本决策扩展ADR-0083，不改写其历史记录。

### 换片必须保留完整分P清单

- 本地只允许选择当前项目已登记、文件哈希与大小可核对、审查与修订记录仍有效的成片；不能由公共接口提交任意路径或任意上传标识。
- 按原CID逐一绑定待替换分P，要求目标唯一，新CID和上传标识不冲突。根据刚读取的远端清单构造完整最终顺序，未替换分P保持原位置、标题、文件身份及可保留的分P简介。
- SDK的 `replace` 模式替换整份分P列表，不能只传新文件。底层在发送前再次检查账号归属、BV/aid、远端版本、完整清单及特殊稿件限制，保留现有文案与受保护设置。
- 换片使用 `PublishChange(kind='replace')` 保存内部冻结请求，但不绑定追加分P使用的 `publication_id`，避免把替换误当追加并消耗原上传草稿。
- “平台接受请求”与“替换已核验”分开：完整CID、文件标识、标题和所选资料写后回读一致，才能确认换片完成；上传完成、转码完成与审核通过也分别展示。

### 一次确认，按阶段恢复

- 执行划分为上传修订视频、提交原稿更新、等待并核对审核、同步章节、核对合集、回读确认。每阶段保存状态、错误与必要进度；已完成上传和同步结果可以复用。
- 视频替换成功而章节或合集失败时，任务显示已完成和待处理部分。重试仅补做未完成动作，不再次上传或再次换片，也不把整个任务笼统显示为投稿失败。
- 已确认任务等待审核期间可以按计划只读核对；明确暂停后保留断点。进程重启不自动重新发送写请求，恢复后需要明确继续或核对。
- 账号与目标BV范围内设置互斥：更新正在执行、等待审核或结果未知时，其他编辑、追加、章节及合集写入不能争写；本次任务内部操作通过明确的执行归属继续，不能用全局绕过开关解除保护。

### 未知结果只读核对，不能盲目重发

- 写请求禁用传输层自动重试。明确未发送或平台明确拒绝，可以保留失败阶段后重新准备；请求已经发出但超时、回执丢失、回读延迟或回读失败，都视为结果未知。
- 未知状态持久化并阻止重复写入。核对动作只读取远端，与冻结请求对比；核对确认已应用后记录完成，不重放旧请求。仅核对这一轮不继续发送尚未执行的后续设置，用户可再继续剩余步骤。
- 写后读取返回明确错误，也不能据此断言此前写入被拒绝。证据不足保持未知，并清楚提示下一步；不能通过自动清锁或生成另一份相同请求规避保护。

### 章节绑定新CID和新成片时间轴

- 每个章节目标从更新任务中可核验的回执绑定，换片对应本次新上传CID，并核对完整分P清单、BV与aid；只更新章节的既有文件也需证明原回执与当前分P仍一致。不得按标题、当前列表序号或旧CID猜测。
- 章节输入在确认时随选中成片冻结。实际成功成片的剪辑快照决定源章节到成片时间轴的映射；剪辑片段消失的章节相应移除，其余边界按保留区间重算，并验证成片时长。缺失、失效或不能证明的时间轴阻断章节写入。
- LLM只对已经映射到新成片的章节进行相邻合并、翻译、短标题改写与表述审查。时间和完整来源覆盖仍由领域校验控制；平台数量、首章、最短时长、标题长度等限制继续使用统一规则。
- 章节整理经过统一LLM会话记录与执行进度。相同时间轴和要求可复用经再次校验的整理结果；失败重试保留已完成分P。已有远端章节默认不静默覆盖，必须包含明确的覆盖意图。

### 合集与其他设置的能力边界

- 文案和创作声明使用既有远端编辑白名单。封面、精选评论、可见性等仍按现有能力目录显示支持范围及官网处理说明，不扩大未经验证的写入承诺。
- 合集归属单独提交、单独核对。合集ID相同不能证明属于所选小节；需要完整小节成员列表和账号/小节归属证据，才能认定目标稿件已加入。
- 移出合集必须明确读取到无合集状态。缺失 `in_season` 或 `collection` 字段代表证据不足，不能转换成“已移出”。合集读写不可靠时保留独立待处理状态，不撤销已经完成的视频替换。

## 验证与边界

领域与API测试使用独立数据根、伪账号和伪平台响应，覆盖完整分P保留、并发版本冲突、重复提交防护、未知回执、阶段恢复、新CID绑定、剪辑时间轴、章节缓存与合集小节证据。Node测试调用真实SDK编辑方法并拦截请求，验证 `replace` 完整清单、参数保留、禁自动重试及写后回读。

浏览器验收使用独立临时数据库与配置，配合真实FFmpeg色块视频和真实成功成片剪辑快照，执行正式更新任务、修改状态机和章节交付逻辑；仅平台传输及LLM回复使用替身。首次章节失败后恢复时应只补章节，保留原BV及未替换分P。

以上证明本地编排、协议构造、恢复与界面行为，不等于真实账户换片已完成或平台审核一定通过。本次实现与隔离验收未向真实B站账号上传、替换或修改稿件；真实账号首次使用仍需核对实际回执、转码审核以及章节和合集回读结果，不能仅凭SDK支持宣称所有稿件都适配。
