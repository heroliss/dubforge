# 0231：显式成片编码与GPU资源准入

日期：2026-10-20；状态：采用。

## 原因

普通完整成片烧录字幕/评论时固定使用libx264、CRF及medium。4K长片在保守2/2/4线程和较低系统余量下可能耗时很长。已有审查修订的NVENC选择不是正常两版本制作合同，不能复用它把CRF当CQ，也不能在同一指纹下悄悄更换编码器。

## 决策

- 新增 `assemble.video_encoder=software|nvenc`，缺省software；新增独立 `assemble.nvenc_cq=18`。软件继续原CRF/medium；NVENC固定为H.264、p6/hq/VBR/CQ、b:v0的 `h264-nvenc-p6-hq-v1` 合同。保留源画幅、帧率、字幕评论和音频处理，不提供auto或静默CPU回退。
- 新选择进入版本values、来源、冻结Job/版本规格和manifest。软件缺省新增键不进入旧规范指纹；旧冻结规格缺键时明确software，不能继承后来全局nvenc。NVENC指纹只消费CQ与版本化profile，软件只消费CRF；画面复制不消费编码设置。运行资源、设备余量及时间不混入内容指纹，成功回执另存实际编码报告。
- 首版只支持普通完整编码。局部修订、内容级更新与剪辑的历史编码基准保持原合同；NVENC基准在建立/解析不兼容计划时明确拒绝，不混接编码头。旧局部版本的编码值与来源固定为基准，不因后来项目默认更换编码器漂移。
- 真正执行NVENC前借用既有TTS GPU资源组；已持有同组时不重入。再以短锁登记本机GPU编码预约，阻止任何本机后端/端口的新TTS use/start；远端请求不受阻。已有本机活跃用户、当前请求待核对、错误归属等会明确拒绝。只遵循既有auto_tts_vram策略停止身份核验通过的闲置托管服务，不停止外部或远端进程；预约与槽位在成功、异常、取消时释放，不跨长编码持有服务管理锁。
- 能力检查只在运行边界，有界调用FFmpeg/nvidia-smi/FFprobe，不加载CUDA/PyTorch或模型。检查编码器/p6/hq、设备0可用显存及8bit SDR支持范围；使用源画幅的一帧null初始化检查驱动/profile，不把该检查当作实片质量或速度验收。不强制降位深、转SDR或缩放。未知/不支持/显存不足有中文错误，旧成品保留。
- 两条正式mux共用编码helper，继续原临时文件、原子替换、取消和音频真峰复核。等待资源前清上一版本ETA；通过准入后才建立本阶段RateProgress和encoding阶段，等待不计入编码测速。软件路径不触碰GPU/TTS准入。

## 验证边界

隔离测试使用能力与进程替身，不运行真实GPU、FFmpeg或模型。覆盖独立旧canonical字节及CRF22/22.0兼容、非消费参数不失效、旧冻结与基准锁、双方资源竞态/跨本机端点/远端边界、身份与pending保护、取消/异常释放、两mux原子成功/失败及准入等待不污染ETA。相关旧配置/继承/托管服务回归保留，实际进程与FFmpeg样片测试本轮排除。

真实支持、编码速度与实际画质由根代理在安全窗口另做受控4K片段、文字/运动/色彩/同步及声音验收；CQ18不宣称等价CRF18。真实config.yaml由根代理原子补缺省键并单独验证，不进入源码包或日志。
