# ADR-0141：B站远端稿件对账与有限同步边界

日期：2026-10-13。状态：采用。

## 背景

本地项目同时保存制作参数、产物和投稿资料，而 B站也会保存稿件资料。只维护其中一份会在官网手动修改后产生错位；把所有官网字段都当作可写又会误报成功，甚至在平台接口不保证生效时覆盖用户设置。

## 决策

DubForge 支持远端稿件的显式读取、差异预览、一次确认写入和写后回读核验，但不承诺与 B站全部字段完全双向同步。已发布记录在“发布到B站”步骤内提供日常同步入口；“设置 → B站账号”保留账号范围内的高级稿件管理，不隐式插入制作或自动发布流程。

当前已验证的远端编辑字段：标题、简介、标签、粉丝动态、创作声明、已有分P顺序、合集归属；追加分P是追加动作，不替换已有分P。每次写入继续执行账号归属、版本冲突、特殊稿件检查，并且不自动重试可能已发送的写请求。

能力目录通过 `studio_capabilities.field_capabilities` 暴露每个字段的 `read_scope`、`write` 和中文 `reason`。`read_scope` 分为 `value`（详情可展示）、`guard_only`（只参与并发校验/保留，不能宣称已读取）和 `none`：

- `remote_edit`：已有稿件可预览后修改，写后回读确认。
- `submission_only`：只在新投稿阶段可靠，已有稿件需到官网处理。
- `read_only`：可以对账或保留原值，当前适配器不写。
- `unsupported`：没有可靠的读写契约，不在界面假装支持。

精选评论、关闭评论/弹幕、可见性、定时、分区、活动话题、字幕上传、商业推广、杜比/Hi-Res 等按字段能力显示原因；章节已按网页实际协议接入逐分P预览、确认、写入和回读，其他字段仍不能仅凭 SDK 类型扩大同步范围。

## 结果

本地发布快照可以记录最后一次对账时间和差异，用户能清楚知道哪些值已经同步、哪些需要官网操作。后续若接入新字段，必须先用真实账号验证“提交后读取一致”，再把字段从只读或投稿阶段提升为 `remote_edit`，并补充适配器测试；不能仅因为 SDK 增加了参数就扩大同步范围。
