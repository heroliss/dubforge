# 0114 — 制作计划归属与发布账号状态

日期：2026-10-08

## 背景

恢复手动制作计划时，普通合成步骤会转换为版本合成任务。原来所有版本任务成功后都不继续制作计划，导致成片已完成，计划仍显示执行中，并锁住后续操作。此前发布页没有草稿时固定提示连接账号，即使本地已经保存账号，用户也无法分辨只是没有稿件还是登录失效。

## 决策

- 制作计划只生成制作产物。准备草稿、上传和投稿由用户明确确认的完整流程或发布操作承担，不因制作完成或服务重启而隐式投稿。页面区分「制作恢复」与「完整流程 · 制作与发布」，同时显示新流程默认终点和旧运行的实际终点。
- 制作任务入队时冻结剩余计划摘要，并把当前 Job ID 绑定到项目计划。只有同时匹配 Job 与摘要的完成通知才能推进计划。停止、放弃和计划结束清理绑定；显式预览、指定输出、指定版本任务没有制作计划归属。迟到的旧任务不得推进或挂起后来确认的计划。
- 启动恢复只收尾可证明完成的合成链尾：剩余仅有合成、没有本次中断任务、最新 Job 和 Step 成功对应、冻结版本定义和当前版本一致，且所有版本的输入指纹、产物登记和文件大小有效。旧任务还须具备冻结恢复方案证据。原片直用复用渲染器的判定并核对源片登记与依赖；需要静音的原片仍须有独立成品证据。缺少证明仍保留为挂起；不清除用户取消或普通失败原因，不开始任何新任务。损坏的挂起记录归为稳定的 `CHAIN_INVALID`，避免首次重启改成中断后，第二次重启误当可收尾计划。该核对不扫描大视频的全量文件哈希。
- 当前制作状态优先显示；上次完整流程的中断另行标记，不覆盖当前制作。有效成片只表示已有版本可复用，发布提示仍要求检查实际版本范围及待补步骤，不暗示新增未生成版本已经完成。
- 发布目录是本地读取，不是登录验证。分别呈现正在读取、读取失败、没有账号、已保存账号及尚未选择发布记录。只有成功读到零账号才引导连接；失败保留已有资料及重读入口。
- 手动「检查登录状态」只读取一次平台登录身份，返回账号、昵称及检查时间，不读取合集、上传或投稿。只有明确未登录归类为登录失效；网络、风控和异常结构表示尚不能确认。最近成功标明「当时有效」，不声明永久有效。
- 账号检查防重复、忽略离开页面或账号变化后的迟到响应。普通目录刷新保留身份及 revision 未变化账号的完成结果；账号删除、身份变化或重新登录使旧检查失效。

## 验证

隔离 pytest 覆盖普通版本合成推进计划、显式任务隔离、旧任务与新计划隔离、安全启动收尾及拒绝缺失证明；账号接口测试验证只读返回、错误分类与凭据隔离。离线 worker 测试拦截 SDK 请求，验证只访问登录身份接口。前端组件测试覆盖账号空态、重读、人工检查与迟到响应，以及制作/完整流程的状态优先级和明确恢复终点。浏览器核对已有项目的只读页面，不触发真实上传或投稿。
