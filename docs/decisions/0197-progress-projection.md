# 0197 · 统一制作与原稿更新进度投影

## 状态

已采用

## 决策

所有用户可见的进度都来自各自任务的事实快照，不把不同任务混成一个百分比：

- 制作步骤继续使用 runner 的 `execution`，显示当前步骤、可量化进度、ETA 和日志。
- 首次投稿使用稿件上传、投稿、审核和章节交付自己的执行快照。
- 更新原稿件使用六个阶段（上传修订视频、提交更新、平台处理、章节、合集、回读核验）。后端统一计算阶段进度，并把 `progress_detail` 投影到项目列表、总览、项目空间和发布页。
- 跳过的阶段不参与总体百分比；没有可量化比例的审核、远端回读等阶段显示当前阶段和处理中状态，不能伪造百分比。
- 列表接口只返回有限的进度摘要，完整冻结方案仍由发布页读取，避免总览轮询造成大对象和 N+1 查询。

## 原因

项目卡片、总览、项目空间和发布页原先只能看到制作步骤或首次投稿，原稿更新在后台执行时容易被误认为已空闲，且不同页面的百分比可能不一致。统一的后端投影可以保持页面语义一致，同时保留各任务的独立生命周期。

## 验证

后端原稿更新及发布回归测试通过；前端原稿更新、发布进度、项目列表和工作流 focused tests 通过，类型检查与生产构建通过。
