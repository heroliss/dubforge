# ADR-0015：简化下载估算与 LLM 预计进度

- 状态：已采纳（2026-09-24）
- 取代 ADR-0014 中下载滑动窗口、LLM 仅按完成窗口推进与三条样本门槛的规定。

## 背景

首次语义整理可能只有一个大窗口，模型长时间思考又没有回调，旧进度一直停在 0.5%。用户明确要求：有真实工作量就展示真实完成比例；只有 LLM 等无法测量完成度的阶段使用耗时估算，避免把下载等简单任务复杂化。

## 决策

1. **下载**：百分比使用音视频合计已下载字节 / 总字节。ETA = 剩余字节 / 本次累计平均速度；累计速度为本次新增字节 / 活动耗时，断点已有字节不计入测速。至少积累两秒有效时间再显示，暂停不计时。下载后的合并与登记不猜耗时，执行器成功前仍保留 99% 上限。
2. **LLM 默认值**：语义整理或翻译整个步骤默认 600 秒，多窗口按原文长度分摊。显示区间为准备 1%、思考 60%、输出 38%、收尾 1%。准备和收尾由真实事件完成，不人为等待六秒；请求预算按 60:38 分配。只有收到正文才进入输出阶段，模型内部思考字符数不用于估计完成度。
3. **历史估算**：沿用同任务、模型连接及参数、模式分组的最近 20 条正常窗口记录。选择输入量在当前窗口一半至两倍之间的记录，换算为单位原文长度耗时，排序后两端各删 `floor(n/3)` 条，平均剩余记录并乘当前输入量；1～2 条直接平均，无可用记录则回退默认值。使用同一预测计算百分比和 ETA。缓存、失败、取消、超时、重试、降级不作为正常历史；拒绝流式或专属参数后的兼容重发也标记为重试，采样前再次检查取消与超时。样本按窗口独立记录，后续窗口失败不否定此前正常完成的窗口；实际暂停时间由活动时钟扣除。
4. **阶段与超时**：每阶段前 80% 预算匀速推进，随后逐渐靠近该阶段上限。当前阶段超时或正在重试时撤下倒计时，显示仍在处理及已用时间；新的正常窗口恢复估算。不倒退、不按计时伪造下一阶段，也不在任务结束前显示 100%。比例和曲线是改善显示的工程默认值，不声称是经校准的统计最优预测。
5. **刷新与文案**：步骤页、管线页和项目列表在 API 轮询时读取同一个实时估算器，即使没有流式回调也更新。LLM 明示“预计”，下载等实际工作量不使用时间推动百分比。沿用活动时钟和 `progress_timing.json` 原子存储，无新增配置项。
6. **文本提示词**：语义整理、结构重试和翻译共用简洁的上下文纠错引导，主动核对疑似错词、专名、数字和单位等，不为个别词设置专用案例。语义整理提供源语言、用途和时间建议；翻译优先采用用户风格要求，允许润色、方言、幽默、网络用语等本地化。提示词以背景、目标、建议和简短输出约定为主，避免重复限制。提示词版本进入文本步骤和翻译窗口指纹，避免重跑时复用旧策略缓存。
7. **语音转文字（实测后补充）**：模型加载、音频准备和首批识别不返回完成量，显示阶段、等待动画和已用时间；不套用 LLM 的十分钟估算。结果返回后按原始音频时间点 / 总时长更新百分比，允许分批跳动。累计平均速度只在完成量增加时更新，批次之间使用该次 ETA 倒计时，耗尽则暂时隐藏；下一批到达后再修正，不强制 ETA 永远下降。模型加载与音频准备不计入识别速度，活动时钟仍排除实际暂停。不读取 Whisper 私有识别窗口、不另建耗时预测模型。

## 验证与限制

- 可控时钟测试覆盖无回调首跑、截尾平均、不同模型/规模、阶段切换、超时、缓存与重试；API 测试验证两个入口的进度一致且轮询不写数据库。
- 提示词与缓存测试验证纠错和风格要求完整传递，新版本不复用旧结果；它们不能证明真实模型的纠错准确率。纠错仍取决于上下文与模型，不做针对孤立词的全局替换。
- 历史总耗时受排队和输入内容影响；固定阶段比例可能偏差较大。先保持规则简单，根据实际运行反馈再决定是否值得记录阶段耗时。
