# 0064 — 评论 AI 对话诊断与有界纠错

日期：2026-09-29

## 背景

评论评分完成 60/90 条后失败，但评论层将底层异常统一包装为“请检查 LLM 设置”，既未记录对话也未落盘原始错误分类，无法区分限流、超时与模型格式错误。

## 决策

- 步骤详情的“运行日志”与“LLM 对话”分为相邻入口。获取视频页的对话区按评分/翻译切换，日志与对话并排，小屏纵排；已有语义整理和翻译对话保留。模型文本转义呈现，系统提示和模型返回的思考默认折叠，不执行其中指令。
- 评论评分、翻译各保留最近一次任务的日志、JSONL 对话和原子状态快照，重启后可读终态；运行中断状态不会伪装成仍在运行。增量读取与原步骤对话共用游标/代次逻辑，半行不提前消费。原先未记录的旧对话不能恢复。
- 仅记录业务提示、模型输出、重试、校验和错误。写入日志、对话、错误和状态时脱敏已配置凭据以及常见令牌格式；不记录 HTTP 请求头和鉴权内容。诊断写失败不破坏制作产物，但必须提示用户。
- 有效评论逐批或局部原子保存。缺项、重复 ID、非法字段只补未完成部分；未知 ID 不进入资料。只允许明确等值的数字/布尔字符串类型归一，不捏造内容、理由、评分或合格判断。
- 每原始批次最多三轮内容生成尝试；格式失败后可把剩余项拆成两个小批次，各最后尝试一次。任何小批次仍失败即停止，整批最多五轮。下层现有网络退避与多配置降级独立有界；鉴权/限流/连接错误不触发内容修复或批次拆分。
- 保留 LLM 错误码和具体原因；业务取消、保存错误不视为格式失败。单次任务固定 LLM 配置池，取消后的模型结果不写入。
- 诊断读取、展开面板都不启动模型请求、合成或投稿；失败后由用户明确继续，已通过校验的缓存按原文、规则与视频上下文复用。

## 验证

隔离测试覆盖部分成功、定向补齐、类型修复、缩小批次上限、取消和磁盘错误不重试、服务错误透传、重启恢复、脱敏、分页半行/代次、前端迟到响应隔离、纯文本渲染以及只读边界。
