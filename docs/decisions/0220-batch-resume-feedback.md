# 0220：批次恢复的即时反馈与准备阶段

日期：2026-10-20

状态：采用

## 背景

确认继续后仍需要执行最终预检、复用检查和排队。此前界面只显示按钮转圈，项目卡片可能继续显示上次失败；完整项目列表又需要核对产物，批次与项目列表的常规轮询分别为四秒和五秒。合集父执行器还在子执行器最终预检前重复读取了一次在线恢复方案。

## 决定

- 请求发出时以独立反馈说明“核对方案”“提交请求”；只有收到确定成功回执才显示受理。未知回执保留原请求标识和作用域，不宣称已经开始。
- 已受理分组保存 `feedback=preparing`，未完成项目保存真实排队及准备说明。该字段独立于 StepRun、Job 和执行百分比；完成项与未选择的组保持原样。
- 项目进度条附近即时显示请求/准备状态。受理后使用有界的轻量批次同步（最多六次、二十秒窗口），不增加完整项目列表的扫描频率。
- 轻量回执只更新项目的批次摘要；慢完整列表返回时保留较晚回执，并把合并后的服务端摘要保存到列表快照。下一次在回执之后发起的完整读取接回真实结果。本地请求意图不写入持久快照。
- 继续同一未知请求时复用 UUID；确定受理或明确拒绝后消费该标识，新的恢复动作使用新 UUID。
- 删除合集父执行器的一次重复在线预检，直接向子执行器传入父方案已确认的指纹。子执行器保留最终在线检查、锁内本地检查及全部发布回执/占用门禁。
- 暂停、停止、失败和重启清理准备字段；受理事务同时清理已恢复组的历史聚合错误。

## 边界

不伪造制作步骤已运行，不显示虚构百分比，不扩大发布授权或自动重投。准备态采用无确定百分比的排队反馈；真实工作流及 Job 受理后转交实际阶段。隐藏页面和卸载停止快速同步，工作目录切换清理本地请求反馈。

## 验证

覆盖单组授权、已完成项保持、回执幂等、未知回执重试、再次中断后的新请求、迟到列表与快照、轻量轮询上限、生命周期清理、最终指纹变更阻断和空执行诊断的准备显示。8611 隔离验收沿用真实批次、工作流、Runner，仅替换制作计划和物理步骤；通过人为延迟核对及受理后的准备阶段，检查 UI 立即反馈与真实 Job 的交接。
