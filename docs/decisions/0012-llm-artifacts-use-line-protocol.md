# ADR 0012：语义整理与翻译产物采用行协议

## 状态

已采用

## 背景

语义整理和翻译的大模型输出已经是固定编号行协议；此前校验通过后还要转换成 JSON。二次转换增加了落盘代码和字段形状，也让产物不能一眼反映模型实际返回。项目里其余 JSON 是内部机器结构，例如词级时间戳、任务表和统计信息，不适合强行改成单行文本。

## 决策

- `split.json` 改为 `split.txt`：`序号. 开始秒-结束秒: 片段`。
- `translate.json` 改为 `translate.txt`：`序号. 译文`；句数、序号及顺序与原文一致，每句译文非空（2026-09-24 同步 ADR-0010 的逐句对齐要求）。历史文件读取仍兼容旧格式，新生成结果按新约定校验。
- 通用序列化/解析和原子写入放在 `dubforge.utils.lineprotocols`；正式产物校验仍使用步骤内的严格协议校验。
- 只转换大模型直接输出语义整理和翻译这两类产物；`words.json`、`meta.json`、`dubtask.json`、`subtitles.json` 等继续按 JSON 保存。
- 产物名变化会让旧项目中的 split/translate 状态按新产物声明失效并需要重跑；这是接受的一次性迁移成本。

## 结果

产物即协议文本，人工可读、可 diff，也便于未来交给支持编号行的普通翻译程序；下游只解析一种稳定文本格式。内部复杂结构仍保留 JSON，不为了统一格式丢失类型和字段。
