# 0210：项目成片版本删除与发布引用同步

状态：已采纳

## 问题

成片工作台原来的“移除定义”只修改本地草稿，入口不够明确；保存时若发布分P或标题仍引用该版本，会校验失败。版本定义、已经生成的媒体和历史发布记录有不同生命周期，删除定义不能破坏仍被修订版使用的基准文件。

## 决策

- 在版本清单和当前版本编辑区提供明确的删除入口。已保存版本先取得删除预检，再由用户确认后立即保存；未保存的新版本只移除本地草稿。
- 删除仅移除本项目的有效版本定义。正式成品、试片、产物登记、成功制作快照、不可变修订方案和发布记录全部保留；文件回收继续使用正式成品管理中的独立功能。
- 同一配置事务内更新版本清单、显式发布分P选择和分P标题。若删除会清空显式发布选择，则阻止删除，要求先选择其他发布版本；不自动把其他视频加入发布清单。默认发布全部版本的继承语义保留。
- 每个项目至少保留一个版本。删除继承版本只在本项目建立覆盖，不修改全局或系列模板。
- 删除属于结构操作，使用项目级任务门禁，拒绝排队、运行、发布、流程占用和已归档项目。提交必须带明确确认、预检取得的修订号及配置指纹，确认期间的配置变化会使操作失效。
- 已保存版本有未保存的版本或剪辑调整时，要求先保存或放弃调整。重复点击、旧项目的迟到预检、确认框跨项目切换不得导致额外删除。

## 验证

隔离 pytest 覆盖发布引用原子更新、唯一发布项与最后版本保护、任务门禁、并发冲突和媒体及历史证据保留。前端回归覆盖预检确认、草稿保护、失败与重复提交、切换项目和选中状态修复。真实浏览器删除验收只在 8611 的独立测试数据目录执行。
