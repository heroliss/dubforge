# ADR-0118：全局根设置以已保存值为撤销基准

状态：已采纳，2026-10-08。

状态更新：项目恢复操作的实时继承含义已由 [ADR-0126](0126-stable-project-settings-and-model-services.md) 替代；全局未保存修改的撤销行为不变。

## 背景

全局、系列模板与项目共用稀疏覆盖编辑器。全局字段的恢复箭头原先也移除已保存的覆盖键，实际回落到配置文件与程序基础值，却显示「恢复继承」，容易被理解为继承某个上级或撤销本次修改。用户希望以当前全局设置为基准。

## 决策

- 全局默认是用户配置的根层，无上级。单项操作改为「撤销修改」，仅字段存在未保存变化时显示，恢复本次读取或保存成功时的全局快照，不清除原已保存值。
- 已保存值包含明确的 `false`、`0`、`null`、空字符串和复合对象；字段原来没有单独设置时，撤销移除新草稿键，回到读取时的有效值。
- 点击单项撤销只改草稿，保留其他字段修改，不发保存请求。保存成功后新值成为撤销基准；保存失败保留原快照与草稿。运行中的编辑锁同时保护撤销。
- 系列模板与项目继续以「恢复继承」移除本层覆盖。全局页面内的成片版本差异仍有共同样式这一上层，其恢复继承行为保留。
- 全局字段及发布选项不再显示「继承自全局默认」的自我继承提示。全局底栏统计未保存修改数，模板与项目继续统计明确设置数。
- 不迁移当前全局参数到代码默认、配置文件或另一份基础快照；实际参数及现有数据库结构保持一致。

## 验证

使用隔离组件测试验证真实按钮事件、保存后更换撤销基准、特殊空值、复合清单、发布选项、版本内部继承及运行锁。模板与项目继承操作保持兼容。
