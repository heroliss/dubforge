# 0103：项目自动名称与手工名称分开保存

状态：已采纳

## 问题

批量地址导入为了快速预览、可重复创建，不联网获取资料，原先直接用域名和视频 ID 作项目名。下载随后保存了原始标题和中文标题，但项目名称没有同步。失败条目重导还会把占位名称写成显式 title，丢失用户原本未填写名称的意图。

## 决策

- Project 增加独立的 `title_mode`：未填名称的新项目为 `auto`，显式填写或手工改名为 `manual`。该字段属于项目管理，不进入制作参数或步骤输入指纹。
- 批量预览与创建保持离线、快速；资料获取成功后，自动名称优先使用未过期且生成成功的中文标题，其次原始标题。获取资料前使用“平台视频 · ID”等可读占位名称。
- 名称与资料保存分开。下载复用缓存及独立资料刷新均可同步自动名称；无有效标题、资料来源不符时不写入。自动同步失败不把完整视频获取判为失败。
- 同步采用带 UID、来源和自动模式条件的列更新，避免迟到资料覆盖手工改名或新来源。手工名称一直保留；改名窗口可显式选择“使用视频标题”恢复自动模式。
- 导入冻结计划保存 `requested_title` 和 `title_mode`。回执用项目当前名称展示，但失败重导仍按原始命名意图创建；历史查询只批量读取 UID 和标题。
- `title_mode` 写入原子清单，重建索引时恢复。旧数据库和旧清单默认 `manual`，不能靠名称形状猜测并覆盖用户意图。本次用户明确指出的旧批量占位项目，通过现有改名 API 使用缓存恢复自动名称。

## 结果

名称变化不移动目录，不改变 UID，不重跑步骤，不改发布草稿，不引入新 LLM 请求。列表直接读取已经保存的管理名称，无逐项联网和隐式写库。批量项目在首次取得资料之前仍需占位名，界面明确说明这一时机。
