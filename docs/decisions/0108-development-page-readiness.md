# 0108：验证开发网页入口并记录启动器生命周期

状态：已采纳

## 问题

用户遇到网页“连接被拒绝”，前后端日志只记录曾成功启动，无法还原启动控制台随后为何退出。原就绪检查只验证前端 HTTP 200，复用后端时还跳过后端健康检查。浏览器启动异常会进入外层清理流程，关闭已就绪的服务。

## 决策

- 网页入口必须同时返回 DubForge 页面和有效的代理健康响应；复用后端仍检查健康。只验证响应，不自动改浏览器或代理设置。
- 自动打开浏览器失败只提供中文提示和手动地址，保留前后端运行。
- 控制台记录端口、就绪检查、打开请求、输入 EOF 和正常退出命令。硬关闭进程不宣称能记录原因；日志缺少退出事件只说明没有正常退出记录。
- 保持已有生命周期：控制台运行时服务存在，quit/关闭控制台结束本次前后端；独立配音服务与复用后端保留。网页入口明确说明该关系。
- 提供 logs launcher，与已有日志查看/跟随入口共用。
- `open` 优先使用已通过网页和 API 代理检查的开发前端。开发前端不可用时，先验证同端口后端健康、DubForge 构建 HTML 以及入口引用的本地 JavaScript/CSS 资源，再打开后端备用页面；单独 API 存活或资源失效都不能误报可用。回退只打开浏览器，不启停后端，也不重试制作或投稿。备用页面可能落后于开发代码，控制台明确说明。

## 验证

Windows PowerShell 回归覆盖页面 200 但代理不可用、错误应用、浏览器打开异常、开发入口优先、构建页面回退、API 存活但无 UI、构建资源失效及复用后端健康检查。真实服务验证仅使用 8611 端口。
