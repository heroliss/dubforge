# 0219：批量中断分层显示与模型账户错误分类

日期：2026-10-20

状态：采用

## 背景

混合批次按分组独立推进。旧界面同时展示父批次聚合错误与各组原始错误，两个组遇到相同模型问题时产生三处重复长响应，难以区分故障范围。HTTP 429 又可能承载服务商余额不足等业务错误，不能统一引导为等待限流结束。

## 决定

- 批次顶部使用实际分组状态计数，只有失败或待处理组参与故障汇总；正在运行的组保持自己的状态。
- 已知模型问题按配置名称及故障类别合并，显示简短中文原因与模型设置入口。未知原因保留各组独立范围，不声称它们存在共同根因。
- 各组保留中断步骤、项目、单组检查入口；技术响应默认折叠。父错误仅在可确认由子错误聚合而来时去重，独有父错误仍保留。
- 新增稳定模型错误码 `LLM_QUOTA_EXHAUSTED` 与 `LLM_SUBSCRIPTION_INVALID`。传输状态处理之前先识别明确的账户业务错误，避免无效重试；普通临时 429 仍沿用原冷却及配置降级。
- 只检查服务商错误信封，不扫描正常模型正文。原始错误详情继续保留，服务故障不能作为单条评论的内容拒绝跳过。
- 历史记录只有泛化 HTTP 429 时，显示“请求受限，需核对限流或配额”，不反推余额不足。

## 边界

不新增数据库字段，不增加列表轮询查询或联网检查，不修改冻结配方、产物指纹、发布回执和恢复授权。修复服务后仍需走原批次检查及确认，不能自动重新投稿或忽略必需步骤。

## 验证

模型解析、传输与评论恢复采用离线 MockTransport 回归；前端验证分组范围、已知/未知问题去重、父独有错误和原有恢复请求。另用独立数据根和 8611 端口，通过真实列表 API 验证旧记录的双组中断、运行与中断并存、不同故障及折叠详情。展示样例不启动真实调度或外部调用。
