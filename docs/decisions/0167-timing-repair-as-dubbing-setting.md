# 0167 配音冲突修复归入普通配音设置

日期：2026-10-15。状态：采纳。补充 ADR-0152、0155、0132。

## 问题

“自动修复配音时间冲突”原来写入本次运行的 `dubbing.repair_timing`。全流程、恢复、批量弹窗都复用本次配音组件，因而重复出现一个默认开启的勾选项；普通配音设置不能表达同一策略，步骤与全流程的行为也容易分叉。

## 决策

1. 新增普通布尔设置 `tts.placement.auto_repair`，默认开启，放在“字幕与配音 / 配音时间排布”。采用现有全局默认、系列模板、项目固定基础值及稀疏覆盖机制；提供已有的来源标记、恢复继承和应用最新设置。保存只改变下一次执行的策略，不启动合成。
2. 本次配音意图只表达生成范围、目标槽和精调/手动声源保护。新前端不再发送 `repair_timing`；运行与恢复弹窗不再提供独立勾选，只读显示预检解析出的实际策略。尚未预检的批量总控明确按各项目已保存设置执行，不能猜测统一开启或关闭。
3. 单项目弹窗可以跳到普通配音参数组并展开。策略的详细解释、继承和编辑留在参数表单；运行方案只展示影响摘要，减少重复配置。
4. 配音进入执行时随正常设置快照冻结；排队中及未开始步骤允许按现有规则修改。策略本身不改变已有声音或成片内容身份，不因切换此开关要求全部配音重新生成。
5. 开启时先利用邻近空位排布，仅对仍不足的目标有限缩短；关闭时仍可排布，但不自动缩短新旧音频。选句执行不扩大声音修改范围。自动缩时适用于IndexTTS，历史声音需要可复现生成快照；原引擎不支持或快照不足仍明确提示。历史配音修复沿用原生成参数，保留同槽历史、人工声源和人工位置。
6. 兼容旧任务中明确保存的 `repair_timing`，历史展示与已冻结执行保留其原语义。重新预检的新运行/恢复方案以项目普通设置为准，并显示实际策略；不重写旧记录来伪造其来源。

## 验证要求

覆盖全局/模板/项目继承与覆盖、普通配音及自动流程读取同一值、排队和运行快照、新旧运行意图兼容、开关不影响已有产物指纹、关闭后不缩短音频。前端覆盖所有恢复与批量入口没有修复勾选，预检只读说明准确，跳转能展开对应参数组。

## 验收记录

- 真实浏览器与本地API在隔离8611端口验收：普通参数关闭时全流程显示“仅排布并提示”；从快捷入口进入配音页自动展开参数，开启并保存后重新预检显示“自动修复”。弹窗没有独立修复勾选，项目参数具有来源标签和恢复基础值按钮。没有启动真实模型或执行制作、投稿。
- 前端全量1187项通过；最终悬浮说明变更后关联131项通过，最终构建通过（7.83秒）。
- 后端13模块扩展379项通过；最后98项恢复、设置与执行回归通过，覆盖真实恢复提交保留operation ID、目标槽和已成功音频，以及旧策略开启/当前普通设置关闭时仍按历史冻结值实际使用缩短因子。各定向集合存在重叠，不直接相加。
- 后端完整回归4253通过、4失败、2跳过（717.08秒）。4项失败揭示此前发布准备中稿件ID变量被字段循环覆盖，以及一个旧测试替身未接受新对话归属参数；已修复后重跑发布准备、文案、执行诊断、完整流程、顺序批次与对话归属6模块，201项全部通过，包含原4项失败及新增稿件身份/幂等回归。最后这两处修复后没有再重跑整套后端；结果为完整运行加针对性修复验证。
