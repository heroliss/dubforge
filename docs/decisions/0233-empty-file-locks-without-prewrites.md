# ADR 0233：空锁文件直接加锁，不预写占位字节

日期：2026-10-21

状态：已接受

## 背景

完整音轨缓存与开发服务登记使用操作系统文件锁，协调同进程线程和独立进程。原实现会先检查空文件、写入占位字节并刷新，再尝试取得锁。

Windows 完整回归暴露了竞争窗口：两个调用都能先观察到空文件；其中一个完成写入并加锁后，另一个尚未刷新的写入会碰到已锁字节，抛出权限错误。该错误发生在等待锁的重试区间之外，可能把正常竞争误报为缓存读写失败。

## 决策

1. **直接锁定偏移 0 开始的一个字节，不预先写入内容。** Windows 的 [`_locking`](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170) 明确允许锁定文件末尾以外的区间；Unix 的文件锁同样不需要占位内容。空文件及已有占位字节的旧锁文件都沿用同一锁范围。
2. **保持现有等待、取消与释放合同。** 音轨缓存等待时继续检查取消；服务登记保留原有等待期限与错误码。锁在退出上下文或进程结束时释放。
3. **保留锁文件，不通过删除文件模拟解锁。** 这样各调用始终协调同一路径对应的文件；不改变缓存指纹、原子写入或已有服务进程的身份校验。
4. **回归验证实际竞争。** 用事件控制旧初始化窗口，并验证空文件跨句柄互斥、等待取消和异常后释放；正常并发仍只产生一次缓存处理。测试使用临时目录，不启动或接管用户服务。

## 结果与边界

修复同时覆盖完整音轨及复用该锁的声音质量缓存，并消除服务登记中的同类预写竞争。该变化不改已有成片、配置、缓存内容或发布回执，也不把网络共享、远程文件系统的锁行为列为已验收范围。
