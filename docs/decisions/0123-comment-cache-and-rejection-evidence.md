# 0123 — 评论缓存、定向重试与审核拒绝证据

日期：2026-10-08

## 背景

北京景点项目的 35 条评论中，31 条已有有效译文，4 条保存了历史服务商审核拒绝。最新补译任务新增 0 条、复用 31 条、跳过 4 条，没有发出模型请求。界面的“全部翻译成中文”和通用成功提示容易让用户误以为它重新翻译了所有内容，或认为 4 条问题项已经处理成功。

最新评分响应分别包含 `content_filter` 和 `sensitive`。历史译文任务只保留逐条错误摘要，原请求对话已被后续运行替换，无法还原拒绝发生在单条还是批次。服务商拒绝请求不能直接等同于本地上屏审查命中，更不能据此保证或否定 B 站审核结果。

## 决策

- 成功译文继续按评论来源指纹复用。补译只处理缺失项，既有译文、采集原文和用户编辑的上屏稿保留；界面以实际新增、有效复用、问题跳过及暂缓数量报告结果。
- 延续 ADR-0113 的范围：定向重试补失败与暂缓项，不把服务商明确拒绝项混入普通重试。相同请求依据下，即使传入 `retry_failed` 或评分 `force`，也不重复发送已记录的拒绝项。原文、相关评分规则或背景、实际模型配置变化后，旧问题证据不再阻止新请求；成功缓存不随之无端丢失。
- 拒绝证据记录实际请求范围及评论来源哈希。批次拒绝只说明所在请求被拒绝，不将批次内每条都判为独立触发项；同批次任一来源变化应使该请求的旧拒绝证据失效。历史记录缺少范围时显示“请求范围未记录”，不推断它是单条请求。
- 拒绝项保留受控的服务配置名、错误代码和结束原因，经过脱敏与长度限制；不保存完整请求或任意响应正文。后续零请求的缓存运行仍可查看这些原因，历史记录缺少字段时不补造证据。
- 保留有预算限制的失败隔离及候选递补。未取得有效译文的评论不会冒充中文或自动上屏；普通阅读的全量补译与实际候选翻译仍是两个用途。
- 服务商审核拒绝、本地规则命中、网络或输出格式错误分别显示。按真实状态提供补译、失败项重试及对应诊断入口；不以空对话记录表示“全部翻译成功”。对疑似误判，可以核对原始请求与服务政策或联系服务商；应用不变造原文或伪造译文以解除拒绝。
- 将审查面板标题改为“内容审查与屏蔽”，明确制作时机：字幕导出隐藏命中句，合成成片处理命中时段声音，发布前核对所选文件是否应用当前规则。修改规则后须重新生成受影响产物；识别稿、译文与原配音保留。

## 验证

隔离测试覆盖成功缓存、全部零新增、失败与暂缓定向重试、拒绝项保护、单条与批次来源绑定、历史范围兼容和真实状态文案。前端构建与浏览器只读验证检查补译入口、问题数量和诊断提示；不调用真实 LLM、不改变现有评论译文或投稿。
