# ADR-0177：目标数量评论准备与人工选择保护

日期：2026-10-16
状态：已采纳

## 背景

原来的“补译候选”和“选入已就绪”要求用户理解评分、缺译和可用条数之间的区别；修改目标数量后还要分别执行，容易误认为目标未生效。旧上屏方案也未记录哪些条目由人工保留，自动重挑可能丢失人工编辑。

## 决策

1. 提供一个“准备目标数量评论”操作。评分、翻译和排名递补由 `comment_preparation.prepare` 统一编排；手动页面和完整自动流程复用同一领域入口，不在前端维护第二套准备算法。
2. 手动准备返回尚未确认的草稿。评分与译文仍逐批持久化，只有“确认上屏方案”才保存选择、文字、排版和目标数量。显式启用自动评论的完整流程可按既有授权确认，不改变 saved 模式的人工确认要求。
3. 条目保存 `selection_origin=manual|automatic`。人工勾选、实际编辑上屏文字或显式保留才意味着手动保留；排序与是否保留独立。自动准备仅增减自动项。按用户确认的兼容策略，旧方案缺少来源或短暂使用过的 legacy 值一律归为 automatic，不增加第三类状态、交接提示或专门按钮。准备区域提供“取消全部手动保留”，只解除固定，不删除当前评论或改动文字、顺序；可撤销上次解除，之后统一确认保存。保留项超过目标或时间容量时明确说明，不自动裁掉。
4. 人工取消勾选保存 `excluded_ids=[{id,source_hash}]`，自动准备跳过同一来源的排除项。可以恢复为自动候选。选择、译文与排除均绑定原文指纹，不将旧来源的人工决定套到新原文。
5. 保留人工文字与顺序，只补空译文；仍入选的自动项复用其有效文字。字符限制用于自动候选筛选；手动保留超过建议字数时只提示，完整参与准备、预览、确认及合成，不要求先精简。渲染完整换行并在需要时缩小字号，不截断正文；界面提醒留意停留时间。缺少当前显示语言的正文、来源变化及内容检查等真正无效项仍需处理，禁止通过确认按钮静默丢弃。逐条翻译可用于任意评论，不隐含选入上屏。
6. 准备任务持有项目操作范围，阶段间不允许另一项评论修改插入；提供独立 `prepare_job` 进度与取消标识，真实评分和翻译仍沿用现有 LLM 对话和诊断。评分、翻译预算、拒绝止损与显式失败重试规则继承 ADR-0113/0123。
7. 仅检查实际所选语言、真实画幅和时间容量。目标不足时说明原因，不用不合格文字填满，不自动重发已被审核拦截的内容。来源变化、并发保存冲突、取消或服务异常不改写已确认方案。
8. 选择来源与人工排除是编排信息，不参与最终画面内容指纹；仅修改这些信息不会让相同的成片无故过期。保存目标会更新项目评论数量；若目标超过既有采集上限，仅提高下一次采集上限，不立即联网采集。

## 影响

常用路径变为“目标数量 → 准备 → 检查/精调 → 确认”。评分更新、全部阅读翻译和失败项重试收进更多处理，逐条翻译与保留状态放在评论旁。自动增减与人工选择能够共存。省略来源字段时，后端先从同 ID、同原文指纹的已保存条目继承；没有记录则归为 automatic。所有新自动项显式保存 automatic，刷新、确认与再次准备不得将其提升为 manual。历史兼容在读取时规范，不因打开页面就改写项目文件或改变已有条目顺序。

本决策更新 ADR-0037 中“AI 不自动勾选”的范围：用户显式点击准备，授权生成自动选择草稿；确认边界保持不变。其余缓存、内容审查与自动流程权限规则继续遵循 ADR-0073、0113、0123。
