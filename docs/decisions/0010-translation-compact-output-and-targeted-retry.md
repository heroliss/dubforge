# ADR 0010：翻译使用编号纯文本并局部修复重试

## 状态

已采用

## 背景

JSON 映射降低了字段重复，但模型仍可能混入孤立字符串、裸换行、尾逗号或括号截断；这些格式错误需要额外的提取、修复和解释逻辑。字幕原文本身已经逐句 trim 且不含换行，所以“行号. 译文”足以无歧义地对齐结果。

## 决策

- 翻译模型输出编号纯文本，每一行是 `行号. 译文`；句子数量、行号和顺序与原始窗口一致，每句译文非空，不跨句合并、拆分或省略。风格润色在逐句对应的前提下进行。（2026-09-24 按用户要求收紧，取代此前允许空译文的规定。）
- 不解析 JSON、Markdown、代码块或解释文字；不识别续行，也不把无编号文本合并到上一句。未知行号、重复、乱序和无编号行都按结构性格式错误处理。
- 中间窗口在所有译文后输出一行 `###HANDOFF###`，其下一行是单行交接摘要；最终窗口无需该标记，多余标记兼容并警告。局部修复响应不再要求重复交接标记。
- 单纯缺句或空译文保留已通过校验的译文，只请求未完成的行号。前后各 2 行原文和已有译文仅作参考，不要求重新返回；提示词、重试提示和校验范围保持一致。若补齐只返回一部分，下一轮只请求剩余问题句，范围不因参考句而扩大。少量缺行（上限取 5 行与窗口 2% 向上取整的较小者，比例阈值至少 2 行）使用独立小请求，不携带完整历史。
- 无编号文本、未知号、重复号、乱序或交接协议错误，一律丢弃本窗口已收集的译文与摘要，独立重翻完整窗口。真实失败日志表明，一行漏编号后，后续编号仍可能齐全但译文连续错位；不能只靠编号存在就复用这些结果。
- 大面积缺行可使用完整多轮上下文补齐，校验仍只要求本次待补行号；发送前按 90% 上下文预算做守卫。若“原始窗口 + 上一轮输出 + 修复要求”会超预算，则清除本窗口旧结果，独立重翻原始窗口。
- 重试仍属于同一个逻辑窗口，所有请求和响应继续写入同一条 LLM trace；界面按发送/接收顺序线性展示，并去重重试请求中重复携带的历史消息。
- 校验通过后按 `translate.txt` 编号行协议原子落盘，不再保留 `translate.json`。
- 窗口缓存阶段为 `window-v6`，整步指纹与窗口缓存均纳入翻译提示词版本；逐句非空约定启用时旧结果失效。缓存读取也检查行号集合和非空单行译文。

## 后果

输出格式更接近翻译软件可复用的行对行协议，解析和失败原因更直观。少量缺行的重试请求从完整上下文缩小到局部邻近语境，显著降低 token、延迟和上下文溢出风险。完整上下文只作为必要时的兜底，并受预算守卫约束。超过上下文预算的窗口之间仍然是独立请求，只通过交接摘要传递必要语境。
