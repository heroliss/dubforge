# ADR-0014：实际工作量进度与独立剩余时间估算

- 状态：部分被 [ADR-0015](0015-simple-progress-estimation.md) 取代（2026-09-24）；保留实际工作量计数、活动时钟和历史存储约定。

## 背景

旧版语义整理按预设时间、思考字符量和阶段占比推进百分比，执行器再从百分比反推 ETA，形成循环估算。进度不增长时 ETA 也停止更新。旧历史只有三个窗口，且缺失新权重字段时回退为固定十分钟；设置页与执行代码还维护了不同的阶段比例。

## 决策

采用两种简单估算，不引入预测模型或额外用户配置。

1. **实际工作量**：下载按音视频合计字节量；转录按已处理音频时长；分离按模型、遍数及分段偏移；TTS 按预计朗读时长；封装按 ffmpeg 输出时间。步骤内部仍可保留准备、处理、收尾的显示区间，它们不用于反推耗时。执行器成功收尾后才置 100%。
2. **实测速率**：下载使用最近十秒的字节增量除以真实经过时间，窗口边界按相邻观测点插值；不足十秒使用已有观测，至少经过两秒才显示 ETA。其他计算使用本次有效处理量除以活动时间。缓存复用不增加测速工作量；实际暂停等待不计时。无回调时仍按当前时间计算，下载连续十秒无新字节便不再显示 ETA。
3. **LLM**：语义整理和翻译仅在窗口校验完成后按原文长度推进。相同任务、模型连接与关键参数、模式共享最近二十条正常请求记录；只用输入量在本次窗口一半至两倍之间的样本，至少三条才计算单位原文长度耗时的中位数。当前请求预计余时加后续窗口预计耗时作为 ETA。
4. **不确定性**：不单独预测思考、随机重试、降级或微小收尾开销。样本不足、重试/降级或当前窗口已经超过预期时撤下 ETA。缓存、重试、降级、失败不作为正常 LLM 样本。阶段 ETA 在界面标为“当前阶段”，不冒充整个步骤。
5. **独立刷新**：百分比只由工作量回调更新，ETA 在 API 轮询时读取活动估算器，不依赖百分比增长。前端只做动画和粗粒度时间格式化。
6. **存储与兼容**：跨项目历史存于数据根目录 `progress_timing.json`，原子替换写入；不保存请求正文或密钥。旧 `split_timing.json` 的样本口径不同，不混入新统计。移除手动阶段占比设置，已有 `runner.progress_estimation` 配置留存但不再参与运算。设置页读取同一份历史。

## 后果

- 单个大 LLM 窗口等待期间百分比可以保持不变，实时面板继续显示模型活动。
- ETA 是典型耗时的粗略估计，模型随机性较大时会暂时不显示；不提供未经校准的置信区间。
- 十秒、二十条和三条样本是固定的工程取值，可以通过实际运行误差再调整，不声称它们是理论最优参数。
- 全新模型至少完成三条相近规模的正常请求后才出现历史 ETA；历史统计损坏或写入失败不影响任务产物。
