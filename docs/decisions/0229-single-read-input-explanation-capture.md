# ADR 0229：一次输入捕获共用说明与指纹表示

日期：2026-10-20

## 背景

项目列表会核对实际产物。1642 句、48 字节项目参数和旧 take 侧车的隔离夹具，单次真实 `_project_view` 调用进行了 32,840 次文件身份核验；其中排布指纹调用 8 次，逐次扫描音频与侧车，合计 26,272 次。侧车 JSON 只解析 1642 次，说明原有请求内解析复用有效，剩余成本不能归因于大项目参数。

`stale_explanation.capture` 的 full/outputs 分支先读取 `fingerprint_payload` 生成脱敏说明，再经 `compute_fingerprint` 重读同一输入。说明和指纹本来应描述同一次输入事实。

## 决策

- 把既有规范序列化与 SHA-256 提为 `utils/input_fingerprint.py::fingerprint_digest`，只依赖标准库，不读取文件或配置。
- `compute_fingerprint` 使用该纯函数；序列化参数与编码字节不变，历史和现行制作指纹不改变。
- full/outputs 捕获只读取一次 payload，并以该表示同时生成说明和摘要。versions 分支保留原逻辑；显式指纹、输出范围和旧范围别名保持原合同。
- 不缓存文件身份、新鲜度或完成结论，不增加全局缓存、TTL 或锁；下一次调用仍实时核验。同一次捕获之后文件再变化，由下一次读取识别，不把两个时刻的说明和摘要混在一起。
- 新说明模块从独立纯工具导入摘要函数，只从运行器取得既有的 `fingerprint_payload`。常驻旧运行器尚未加载新代码时，也不会因缺少新增导出符号而发生混合版本导入错误。

## 验证与边界

隔离 pytest 覆盖完整/输出范围等价、六种现行及兼容模式指纹字节、同一 Dependencies 上原地改写、原子替换、删除、恢复 mtime，以及读取过程中替换侧车、错误不被缓存和常驻旧运行器兼容。

同一夹具普通读取，响应逐字段相等，身份核验次数为 32,840→26,272（减少 6568 次，20%）；侧车解析和其余实时身份检查次数不变。首次按旧版→候选的墙钟为 5.26→7.24 秒；额外一次反向候选→旧版为 8.19→10.44 秒，调用次数与响应等价均复现，但时间波动明显，未证明稳定提速。不把次数下降当作生产列表所有延迟已解决。带 cProfile 的先前 16.65 秒读数包含剖析开销，不用于生产性能承诺。

此变更只减少同一次证据捕获中的重复读取，不修改成片记录、文件身份合同、产物指纹或当前目标完成范围。生产后端未重启，实际列表的同口径验证留待全局空闲的安全加载窗口。

证据位于 `data/diagnostics/project-list-isolated-20261020/`。
