# 0173：逐句朗读文本与字幕分离

日期：2026-10-16

## 问题

IndexTTS 2.5 对多音字、数字或停顿可能采用不符合预期的读法。直接修改字幕会混淆展示文字与实际朗读；把独立朗读入口限制为固定注音模板，又会阻止调整标点、数字写法和措辞。实际模型输入必须独立保存，并贯穿缓存、历史声音和自动缩时重试。

## 决策

- 逐句设置保留兼容键 `tts.indextts25.pronunciation_text`，界面名称为“朗读文本”，仅在单句参数接口注入；它不是全局或项目配置，不加入 `DEFAULTS`、全局参数 schema 或配置文件。去掉首尾空白后为空时跟随当前译文；非空时保存为独立朗读，即使当前内容恰好与译文相同，也保留该覆盖关系。
- 跟随状态下输入框直接显示当前译文，不因此创建覆盖或待保存修改；编辑后成为自定义朗读。“恢复跟随译文”立即显示当前译文，保存后恢复继承；详细说明只保留主要操作与一个可选标音示例。
- 用户可以修改标点、数字写法、措辞或整句话；只校验传输值为字符串，不校验与字幕一致，不强制注音模板，不改写内部空白或标记大小写。引擎原生 `<朝|CHAO2>` 是可选读音标记，模型仍负责解释实际输入；自由文本入口不代表引擎支持任意 SSML 或停顿控制命令。
- 逐句身份、字幕、时间轴保持不变。实际朗读不同于译文时，进入音频指纹及 take 的声音参数快照；空值及与译文相同的实际输入保持历史指纹兼容，避免仅因覆盖关系变化而重做相同音频。仅保存不改变现有声音和满意状态；实际修复默认覆盖当前槽，成功后重新试听，需要比较不同声音时用户可明确选择新槽。
- 独立朗读属于内容意图，统一项目声音参数时仍保留。在“文字与时间”中人工修改同一句字幕或时间时，重绑句子身份并保留显式朗读；清空朗读文本才恢复跟随译文。上游重新生成后若句子身份不匹配，旧句设置仍不自动套给新句，防止跨句误用。
- 运行中修改复用已有逐句更新队列、修订号和候选发布事务；当前模型请求固定，下句边界执行新意图，失败保留旧声音。
- 自动缩时沿用被修复 take 的实际朗读快照，不能偷偷套用之后修改的朗读设置；历史快照无独立文本时仍朗读其绑定译文。普通重做和该句内部缩时重试共同使用同一份朗读文本。

## 验证

隔离测试覆盖任意朗读文本、基本类型校验、空值跟随、相同文本的显式覆盖、字幕不变、旧指纹和旧槽保留、统一项目声音策略、人工字幕修改与上游身份保护、历史 take 缩时上下文及运行中队列。模型使用替身，不启动真实服务。
