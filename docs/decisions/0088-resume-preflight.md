# ADR-0088：恢复执行前统一预检与请求回执

日期：2026-10-06。状态：采用。

## 背景

项目有两套恢复记录：手动勾选链在项目参数中保留剩余步骤和挂起原因（ADR-0072），完整流程用 `WorkflowRun` 保存制作、草稿及投稿终点（ADR-0052）。恢复原失败步骤时，前面的文字、设置或文件可能已经变化。直接从旧链头继续会再次撞到依赖门禁；按当前默认流程重建则可能扩大成片版本、草稿或投稿范围。重复点击及响应丢失也不能被解释为另一份执行授权。

## 决定

- 两套执行器保留各自的记录、游标和发布边界，恢复入口统一为“只读检查实际计划 → 展示变化和副作用 → 明确确认 → 执行前复核”。读预览、刷新页面、服务重启均不恢复任务。
- 手动链新增 `POST /api/projects/{uid}/chain/plan`。返回步骤及中文名称、实际保存的成片版本、阻断原因、执行影响、恢复位置与逐步处置（复用、更新、重试、生成或运行），以及绑定该预览的指纹。恢复位置同时展示原位置与当前位置；旧记录无法提供历史设置时，不猜测原参数或原版本。
- 依据当前有效输入及实际版本消费关系，补入完成**原剩余目标**所需的失效或缺失上游；已有效步骤复用。复用逐句音频遵循现有配音规则，正常缓存不强制重做。手动链始终只负责制作，不产生草稿、上传或投稿。当前保存版本和评论自动准备的影响必须在预览中明确展示，不能将审查修订成片误称为文字及配音已重新生成。
- 新恢复请求携带 `confirmed: true`、预览 `fingerprint` 和 UUID `request_id`。在现有启动、制作及编辑互斥范围内重新计算预览；链状态、输入、配置或版本变化时拒绝执行，要求重新检查。没有阻断且指纹仍一致才登记并启动。
- 执行快照按剩余消费者绑定设置、字幕校对、声源选择、句级参数及已确认评论；成片只比较版本实际启用的值，未消费或被版本覆盖的全局参数不引起挂起。正常上游生成产物和自动采集评论不会被当作人工修改。
- 恢复检查核验文本内容，避免等长替换文件仍显示可复用。未修改的大媒体沿用登记与元数据检查；登记后修改的大文件才读取哈希，已核验的同一文件版本复用有界缓存，避免预检反复扫描长视频。执行器仍保留正式完整性校验。
- 兼容旧客户端不带请求体的恢复入口，但仅允许维持原链的执行范围。缺失或失效上游仍由执行门禁阻断并挂起，不隐式补入原链外步骤；要补齐依赖须使用新版预检和确认。不存在挂起链的普通失败项目不凭空获得链历史；如界面提供新的制作计划，须单独预览确认，不能继承默认投稿终点。
- 在项目 `params._chain_resume_receipts` 中保存请求标识、确认指纹及恢复结果。同一 UUID、同一载荷重放原回执；链已经推进、任务已经快速失败或响应已经丢失时，也不再次执行。相同 UUID 换载荷拒绝。用户重新检查后使用新的 UUID，才表示新的恢复尝试。回执只记录调度结果，不证明后续制作成功，也不改写上次成功生成的输入快照。
- 完整流程恢复仍以原流程及其发布关联为边界。已绑定稿件继续原记录；结果未知须人工核对，有 BV 回执后进入审核查询，不重新创建稿件或投稿。没有流程历史的项目不能从全局默认设置推断出此前同意发布。批量恢复逐项目冻结确认输入与请求标识，成功项移出待处理集合，失败及无明确回执项保留供重试。

## 取舍与限制

本决策统一检查与授权语义，不将旧链迁移为完整发布流程，不替换现有产物、逐句选择、审核或发布规则。前置检查只能确认当前本地条件，不能保证模型、网络和平台审核成功。请求回执基于当前单进程锁及数据库持久化；不会提供跨进程执行器的分布式事务保证。进程在登记请求后异常终止时应保留可核对的结果，不能因结果不明盲目执行第二次。

## 验证

`backend/tests/test_chain_resume_plan.py` 使用独立数据根和配置，覆盖预览不写入、较早上游过期或丢失、有效步骤复用、原终点保持、旧入口范围保护、设置及版本漂移、同 UUID 并发与重放、不同载荷冲突、快速失败及真实隔离制作失败后保留成功输入快照，以及无历史项目不生成流程或稿件。测试只替代模型与实际调度，不触发真实上传或投稿。完整流程及发布的既有恢复、去重与未知结果回归继续作为共同边界。
