# ADR-0215：首次发布缺省新稿与统一目标解析

日期：2026-10-20。状态：采用。替代ADR-0211中无发布历史也必须逐项目明确选新稿的交互要求。

## 决策

- 本项目没有发布历史、也从未显式保存目标时，有效目标缺省为创建新稿。普通新建、批量导入、已存在的未发布项目和模板绑定共用规则；不要求逐项目补设，不执行数据库回填。
- 缺省仅是当前解析结果，不写入项目覆盖、模板、基线或清单。保存其他设置也不能把它变成永久“另发新稿”授权。目标解析元数据说明来源、原因、历史和是否显式选择；表单、卡片、单项目运行与批次统一展示。
- 所有本地草稿、归档或回收记录、上传、未知投稿、稿件更新任务，以及已经确认的发布工作流均构成历史。已确认仅制作任务不提升发布权限。坏历史证据保守要求核对；不从最近BV猜测原稿。
- 有历史而没有明确目标时，准备草稿、上传和投稿都要求先选目标；主动保存空目标同样要求选择。仅制作独立成立。明确保存“创建新稿”后可统一批量预检并确认，进入已有原稿则必须保存具体稿件与更新范围。
- 首次默认不携带另发新稿确认；明确的新稿选择才派生该意图。任何未知投稿回执都须先核对，不能借新稿选择重投。预检后出现历史时，普通启动和批次子任务均在公共启动锁内再次核对，不能使用旧的“首次发布”证据。
- 已确认工作流与批次保留冻结目标和自己的发布回执。新增历史让当前项目不再具有首次缺省，不影响原任务的恢复；不重新创建稿件，不扩大旧任务交付终点。
- 项目列表只增加一次批量历史查询，不为每卡加载完整配置或查询远端。未引入第二份批量发布设置，也不修改用户现有发布目标。

## 验证

隔离回归覆盖新建/导入/模板、显式null、各类历史与损坏证据、首次缺省不落覆盖、CAS与启动竞态、旧任务冻结恢复、已有新稿的批次许可及原稿不误选。浏览器只在8611专用合成数据与本地平台替身验收；不进行真实投稿。
