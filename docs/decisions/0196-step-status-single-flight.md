# ADR-0196：步骤状态读取采用运行态轻量核对与同项目单飞

- 状态：已采用
- 日期：2026-10-18

## 背景

长视频的 `/api/projects/{uid}/steps` 不只是读取数据库状态，还会计算逐句配音有效性、成片版本新鲜度和文件身份。合成成片期间，CPU、磁盘和内存已经被编码占用，完整核对可能明显变慢；总览、步骤页和预览组件又可能在同一时间读取同一接口，重复计算会进一步放大延迟，最终让前端把“状态读取慢”误报为“步骤状态未更新”。

## 决策

1. 同一进程内同一项目的步骤状态读取采用 single-flight：第一个请求负责计算，后续并发请求等待并复用同一只读结果；不缓存完成结果，写操作后下一次读取仍会立即重新核对。
2. 步骤处于排队、运行、暂停请求或停止收尾时，状态接口只返回执行所需的即时状态和轻量产物信息，暂缓该运行步骤的 freshness、逐句音频和成片版本完整核对；步骤结束后的下一次读取恢复完整核对。
3. 前端自动轮询不再互相取消在途读取；显式点击“重试”才会取消当前请求并重新开始。步骤状态读取窗口由 15 秒扩大到 30 秒，以覆盖后台资源短时争用；这不是任务执行超时设置。
4. single-flight 等待超过 25 秒返回稳定的 `STEP_STATUS_BUSY` 业务错误，提示继续重试，不伪装为成片失败。

## 结果与边界

- 合成运行期间页面仍能及时显示运行状态和进度，最终 freshness 以任务结束后的完整核对为准。
- 该机制是进程内保护；多进程部署仍应避免重复 worker 或额外配置共享状态缓存。
- 状态读取仍可能因机器内存不足或磁盘不可用而失败；失败只保留上次可信状态，不改变后台任务终态。
