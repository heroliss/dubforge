# 0191 · 以独立成片版本执行等时局部修订

日期：2026-10-17

## 问题

长片只修改数句字幕时，完整视频编码成本远大于修改范围。已有成功记录只保留汇总指纹和版本参数，没有完整逐句字幕、声音和评论的历史渲染事件，无法可靠地自动推断所有新旧差异。

## 决策

使用显式局部修订版本，复用现有 `assemble / versions`、预检、冻结、排队、产物注册及发布绑定。没有增加独立工作流步骤。

- 用户选择已有正式成片作基准，通过句子、多段源时间范围或两者组合定义修订。范围重叠时合并，按句选择纳入实际字幕最短显示延长和配音排布。时间轴总长度不变。
- 范围内从干净原视频、当前字幕与评论重新渲染；范围外保留基准画面与音频。局部版本不宣称范围外也已应用最新设置，原版本的新鲜度不受它影响。
- 基准按内容摘要固定在本项目输出目录，优先硬链接，无法链接时复制；之后的原子重做不会破坏已固定基准。不可变计划同样存于项目内，由项目归属、内容摘要和源身份约束。跨项目、全局、模板不能复用这种引用。
- 默认保留完整旧音轨，直接复制 AAC 等原始音频包。需要更新声音时只准备一次当前完整 PCM 候选，在所选范围替换，边界内侧以 5 ms 交叉过渡，完整音轨仅 AAC 编码一次。相同声音可复用与基准文件绑定的有效测量报告。
- 视频将编码窗口向外扩至独立关键帧，但扩大区域仍取基准画面；新增内容只作用到所选帧。窗口之外流复制，无新增视频压缩损失。
- 严格保持相同 H.264 画面参数、重排策略与固定帧率；局部版本的声音类型和 CRF 固定与基准一致。首版支持可验证的 8 位 yuv420p、x264 封闭 GOP、零起点 CFR 成片。时间轴剪辑、未知编码、编码头不兼容、尺寸或帧率变化明确拒绝并提示完整生成，不静默降级到另一个含义不同的任务。
- 流复制段按帧数限制，不能简单使用 `-t`；B 帧可能令按 DTS 截止的段带入下一 GOP。TS AnnexB 中间片段、显式呈现时长的 concat、MP4 封装已经真实逐帧验证。
- 完成前检查压缩包 PTS/DTS、CFR、编码头、帧数、音视频时长与基准未被改写。产品不为每次修订软件解码完整 4K 长片；完整解码与未改帧 hash 由隔离集成测试覆盖。全部成功后才原子替换局部版本自身产物，失败和取消保留旧成片。

## 界面与自动流程

入口位于合成成片的版本清单下方“局部修订已有成片”。先检查所选范围及包含关键帧边界的编码量，再添加为新版本草稿。保存版本设置后，可直接勾选生成，也可在总览、项目空间的自动流程中选择该版本。既有“更新原稿件”流程继续使用同一产物绑定和章节时间轴；B 站端仍需上传完整新文件。

局部版本明确展示保留基准的语义及范围。保留音轨时不展示无效的声音调整；声音类型和画质不能在局部版本改变。不使用普通全量试片冒充局部版本的最终结果，生成后通过正式成品预览核对。

历史字幕的旧手工时间如果已被覆盖，不能凭当前句子位置恢复。用户可以补充时间范围覆盖旧字幕所在位置。后续已按 ADR 0192 为新成片增加逐句输入快照和差异入口；没有快照的历史成片仍需人工核对，不能补造旧输入。

## 验证

隔离测试包含实际 FFmpeg：关键帧边界、B 帧、23.976 fps、多范围逐帧覆盖、未修改 GOP 像素 hash、复制音轨压缩包 hash、PCM 局部换音与交叉过渡、一次音轨准备、取消与异常原子保留、正式 runner 新版本登记与幂等。网页在独立数据目录与 8611 端口验收，不影响用户常驻实例或 B 站稿件。
