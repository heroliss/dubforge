# 0147 配音单句超时的运行边界与阶段诊断

## 状态

已采用

## 决策

IndexTTS 单句请求的超时是本地等待保护，不代表服务端计算已经停止。请求超时后保留已完成音频，并继续由 `tts_requests` 观察远端任务，防止同一服务被重复提交。

配音进入步骤时仍冻结制作参数、模型参数和步骤级总时限，保证本次运行可复现。列入运行保护白名单的连接与请求参数可以在句子边界重新读取；已提交的当前句保持原超时，下一句使用最新值。这样运行中把单句超时从 300 秒改为 600 秒时，不会改变正在执行的请求，但会作用于后续未提交句子。

超时错误记录等待阶段、已等待秒数、最后已知进度和轮询次数，界面据此区分模型推理、服务排队、结果回传和本地等待。超时边界先尝试读取已经完成的 Gradio 任务，避免完成状态传播稍慢造成误报；仍未完成就严格停止，避免异常推理长期占用服务。

## 原因

IndexTTS 的 `s2mel` 阶段存在明显长尾，短句也可能出现数百秒推理；实测曾出现约 623 秒总推理。根因是动态参考音频与目标 mel 拼接后，在 8GB 显存设备上以 FP32 做多步 CFM 推理，参考越长显存和计算压力越大。因此动态参考默认限制为 5 秒，步骤参数允许在 0.5～15 秒内调整；15 秒与服务端读取上限一致。默认值保留说话人特征并避免把整句原声送入低显存推理。300 秒仍不应被宽限机制掩盖；默认保护值为 600 秒，异常请求到点即停止，重试时变快也可能只是 GPU 状态恢复或队列抖动消失。
