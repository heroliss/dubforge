# 0205 单成片预览与跨版本源时间轴剪辑

## 状态

提议，待前端联动重构后采用

## 背景

当前剪辑页同时播放原视频和当前成片。两者时长、缓冲和解码时钟不同，且删除范围可能尚未保存。双向播放同步因此会把“草稿时间轴”“已保存方案”和“上一版正式产物”混在一起，导致暂停/恢复、关闭再打开联动以及删除试听时出现卡顿或跳回。

## 决策

1. **剪辑数据的唯一坐标是原视频时间。** 每个成片版本保存自己的 `output_cuts` 快照，范围仍是原视频上的删除区间；版本快照中保存源指纹、源时长和渲染版本。成片输出时间只通过 `keep_segments`、`map_time`、`unmap_time` 临时计算，不能作为持久化编辑坐标。
2. **每个版本独立保存，历史版本不可变。** 已生成版本的 `snapshot.output_cuts` 是完整修改记录。新版本可以选择任意同源旧版本作为起点，但导入的是源坐标范围；保存新版本不会改变旧版本。源指纹或时长不同的版本不能直接恢复，必须重新核对并绑定新源。
3. **恢复/删除按源区间运算。** 从旧版本恢复片段等价于从当前版本的有效删除并集做区间减法；从源或其他版本删除片段等价于做区间加法。备注、行 ID 和启用状态只属于当前版本的编辑记录，合并后的有效区间用于渲染和指纹。
4. **页面默认只播放一个“当前成片预览”。** 下方保留原视频完整时间轴作为可编辑标尺和删除/恢复清单，不再把第二个原视频播放器作为联动播放端。当前正式成片存在时，播放器按已保存版本时间轴播放；没有正式产物或草稿改变了恢复范围时显示“需要重制”，不把旧文件冒充为当前草稿。
5. **实时试听分两级。** 对只删除当前成片已有内容的草稿，可以在当前成片播放器上按输出坐标跳过相应区间；涉及恢复、改变字幕/配音内容或跨版本基片的草稿，必须保存并生成短预览/正式版本后再试听。页面明确标出“已生成”“已保存待重制”“当前草稿”三种状态。
6. **联动开关只控制时间定位，不控制数据模型。** 关闭再打开时要先暂停或选定唯一主时钟，按当前版本映射执行一次强制定位，再恢复播放；不能让两个播放器重新互相监听 `timeupdate`。

## 原因

一个成片播放器和一个源时间标尺能消除两个异步媒体时钟的竞争；源坐标区间运算又能让不同版本之间安全恢复片段。实时试听的能力边界被明确后，用户不会误以为尚未生成的字幕、配音或恢复画面已经存在。

## 最小改造

- 保留 `output_cuts.json` schema 2 与 `snapshot.output_cuts`，新增纯函数 `add_ranges`/`subtract_ranges`（或等价的前端与后端测试辅助）以及源指纹校验。
- 将 `OutputCutsEditor` 的双播放器降级为当前成片单播放器；保留源时间轴、帧步进、区间清单和旧版本选择。
- 将“播放时跳过当前删除清单”改名为“试听当前草稿（仅删除可即时试听）”，只在当前成片已有内容可映射时启用；恢复区间显示待重制提示。
- 为版本切换和联动开关补充状态机测试：`idle → syncing → waiting`、暂停/重播、切换主端、关闭再开联动。

## 风险与边界

- 浏览器不能在当前成片中即时恢复旧成片不存在的画面、配音或评论；强行拼接原视频会产生内容错位，禁止作为默认试听。
- 旧版本若没有可靠的源指纹、源时长或产物哈希，只能作为只读参考，不能自动导入。
- 删除范围过多时，短预览仍需走编码任务；不能在播放事件中启动 ffmpeg。
