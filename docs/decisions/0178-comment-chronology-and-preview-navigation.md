# ADR-0178：评论先选后排与双向预览定位

日期：2026-10-16

状态：已采纳

## 决策

- 评分只决定自动选入哪些评论；默认上屏排列按原平台评论发布时间从早到晚进行。相同时间按采集次序稳定排列，缺少时间的评论排在有时间的评论后面，不能用评分或零时间代替发布时间。
- 保留权威 `timestamp` 贯穿评论来源、工作区与确认方案；客户端不能伪造时间。原文指纹不包含时间，修改时间元数据不使评分或译文缓存失效。
- `selection_origin` 决定是否保留选中的评论，`order_mode` 决定如何排列，两者独立。手动勾选或编辑文字不将评论固定置顶；上下移动会明确切换为手动排列。再次准备时，手动排列保留既有条目的相对顺序，新条目按时间追加。可通过“按发布时间排列”恢复默认策略。
- 旧确认方案打开时保持原数组与预览不变。用户重新准备或主动按时间排列后才调整草稿，最终确认保存当前预览顺序。渲染器只消费已确认数组，不再自行按分数或时间重排。
- `timestamp`、`order_mode` 属于编辑元数据，不参与渲染内容指纹；实际条目数组顺序改变仍会让对应成片需要更新。
- 候选列表默认按发布时间浏览；“按分数浏览”只影响阅读顺序，与上屏排列分离。
- 评论列表与预览通过评论 ID 双向定位。列表入口展开预览并跳到该评论实际上屏时刻；预览入口根据当前画面对应的评论定位列表，必要时取消候选过滤、切换分页、滚动并高亮。
- 点击已选评论直接将同一完整时间轴的播放头定位到其上屏起点并刷新该时刻画面。未选评论尚无实际上屏位置，可在完整方案中临时插入试放，保留其他评论和完整时间轴，不改为独立单条预览。试放不加入选择、不改变方案、不调用 LLM；结束试放保留视频播放头位置。
- 缺少译文的试放明确临时显示原文；不可上屏的文字显示原因。显式定位及时刷新，连续参数调整仍防抖；请求保持串行和旧响应隔离，不保存草稿。

本决策补充 ADR-0177：人工选择保护不意味着人工项总在自动项之前；手动顺序必须来自明确的排序操作。
