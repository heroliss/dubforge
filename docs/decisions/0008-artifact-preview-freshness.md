# 0008 产物预览按内容版本刷新

## 状态

已采用。

## 背景

管线重跑通常会原子替换同名产物，例如 `split.txt`、字幕文件、分离音轨和逐句配音。
如果界面只按文件名判断变化，浏览器媒体元素、波形和工作台的 Web Audio 缓存会继续使用旧内容；
任务很快完成时，页面甚至可能没有观察到 `running` 状态，导致轮询补救也失效。

## 决策

- 步骤产物列表返回登记时计算的 `sha256`，前端以 `sha256`（旧数据无哈希时回退到大小）作为内容版本。
- 同名文本预览、字幕轨道、音频/视频元素和音轨波形都根据内容版本重建或重新读取。
- 成片允许多个历史版本并存，按文件名中的时间戳选择最新视频，不能依赖产物列表顺序。
- 轮询型 JSON、日志、LLM 事件和波形请求使用 `Cache-Control: no-store`，前端 fetch 同样明确禁用缓存。
- 工作台逐句配音、背景音和视频 URL 带文件时间/大小版本；Web Audio 缓存以版本 URL 为键，并限制缓存数量。
- 步骤页与工作台每 1.5 秒检查更新。首次产物登记后自动出现预览；字幕同时监听源视频和上游时间轴版本。
- 同版本的并发读取合并补读，版本变化则取消旧请求并丢弃迟到响应；读取失败继续重试，步骤结束补读最终结果。
- 本页启动重跑前主动暂停并释放媒体请求，离开页面也释放；视频、音轨重建期间撤下对应播放器，结束后重新挂载，不自动播放。
- 工作台发现媒体版本变化时停止试听；切换句子、停止或离开页面后，未完成的音频读取不得再次开始播放。

## 结果

重跑同一步骤后，即使产物文件名不变，文本、字幕、波形、音频试听、视频和工作台混音都会切换到最新产物。
文本和字幕读取暂时失败时保留上一次有效预览，并在下一轮轮询继续尝试。
下载、音轨分离和成片重跑期间暂停对应媒体预览，避免浏览器继续占用即将替换的文件。
