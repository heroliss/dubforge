# 0056 写操作回执与列表刷新分离

日期：2026-09-28

## 问题

“仅删除记录”的确认回调在收到成功回执后，还等待 `nav.poll()` 的项目、步骤、发布三个读取全部结束。慢的发布状态读取会让已经完成的本地删除继续占用确认框。成品生成、试合成、步骤控制、发布队列和全流程操作也存在类似等待。

## 决定

- 写请求仍必须等待真实回执；不提前显示成功，不跳过文件版本、任务 ID、发布指纹等校验。
- 成功回执立即更新可确定的本地状态，确认回调结束；派生列表在后台同步。刷新失败单独提示，不能把写成功误报为写失败。
- 成品手动刷新只读取步骤状态，不等待项目资料和发布状态。删除记录立即移除对应条目；移到回收站立即标为缺失，仍保留原位置。
- 取消写操作之前的旧步骤读取；发布列表采用读取代次，旧响应不能回滚新写回执。后续主动刷新仍可接受真实磁盘恢复和后台任务进展。
- 删除请求期间显示加载并禁用重复操作；失败保留确认框、保留记录并允许重试。成功确认不可再次发送。
- 共用 `refreshInBackground` 表达这个边界，不把整个请求改为不等待，也不统一取消所有必要读取。

## 验证

真实 Vue 组件回归覆盖写请求仍在等待、慢刷新、写失败重试、重复确认、保留生成清单和发布队列旧响应；store 测试覆盖成品局部刷新、回收后的磁盘恢复、跨项目回执与步骤启动状态。测试不删除用户文件，不触发真实上传或投稿。
