# ADR-0002: 产物完整性与可恢复写入

- 状态：已采纳（2026-09-19）
- 背景：管线步骤可以被取消、进程可以重启，用户也可能从项目目录手动删除文件。仅依赖数据库里的 `done` 状态和输入指纹，会把缺失或半成品误判为可复用结果。

## 决策

1. **完成条件同时检查索引和文件**：步骤只有在状态为 `done`、实时输入指纹一致、最新登记产物全部存在、大小一致且位于项目目录（外部零拷贝引用除外）时才允许跳过；真正跳过前再校验一次登记的 SHA-256。
2. **所有持久化产物先写临时名**：写入完成后统一通过 `dubforge.utils.fs.atomic_replace` 转正；异常路径清理临时文件。上传、JSON/SRT、音频、字幕副本和成片封装均遵循这条规则。
3. **重建语义在入队前固定**：步骤的 `failed`、`stale`、`interrupted` 状态以及输入指纹变化都会把本次执行标记为 rebuild，步骤实现不能继续复用旧产物。
4. **源输入参与首步指纹**：下载步骤的链接、来源类型，以及本地源文件的大小和修改时间纳入指纹；没有 `source_url` 的旧本地项目继续使用 `media/` 中的副本。
5. **数据库是索引，目录清单可重建**：`manifest.json` 记录步骤、指纹和产物；重建索引时对现有文件重新计算 SHA-256，缺失文件以空哈希登记，使其下一次执行必然失效。

## 后果

- 手动删文件、替换本地源或修改项目覆盖参数后，下一次运行会明确重建，不会静默复用旧结果。
- 原子替换降低中断后留下损坏最终文件的概率；临时文件仍可能在系统强制断电时残留，启动清扫会按步骤作用域处理。
- 本地外部引用仍由用户负责保管，删除 DubForge 项目不会删除引用文件。
