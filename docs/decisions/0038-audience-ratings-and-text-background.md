# ADR-0038：观众反馈评分与共享文字背景

日期：2026-09-27。扩展 ADR-0037 和 ADR-0026/0034。

## 证据与问题

旧默认要求“与视频内容有关、有具体观点或有趣体验”，容易被理解为只选具体信息，漏掉赞美、
共鸣、祝福和对创作者互动的反馈。只返回入选项也无法解释未入选原因。实际案例中，17 条评论、
50 条上限、只返回 10 条，因此用户举例并非被总数量上限截掉；旧记录不足以还原模型的具体理由。
用户进一步要求每条只评一次，之后灵活改变展示数量，不反复消耗 AI 调用。

评论渲染和字幕渲染各自拼装 ASS 颜色/背景。评论固定黑色背景且无法保留双语，重复的原文展开按钮
增加了编辑操作；评论列表间距过大，常驻筛选理由干扰正文阅读。

## 决策

1. 目标改为“适合展示的观众反馈”，不额外要求具体信息或复述画面。观感、共鸣、幽默、创作者互动、
   赞美、祝福、经历、建议、疑问和有理有据的批评均可有效；宗教用语、emoji、拼写不标准不是独立淘汰理由。
   用户明确自定义的范围优先。上下文用于帮助理解，不作为严格相关性门槛；评论仍是不可信引用资料。
2. LLM 每批必须完整评价每个 ID：是否符合当前要求、0–100 展示优先度、简短中文理由。不限制每批名额，
   也不由模型截取全局前 N 项。使用统一评分区间，不按批内排名分配分数，降低批次间尺度差异。
   保存所有评价，候选仅是其中一个可调视图，未入候选也能手动勾选。
3. 评分缓存绑定提示词、算法版本、视频参考上下文及评论原文指纹。改候选数量不重新调用 LLM；
   同标准下只补评新增或修改的评论。逐批原子保存 `rating_cache`，中断重试不重复成功批次。
   全部完成才替换已发布评分列表，避免中途换规则覆盖旧结果。另有显式“全部重新评分”操作。
4. 前端根据完整评分本地排序、调整前 N 条；这不等于修改待上屏列表。点击“使用前 N 条”才应用，
   保留仍入选评论的编辑文字；移出其他已选评论先确认。候选最多 500，待上屏仍最多 100。
   卡片分数的悬停说明区分不符合要求、符合但不在前 N 条、当前候选。旧数据不编造未入选理由。
5. 评论提供中文、原文、双语模式，双语可切换顺序；原文直接在编辑区显示，不再需要“核对原文”按钮。
   平台原文、可编辑上屏原文和上屏中文分开保存；不因切换模式丢失任何语言的编辑。
   当前显示中文限 240 字、原文限 600 字，超限明确报错而非截断。无译文不伪装为中文。
6. 新方案默认左上角，可选六个边缘位置；旧已确认方案保留原位置。左/右对齐使用较窄文字区，
   不让短评横跨整个画面；双语合并计算换行与缩小字号，放不下时仍明确报错。
7. `pipeline/text_style.py` 统一 RGB→ASS、0–100 不透明度校验、背景与描边独立的绘制规则。
   字幕和评论的预览、成片都使用它。libass `BorderStyle=4` 让多行共用一块背景并保留描边；
   透明度 0 恢复普通描边、关闭背景。内部临时 ASS 不作为跨播放器分发格式，SRT 不携带样式。
   前端两处共用 `ParamControl` 颜色选择和不透明度滑条，提供“透明”快捷操作。
8. 新增字幕全局默认：`assemble.subtitle_background_color=#000000`、
   `assemble.subtitle_background_opacity=0`，同步 DEFAULTS、示例和本地配置；旧无背景字幕不变。
   评论背景保留半透明黑色默认，独立保存在上屏方案，不强制同步两者的具体样式值。

## 验证与边界

- 隔离测试覆盖完整评分 ID 校验、未知/遗漏/重复值、缓存命中、改变数量、增量评分、标准变更、
  强制重评、失败批次续评与不自动选中；提示词契约包含温暖反馈和合理批评，不声称替身能证明真实模型判断。
- 真实 FFmpeg 像素测试覆盖字幕双语背景颜色、半透明/全透明、独立描边、评论左上角/右上角、双语行。
- 实际 Vue 组件测试覆盖移除冗余按钮、共享控件、双语文字保留、调 N 不发请求、候选应用保留编辑和移出确认。
- 分数仍是模型建议，不保证客观排序或特定评论必然高分；用户能直接手动选中。

渲染依据：[libass 官方扩展说明](https://github.com/libass/libass/wiki/Libass%27-ASS-Extensions#borderstyle4)。
