# ADR-0127：顺序发布先完成当前制作，再绑定有效成片

日期：2026-10-08。状态：采用。

## 问题

顺序发布遇到已有发布记录时，直接预检该记录中的旧文件并跳过制作。未选成片的草稿因此不能进入批次；审查要求变化后的旧草稿也先被成片门禁阻断，用户必须逐项目重做并重新选文件。这个分支与“完整流程会自动补齐制作”的操作含义冲突。

## 决策

- 项目空间以“制作并按顺序发布”明确完整操作。批次展示有序项目、目标账号和合集小节、每项选定成片版本、发布记录处理方式及制作计划。版本预选来自项目发布设置，用户可在批次中修改；实际选择进入确认指纹，不从磁盘猜测成片。预检成功后收起设置区，各项目集中展示更新起点、执行和复用数量；步骤明细可展开，确认操作固定在面板底部。
- 新项目和未投稿草稿先按选定版本补齐缺失、失败及需更新的制作步骤，复用有效产物；生成后将最新有效成片绑定到草稿，再运行发布预检、上传与投稿。草稿的存在不代表制作已经完成。开始前不要求将要自动生成的成片已经存在或旧文件已符合新审查。
- 批次仍使用现有完整流程、依赖计划、版本合成和发布执行器。草稿准备和继续已上传资料是不同执行意图；使用旧冻结文件继续上传时必须明确展示，不伪装成重新制作。
- 内容审查仍在合成和实际发布边界核验。制作计划能修复旧文件问题，但不豁免新成片的审查；未生成指定版本、审查失效或文件改变时停止本项，不退回旧文件或改选其他版本。
- 已有 BV 的记录保留回执和来源。复用原稿仅核对审核、合集归属及最终顺序；重做本地视频不自动替换远端原视频，也不因失败或归档另投重复稿件。审核修订草稿的重新制作仍保留原稿来源和新投稿含义。
- 版本选择、草稿处理方式、项目有效配置和恢复方案一起确认并冻结。执行中检查变化；停止、失败和重启保留产物及回执，恢复从有效断点继续，不能跳过未完成的前项。
- 最终发布顺序仍由完整合集成员快照、单次排序发送和回读校验保证。未知投稿或排序回执继续只读核对，不自动重发。
- 当前批次的执行状态与用于恢复的历史流程分开。等待项只显示等待前项完成，不继承旧流程的错误、阶段或稿件身份；本次实际失败仍保留错误。只读展示也净化升级前保存的等待项，不能为修复显示而修改正在运行的批次。
- 项目完成数量和当前阶段进度分开。当前项从工作流游标、步骤回调和实际上传记录读取，LLM 预计进度明确标注；审核、稿件核对与最终排序不伪造百分比。列表按当前项批量读取数据库和内存进度，不扫描产物、重跑预检或请求平台。后台轮询不切换刷新按钮的加载布局，批次操作栏与可展开明细独立。

本决定补充 ADR-0115 的制作与发布衔接，保留其账号、合集、权利确认、远端写入及未知结果保护。项目基础值继续遵循 ADR-0126，不为批次预览修改项目设置。

## 验证

隔离测试覆盖空草稿、失败或需更新步骤、旧审查文件、明确版本范围、准备后重绑、继续已上传资料、已有 BV 复用、迟到回执及顺序恢复；所有平台操作使用桩，不向真实账号投稿。界面覆盖预选、差异计划、失效确认、重复点击和批次进度。
