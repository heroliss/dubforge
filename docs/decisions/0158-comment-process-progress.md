# ADR-0158：评论准备的统一阶段与轻量进度

状态：已采用。日期：2026-10-15。

## 问题与现场证据

评分与翻译已经共用`comment_studio.run`并逐批原子保存，但页面只有一行
完成条数；采集位于父页面，自动流程仅显示阶段文本。模型思考期间一批的
完成数不变，用户无法区分正常等待、生成、纠错与停滞，必须打开日志排查。
工作区每两秒重复读取全部评论、配置及逐条审查；结果排序和分页也可能打断阅读。

现场只读观察的102条评分共11次请求，13:29:18至13:34:59完成，未见校验
错误、自动重试或服务商拦截，随后自动处理候选翻译并确认30条上屏方案。
思考流持续返回，而心跳每4秒仍打印“静默等待0秒”，造成状态误导。

## 决策

工作区始终展示获取原文、评分、按需翻译、上屏方案四个阶段；总览在当前
评论准备期间复用同一展示及状态来源。它是实际执行与已保存结果的展示，
不另造流水线任务，不将手动评分后的翻译或确认错误地宣称已排队。

`Diagnostics.trace`将已有LLM事件投影到短小job字段：请求按request_id去重，
阶段包括准备、等待、思考、正文接收、校验、纠错和收尾；展示真实批总数、
批大小、尝试、活动时间和耗时。正文及思考仅统计字符数，不放入进度响应。
持续流每秒最多持久化一次状态，阶段变化与终态立即保存，不每个token写JSON。
未知历史耗时返回空值，终态耗时冻结；跨时区历史按真实时刻而非字符串排序。

轻量`GET /comments/progress`返回`job/jobs/collection/data_revision`。
资料版本覆盖评论工作区、YouTube采集及外部B站评论三份文件。只有保存结果
改变版本、明确操作或恢复页面可见时才重新读取完整工作区，不反复解析配置。
状态请求合并并发、设读取超时、卸载取消、后台暂停，保留表单草稿与阅读顺序。
旧进程无新路由时识别一次404/405并回退原接口，不为进度功能重启当前任务。

采集只显示真实生命周期、来源快照数量、请求上限、复用、耗时和安全错误。
yt-dlp目前没有可用的逐条回调，不能将上次快照除以本次上限伪造成实时百分比。
评分/翻译的`processed+skipped`代表本次已结束处理量，成功、缓存、失败、
拦截和待处理分开显示；不能把“已处理”都当作成功。

LLM静默心跳仅在真实静默达到周期后记录，流式正文与思考刷新活动时间。
保持现有思考设置、10条/6000字符批次、定向纠错和失败恢复策略，不为进度
展示调整模型参数或增加模型请求。当前采集的网络取消响应性另行评估。

## 本次检查范围

只读检查了用户实际任务、最终评分及候选翻译数量；没有修改其任务、资料、
模型设置或重启服务。新增后端阶段/节流/跨时区/采集生命周期与前端展示
回归用例，按此前用户要求仅写入、不运行测试。交付前检查Python语法并构建
前端；新后端阶段字段需正常重启后生效，当前任务仍使用兼容展示。
