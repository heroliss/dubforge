# 0195 按稿件状态组织发布工作区

日期：2026-10-18

## 问题

发布页同时展开新稿准备、投稿进度、原稿更新、单独同步、历史快照和本地记录管理。用户难以判断当前应操作哪一块；锚点导航也无法表达当前正在查看的任务。已有BV的更新与另发新BV尤其容易混淆。

## 决定

- 一条发布记录拥有一排任务导航，当前只展示一个任务。新稿按选择视频、投稿资料、确认投稿、进度排列；有BV的稿件提供进度、更新原稿件、文案与章节、快照和更多。
- `publishWorkspace.ts` 是纯状态解释器。未知投稿结果仅提供核对与快照；后台上传提供进度与冻结清单；归档或保留记录保持只读。它不授予上传、远端写入或恢复权限，各组件和服务端继续执行原有检查。
- 初次打开记录按状态选择任务；驳回优先原稿更新。用户主动选择之后，输入、保存和同记录轮询不自动抢走当前任务。状态变化使任务不再可用时，回退到安全入口。
- 同记录用 `v-show` 切换，保持表单、AI候选和原稿更新方案挂载。跨记录、项目、项目设置和离开页面继续执行未保存修改与忙态保护。
- 稳定锚点先展示对应任务，再定位内容。记录选择同步地址中的 `publication`；地址更新指向当前记录时不重复读取或丢弃编辑。
- 原稿更新以选择现有成片为主入口；视频、文案、章节、合集按范围展示，统一检查后确认。创建新BV、官网操作和本地管理移到更多。
- `PublishResultPanel.surface` 将状态与更多操作拆开，默认 `all` 保持其他调用兼容。只有状态区域拥有回执锚点，避免重复ID和重复进度。
- 草稿没有已启动的执行进度。视频已通过审核而章节失败、待核对或处理中时，工作区显示对应的后续待办，不能以视频已发布掩盖交付未完成。

## 视觉与适配

沿用现有暗色主题、字体与控件；减少重复标题、嵌套卡片和长说明。颜色服务于成功、待处理、错误和当前任务。较窄桌面用顶部记录选择器代替第二层侧栏；任务横向溢出时可滚动。选片保留成片名称、实际生成或登记时间、效果摘要与文件名。

本轮使用 Impeccable、frontend-design 和浏览器验收。已核实 Open Design 安装且MCP启用，但当前会话没有暴露其工具，未调用原型生成或外部设计服务。

## 验证边界

前端状态、组件与渲染测试覆盖未保存编辑保留、未知结果保护、章节重试、状态刷新、锚点和记录地址一致性。浏览器在8611隔离夹具检查草稿、驳回、投稿待审核、上传中、章节失败和原稿更新待审核；夹具拒绝真实投稿、上传及远端修改。生产端口与发布记录不受测试写入。
